# 架构总览：实现一个简单的 Agent

> 这不是一道新形态的题，而是把六道无状态题串成一条里程碑链：**官方脚手架 + 你当前这一步的填空**，判题机只回放冻结的参考模块，从不回放你自己前序步骤写的代码。

## 一句话

模型永远不进判题环境。每一句「模型说了什么」都作为 fixture 显式入参；你要写的是围绕它的纯逻辑：schema 校验、循环状态机、记忆账本、重试熔断、多轮验收、架构复盘。

## 里程碑依赖图

```text
                       +-----------------------+
   user turn --------> |  01 tool_schema       |  validate(spec, args)
                       +-----------+-----------+
                                   |
                                   v
                       +-----------------------+
   fixture LLM ------> |  02 react_loop        |  trace / final / why
                       +-----+-----------+-----+
                             |           |
               +-------------+           +-------------+
               v                                       v
    +----------------------+             +----------------------+
    | 03 memory_ledger     |             | 04 retry_breaker     |
    | append / compact     |             | plan / breaker       |
    +----------+-----------+             +-----------+----------+
               |                                     |
               +----------------+--------------------+
                                v
                   +------------------------------+
                   | 05 dialog_runner  (FINAL)    |
                   | turns / calls / answers      |
                   +--------------+---------------+
                                  v
                   +------------------------------+
                   | 06 L4 design review          |
                   +------------------------------+
```

依赖只表示**推荐路径**，不强锁：任意一步的 `starter.py` 都已内置全部前序官方实现，可以从任何一步直接开始。

## 每步为什么存在

| Step | 里程碑 | 为什么存在 | 验收层 |
| --- | --- | --- | --- |
| 01 | 工具 schema 校验器 | 先把「调用是否合法」变成纯函数，循环才有可断言的边界 | L1 / L2 |
| 02 | ReAct 循环状态机 | 让 Agent 有一轮可观测的循环边界，终止原因也必须可判 | L1 / L2 |
| 03 | 记忆账本与确定性压缩 | 把轨迹写成可回放的账本，长对话才有界、可复现 | L1 / L2 |
| 04 | 重试退避与熔断预算 | 失败路径同样确定性：退避是算出来的计划，不是真的等待 | L1 / L2 |
| 05 | 多轮脚本化对话终局验收 | 把前四块拼成一条数据流，断言工具调用序列与最终答案 | L1 / L2 |
| 06 | L4 设计复盘 | 用排序/判定题收尾，考的是「为什么这么切」而不是手感 | L4 |

## 全程数据流

```text
user turn -> fixture replies -> schema validate -> ReAct trace
          -> ledger append/compact -> retry plan -> per-turn report
          -> final answer -> L4 stage audit
```

## 判题口径

- **无状态**：每一步的输入只有题面给的 fixture 与 `scaffold/` 里的官方模块；用户历史代码不参与判题。
- **确定性**：无随机、无网络、无 sleep、无全局状态；生成文本、概率、logprob、工具结果全部显式入参。
- **四层验证栈**：L1 单元对拍（oracle 逐字段比对）、L2 性质不变量（幂等、往返、有界、可复现）、L4 设计复盘（确定性可判）；本项目无训练步骤，因此不用 L3 固定种子带。
- **独立记录**：项目题在 `problems/projects/` 下，不进 `collections.json`、不占全库 `order` 池，进度单独写 `data/project_progress.json`。

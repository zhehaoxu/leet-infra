# MoE：抖动优先级的容量分派与溢出转投

## 任务

实现 `solve`：每个专家只有 `capacity` 个槽位，把所有 token 的 top-k 候选按**抖动后的优先级键**从高到低排队占位；自己的专家满了就**沿秩往前转投**次优候选，投不出去就丢弃。最后只在**存活槽位**上重新归一化门控权重。

这是容量分派里「谁被丢掉」这一决策的显式建模。按 token 顺序丢（先到的活）会让 batch 里靠后的 token 系统性挨饿，所以工程上会给优先级加扰动再排队。本题把扰动做成**输入张量**而不是内部随机数，判题因此完全确定。本题不涉及反向传播，也不模拟 all-to-all 通信。

## 输入

- `probs`：CPU float64 `[T,E]`，非空、有限、元素非负；每行**不要求**和为 1。
- `jitter`：CPU float64 `[T,E]`，与 `probs` 同形、有限，可正可负。
- `k`：Python `int`，$1\le k\le E$（`bool` 不算 `int`）。
- `capacity`：Python `int`，$\ge 0$（`bool` 不算）。

接受非连续张量，不修改任何输入。dtype、形状、设备、维数、有限性、非负性、`k`/`capacity` 越界一律抛 `ValueError`。

## 精确规则

槽位编号 $s=t\,k+j$，秩 $j$ 就是候选在该 token 内的排名。

**候选**：$cand_t$ 是 `probs[t]` 的 top-$k$，按键 `(-probs[t][e], e)` 升序取前 $k$ 个——**并列时专家索引小者优先**。`jitter` 不参与候选筛选，只影响下面的处理顺序。

**优先级键与处理顺序**：

$$
key_{t,j}=probs[t][cand_t[j]]+jitter[t][cand_t[j]],\qquad
order=\text{argsort}\bigl((-key,\;s)\bigr).
$$

即所有 $S=Tk$ 个槽位**全局**按 $key$ 降序排队，$key$ 相同则槽位编号小的先处理。注意这不是 token 顺序：同一 token 的低秩槽位完全可能先被处理。

**贪心占位**：按 `order` 逐个处理，`remaining[e]` 初值为 `capacity`。对槽位 $(t,j)$，依次考察

$$
cand_t[j],\;cand_t[j+1],\;\dots,\;cand_t[k-1]\qquad(\text{只往前走，不回绕}),
$$

取第一个满足 $remaining[e]>0$ **且** $e$ 尚未被 token $t$ 占用的专家：置 `assign[t][j]=e`、`remaining[e]-=1`。找不到就 `assign[t][j]=-1`。被丢弃的槽位不占任何容量。

一条不变量由此自动成立：**同一 token 的存活槽位必然落在互不相同的专家上**（top-$k$ 本身无重复，占位时又排除已用专家）。

**权重**：$w^{raw}_{t,j}=probs[t][assign_{t,j}]$（丢弃记 0），

$$
weights_{t,j}=\begin{cases}
w^{raw}_{t,j}\big/\sum_{j'} w^{raw}_{t,j'}, & \sum_{j'} w^{raw}_{t,j'} > 0,\\[3pt]
0, & \text{否则}.
\end{cases}
$$

归一化只覆盖存活槽位，不是原 top-$k$。全行丢弃或整行概率为 0 时分母为 0，必须给 0 而不是 NaN。

## 返回

`(assign, weights, counts, dropped, order)`：

| 项 | 形状 / 类型 | 含义 |
| --- | --- | --- |
| `assign` | int64 `[T,k]` | 每个槽位最终落在哪个专家，`-1` 表示丢弃 |
| `weights` | float64 `[T,k]` | 存活槽位归一化后的门控权重，丢弃处为 0 |
| `counts` | int64 `[E]` | 每个专家实际占到的槽位数 |
| `dropped` | Python `int` | `assign == -1` 的个数 |
| `order` | int64 `[T*k]` | 处理顺序，元素是槽位编号 |

浮点用 `rtol=atol=2e-11`，整数张量逐位比较。

## 示例

`T=4, E=4, k=2, capacity=1`，`jitter` 全 0 除 `jitter[1][0]=0.25`：

```python
probs = [[0.5,    0.25,   0.125,  0.125 ],
         [0.4375, 0.3125, 0.125,  0.125 ],
         [0.375,  0.25,   0.125,  0.25  ],
         [0.0625, 0.125,  0.25,   0.5   ]]

# cand      t0=[0,1] t1=[0,1] t2=[0,1] t3=[3,2]
# key       (1,0)=0.6875 (0,0)=0.5 (3,0)=0.5 (2,0)=0.375
#           (1,1)=0.3125 (0,1)=0.25 (2,1)=0.25 (3,1)=0.25
# order     [2, 0, 6, 4, 3, 1, 5, 7]
# assign    [[1, -1], [0, -1], [-1, -1], [3, 2]]
# counts    [1, 1, 1, 1]      dropped = 4
# weights   [[1, 0], [1, 0], [0, 0], [2/3, 1/3]]
```

三点解释：

- token2 的 $cand_2=[0,1]$ 里 e1 是靠并列赢下的——`probs[2][1] == probs[2][3] == 0.25`，并列取小索引，所以 e3 根本没进候选。
- `order` 先处理 $(1,0)$（键 0.6875）占走 e0；接着 $(0,0)$ 发现自己专家已满，**沿秩前进一格**转投 e1，于是 `assign[0][0]=1`，权重取的是 `probs[0][1]=0.25`。键 0.5 处 $(0,0)$ 与 $(3,0)$ 并列，按槽位编号 0 先于 6。
- token3 两个槽位都活着，权重是 $0.5/0.75=2/3$ 与 $0.25/0.75=1/3$；token0 只剩存活的那个槽位，所以权重是 1 而不是 0.5——**存活者优先归一化**。

# 详解：分辨率分桶字符串的解析与校验

## 出处

HuggingFace diffusers 的 `src/diffusers/training_utils.py` 里的 `parse_buckets_string`。它是 SD3 / Flux 一类多分辨率训练脚本读取 `--bucket` 配置的入口，解析出来的 `[(h, w), ...]` 随后交给 `generate_aspect_ratio_buckets` / `find_nearest_bucket`（那部分已由 `diff-aspect-ratio-buckets` 覆盖）使用。

## 核心与易错点

1. **正则只认「整段都是两个整数」**：`^\s*(\d+)\s*,\s*(\d+)\s*$` 要求整段匹配，所以 `"512,768,1024"`、`"512,"`、`",768"`、`"512x768"`、`"-512,768"`、`"+512,768"`、`"5e2,768"`、`"512.0,768"` 全部被拒。用 `split(",")` 再 `int()` 的写法会把 `"+512"` 与 `"-512"` 放过去，是最常见的偏差。
2. **白名单而不是黑名单**：允许的只有「数字 + 逗号两侧空白 + 段首尾空白」。别去逐个禁止非法字符，漏一个就漏一类。
3. **`\d` 匹配的是 Unicode 十进制数字**：`"٥١٢,٧٦٨"`（阿拉伯-印度数字）同样能通过并得到 `(512, 768)`；`int()` 也接受它们。这是上游的真实行为，本题不为它单独设断言，但实现应沿用 `\d` + `int()` 的组合。
4. **0 尺寸的错误消息被包了两层**：上游先 `raise ValueError("Bucket dimensions must be positive integers.")`，而这一句在 `try` 之内，于是被外层的 `except ValueError` 再包成 `Invalid integer in bucket pair '0,0': Bucket dimensions must be positive integers.`。照抄这段嵌套 `try` 才拿得到同样的消息。
5. **警告的粒度是桶，不是边**：上游的条件是 `if height % 8 != 0 or width % 8 != 0:`，一个 `warnings.warn`、一条消息，因此 `"3,5"` 只发一条而不是两条。把警告写进两个独立 `if` 是本条最容易写错的细节。
6. **警告不是错误**：不能整除 8 的桶照样返回。上游的理由是某些 VAE 的 patch size 不是 8，只是「可能会有问题」。
7. **顺序与重复**：不排序、不去重。分桶清单的先后会影响 `find_nearest_bucket` 的并列裁决（并列取更靠后的桶），所以顺序是语义的一部分。
8. **只有 `;` 是分隔符**：`|`、换行、空格都不切分；`"512,768|256,256"` 会在正则那一关失败。段首尾的换行则因为整体 `strip()` 而被去掉。
9. **空白串的失败位置**：`"   "` 不是「空串」，不会命中 `if not buckets_str`，而是 `strip()` 后得到 `""`、`split(";")` 得到 `[""]`、再在正则处失败。两条路径都抛 `ValueError`，但走的是不同分支。

## 对拍口径

无张量参与的纯字符串题，判题用两组独立断言：

- **独立实现对拍**：`_alt_parse` 不用正则，改成 `split(",")` + `str.isdigit()` 判定 + `int()` 转换，与参考解在 7 个合法样例上要求完全相同的返回值、在 20 个非法样例上要求**都**被拒；
- **行为契约**：返回值类型（list / tuple / int，且不是 bool）、`0` 尺寸与非法分隔符的错误消息关键字、警告的条数与消息关键字（含「两条边都不合规也只发一条」「两个坏桶各发一条」「两边都对齐时不发」三种情形）、`|` 不作分隔符、末尾换行被去掉、重复桶不合并。

共七组断言，覆盖示例、返回类型、警告、非法输入、错误消息、独立实现对拍、分隔符语义。

## 复杂度

对输入长度 \(n\) 做一次 `strip` + 一次 `split` + 每段一次正则匹配，\(O(n)\) 时间、\(O(k)\) 空间（\(k\) 为桶数）。

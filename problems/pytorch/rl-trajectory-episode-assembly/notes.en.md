# Deep dive: Multi-segment rollout assembly and truncation bootstrap

## Origin

- **The Gymnasium / gym ≥ 0.26 Env API** splits "the episode ended" into two unrelated booleans: `step()` returns `(obs, reward, terminated, truncated, info)`. `terminated=True` means the run genuinely reached an absorbing state (goal / failure / EOS / a tool deciding the conversation is over); `truncated=True` means the environment was *not* finished — the harness cut it off, via `TimeLimit` (`max_episode_steps`) or, on the LLM side, `max_new_tokens` / `max_turns`. `gymnasium.wrappers.TimeLimit` sets `info["TimeLimit.truncated"] = True` with `terminated=False` when the step budget expires. The two 0/1 vectors `terminated` / `truncated` in this problem are exactly those two booleans logged per step, and **they are mutually exclusive** (the statement guarantees: every segment carries exactly one flag, at its last step only, i.e. XOR = 1 there).
- **The value of an absorbing state is 0**: this is definitional in the episodic return decomposition (Sutton & Barto, *Reinforcement Learning: An Introduction*, ch. 3 on episodic tasks) — there is no future reward after termination, hence \(v(\text{terminal})\equiv 0\). That is the entire reason "a true termination must never be bootstrapped".
- **A truncation must be bootstrapped**: the consensus convention across PPO implementations (dropping it is a systematic bias). The formal discussion that treating a timeout as a terminal state breaks the Markov property / injects bias goes back to Pardo et al. (2018) on augmenting timeouts into partially observed environments (**arXiv id to be re-sourced — deliberately not written from memory**).
- This problem only **delivers** the \((r, V, next\_value, done)\) sequences; the recursion \(\delta_t\) / \(\hat A_t=\delta_t+\gamma\lambda\hat A_{t+1}\) belongs to `to-gae` (Schulman et al., *High-Dimensional Continuous Control Using Generalized Advantage Estimation*, arXiv:1506.02438).

## Full derivation and index conventions

Nail down the three index spaces first — half of the bugs here are "index spaces got crossed":

- \(t\in[0,T)\): **arrival order**, the physical position in the rollout buffer;
- \(e\in[0,K)\): the **segment number**, \(K\) = number of maximal contiguous segments;
- \(i\in[0,T)\): **training order**, the physical position in the output arrays.

1. **Segmentation**: \(\text{run}_t=\sum_{s\le t}\big[s=0 \lor ep_s\ne ep_{s-1}\big]-1\in\{0,\dots,K-1\}\) (segment ids via `cumsum`). Because one episode's steps form exactly one maximal contiguous run and ids are globally unique and never reused, "segment" ≡ "episode", and `run` is precisely the index space of `final_value`.
2. **Segment end / done**: \(\text{last}_t=(t=T-1)\lor(ep_{t+1}\ne ep_t)\), \(done_t=\text{last}_t\). The last step of a truncated segment is \(done=1\) too.
3. **Re-ordering**: segments are sorted by ascending \(ep\) id, so training slot \(e\) corresponds to some arrival segment; steps keep chronological order inside a segment. `lengths` (per-segment step counts in training order) and `starts` (exclusive prefix sum) follow, and a single length-\(T\) `gather` index moves all five \((T,)\) arrays into training order at once. **Do not confuse \(K\) with "which training slot"**: in the arrival run `[7,7,7,3,3,8,8,8]`, id=3 is arrival segment 1 but training segment 0.
4. **The next_value three-way rule** (computed in arrival order first, gathered last):
   \[
   nv_t=\begin{cases} V_{t+1}, & \neg\,\text{last}_t\\[2pt] final\_value[\text{run}_t], & \text{last}_t\land truncated_t=1\\[2pt] 0, & \text{last}_t\land terminated_t=1\end{cases}
   \]
   The vectorized form is "roll the whole array (`nv[:-1]=V[1:]`), then **overwrite** every segment-end position with `nv[is_last] = where(truncated, final_value[run], 0)`". At a segment end the roll brings in the **first value of the neighbouring segment** (the leak), but it is always overwritten; the very last array position rolls out-of-range to 0 and is also always overwritten (\(\text{last}_{T-1}\) is true by definition). Never invert this "pollute first, overwrite after" order.
5. **How the consumer uses it** (`to-gae`'s business, stated here only to mark the seam): with the assembled per-segment \((r_i, V_i, nv_i)\), \(\delta_i=r_i+\gamma\,nv_i-V_i\) holds for **every** \(i\) as one single formula — no bounds test, no in-segment/at-boundary branch. On the advantage side one then uses the done-masked recursion \(\hat A_i=\delta_i+\gamma\lambda(1-done_i)\hat A_{i+1}\), which is strictly equivalent to "loop per segment over \([\text{starts}_e,\text{starts}_e+\text{lengths}_e)\) and reset the accumulator to 0 at each segment end".

**Measured numbers (all produced by `solution.py`)**:

- The statement's example (ids 7/3/8; segment 0 truly terminates, segments 1 and 2 are truncated), training order:
  `values=[0.25,0.375,0.5,0.625,0.75,0.125,0.25,0.3125]`, `dones=[0,1,0,0,1,0,0,1]`,
  `next_values=[0.375,0.875,0.625,0.75,0.0,0.25,0.3125,0.625]`, `lengths=[2,3,3]`, `starts=[0,2,5]`;
  with \(\gamma=1\): \(\delta=[0.625,2.5,1.125,0.125,-0.25,1.125,1.0625,0.3125]\).
- A naive `roll(-1)` over the arrival array yields `[0.625,0.75,0.25,0.375,0.125,0.25,0.3125,0.0]`: position 2 (last step of id=7) gets **0.25** (first value of the id=3 segment) and position 4 (last step of id=3) gets **0.125** (first value of the id=8 segment) — both cross-segment leaks; the correct values are 0.0 and 0.875.
- **Multi-turn LLM-RL variant** (one episode = one conversation, one step = one assistant turn, the segment-end flag = how that conversation's final generation ended): arrival `episode_id=[12,12,12,5,5,5,5,9]` (id=12 terminates on EOS after three turns; id=5 is four turns cut by `max_new_tokens`; id=9 is a **single-turn** conversation that is also cut), `terminated=[0,0,1,0,0,0,0,0]`, `truncated=[0,0,0,0,0,0,1,1]`, `values=[0.125,0.25,0.375,0.5,0.625,0.75,0.875,0.0625]`, `rewards=[0.0,0.0,1.0,0.5,0.5,0.5,0.5,2.0]`, `final_value=[0.5,0.9375,0.1875]` (indexed by arrival segment) → training order (ids ascending 5, 9, 12):
  `actions=[11,12,13,14,7,101,202,303]`, `rewards=[0.5,0.5,0.5,0.5,2.0,0.0,0.0,1.0]`, `values=[0.5,0.625,0.75,0.875,0.0625,0.125,0.25,0.375]`,
  `dones=[0,0,0,1,1,0,0,1]`, `next_values=[0.625,0.75,0.875,0.9375,0.1875,0.25,0.375,0.0]`, `lengths=[4,1,3]`, `starts=[0,4,5]`.
  Position 4 is that **single-turn truncated** conversation: first step = last step, yet it must still bootstrap `0.1875` — never skip it because "this episode has only one step". Turn boundaries (who follows whom) have nothing to do with token boundaries: assembly works at turn granularity, token-level masks are the SFT-side problems' job.

## Core points and classic mistakes

1. **Which step owns the flag.** The three-way rule reads the flag at the **segment's last step**, not "this step ends an episode by itself". The contract guarantees the flag sits at the segment end with XOR = 1. If the data marks a truncation in the middle of a segment (or leaves the segment end flagless), the "correct output" simply does not exist under the contract. The ⓪ input-legality self-check in the invariant probe guards exactly this — two fixtures once misplaced the truncation flag, which turned the judge into "force the reference solution to violate the contract".
2. **Each of the two mixes biases in exactly one direction** (measured; the leaked/spurious quantity is precisely \(V_{end}\)):
   - Truncation treated as termination (**bootstrap dropped**): the last step's \(\delta\) loses \(\gamma V_{end}\). For the id=5 segment above, the correct last-step \(\delta=0.5+0.1875-0.875=-0.1875\); zeroing gives \(-0.375\) (short by 0.1875); a naive roll gives \(-0.3125\) (short by the neighbour's first value 0.0625). On the critic side this systematically deflates the value of "near the generation limit" states; on the policy side every truncated sample gets a negative advantage across its tail.
   - Termination bootstrapped (**bootstrap added**): the last step's \(\delta\) gains \(\gamma V_{end}\). For the truly terminated id=7 segment of the example the correct \(\delta=0.5+0.0-0.75=-0.25\), while wrongly using `final_value[0]=0.9375` gives \(+0.6875\). The absorbing state is paid a future value it does not have, so "failed / was cut off" becomes indistinguishable from "a valuable continuation" — this is the entry point of the "just stall until the limit and it counts as a good ending" family of reward hacking.
   Because the two mistakes push in opposite signs, "the numbers look plausible" is not a self-check; only the flag branch can be right.
3. **done ≠ "the episode really ended".** `done` is a **structural** bit meaning "do not treat the next record of the concatenated array as your successor"; it simultaneously blocks two things: the roll from crossing segments, and the advantage recursion from carrying across a segment boundary. A truncated end has \(done=1\) with \(nv=V_{end}\); a terminated end has \(done=1\) with \(nv=0\). Reading done as terminated makes you zero \(nv\) at every done position, which degenerates into mistake 2's first branch.
4. **Never infer "terminated" from \(nv=0\).** A truncated segment's \(V(s_{end})\) can legitimately be \(0.0\) (zero-value terminal observation, or 0 after reward/value normalization). Measured: `episode_id=[4,4,2]`, `truncated=[0,1,1]`, `final_value=[0.0,0.75]` → training `next_values=[0.75,0.5,0.0]`, where position 2 is a *bootstrap* yet equals 0. Termination vs truncation can only be recovered from the flags (done + flag as two dimensions); any "guess the boundary from the numbers" implementation silently breaks on batches containing zeros.
5. **The done-mask cannot be skipped.** Running the backward recursion over the whole concatenated array without resetting, on the statement's example, gives \(\hat A = [5.788627,5.435397,3.089891,2.068307,2.045586,2.416406,1.359375,0.3125]\): position 4 — the truly terminated last step of the id=7 segment — should be \(-0.25\) but is flooded to \(2.045586\) by the *next* episode's (id=8) advantage. Correct options: loop per segment using `starts/lengths`, or multiply by \((1-done_i)\); the two are strictly equivalent, and the done-masked run measures `[3.0,2.5,1.018125,-0.1125,-0.25,2.416406,1.359375,0.3125]`.
6. **`final_value`'s index space.** It is indexed by **segment arrival number** (`run_idx`), not by the sorted training slot and not by the lexicographic rank of the id; a truly terminated segment's entry exists but is never read (in the example `final_value[0]=0.9375` never appears in the output). Writing `boot = final_value[slot]` instead of `final_value[run_idx]` is a pure permutation off-by-error, and it is only wrong on out-of-order batches — ascending-id batches come out perfectly, which is the sneakiest class of bug (`check_sorted_ids_identity` exists for this).
7. **Degenerate and boundary conventions.** The maximal-run definition guarantees **segment length \(\ge 1\)**, so `lengths` never contains a 0, \(K=\) number of distinct ids, and \(starts_{K-1}+lengths_{K-1}=T\). An "empty episode" does not exist under the contract — a conversation with zero turns must be dropped before it enters the buffer, otherwise it would consume a `final_value` slot with no steps to own it. \(T=0\) (then \(K=0\) and `final_value` is empty too) follows the empty convention: seven 0-element tensors with dtypes `int64/float32/float32/int64/float32/int64/int64`, no exception. When ids already arrive ascending the `gather` degenerates to the identity and no rule changes. Outside the contract, id reuse (e.g. `[3,5,3]`) is not judged; the reference solution's actual behaviour is "three segments, `lengths=[1,1,1]`", i.e. it treats the two same-id runs as two episodes.

## Differences from neighbouring problems

- **`to-gae` (the seam must be pinned exactly).** `to-gae` derives \(\hat A\) and \(R\) from an **already-assembled** single \((r_0..r_{T-1}, V_0..V_{T-1})\) sequence; in its \(\delta_t=r_t+\gamma V_{t+1}-V_t\) the \(V_{t+1}\) comes from an **in-array right shift**, and out of range it hard-codes \(V_T=0\) — which is exactly the special case "this array's last step is a true termination and the array holds only one episode". This problem computes **no** \(\delta\), no sums, no recursion; it only hands over \(r, V, next\_value, done, lengths, starts\). The seam is precisely **where the last step's \(V_{t+1}\) comes from**: `to-gae` assumes 0, this problem decides — from the flag — whether it is 0 or \(V(s_{end})\), and makes "one array is actually K episodes" explicit through done/offsets. Measured on the statement's example with \(\gamma=1,\lambda=0.95\): feeding `to-gae` each training segment gives the truly terminated id=7 segment `advantages=[1.018125,-0.1125,-0.25]`, position-by-position identical to the done-masked result (there \(nv_{end}=0\) matches its \(V_T=0\) assumption); the truncated id=3 segment gives `[2.168750,1.625]` from `to-gae` versus `[3.0,2.5]` from the done-masked recursion using \(nv_{end}=0.875\), the gaps being exactly \(V_{end}=0.875\) and \(\gamma\lambda V_{end}=0.831250\). That gap is **entirely the assembly layer's responsibility** — `to-gae` cannot infer it from any information it receives (it is not even given a flag). On the other side: `to-gae` is single-segment \((T,)\to\) 2-tuple, with no id, no flags, no re-ordering, no gather.
- **`data-collator` / `sequence-pack-pad`**: SFT-side batching — pad/collate into token-level `input_ids/attention_mask/position_ids/labels` plus cu_seqlens-style boundaries. Similar in shape (both "pack variable-length records into a training batch"), different in substance: those have **no \(V\), no done, no bootstrap at all** — a boundary only changes the mask, never a numeric branch. This problem emits no token-level tensor; `actions` is just an int64 column passed through. Here the boundary changes **the successor value of every position**.
- **`rl-rollout-shard-repack`**: cross-rank re-sharding and padding-free bin packing — load balancing, number of moves, padding cost. It moves **already-assembled samples**; this problem reconstructs **the samples themselves** (segment boundaries and value alignment). Both work on "multi-segment mixed" streams, but this one is single-process and rank-agnostic.
- **`rl-reward-batch-norm`**: the batch-statistics side (running mean/std, per-group vs global normalization) acting on the reward distribution; it is insensitive to segment boundaries and flag semantics, and it produces no boundary information. This problem computes no statistics and never rewrites a reward value.
- **`rl-async-rollout-staleness`**: the generation queue and staleness accounting (partial rollout, off-policyness over time). This problem assumes all rollouts have already landed as explicit tensors; there is no time/staleness semantics — "out of order" here means only that segments are permuted inside the buffer.

## Cross-check setup

The reference solution takes the vectorized path: `cumsum` for segment ids → `bincount` for segment lengths → `argsort` for segment order → one `gather` to collect the five \((T,)\) arrays, with next_value rolled over the whole array then overwritten at segment ends by `where`. The judge's `_oracle` takes a structurally disjoint path: explicit segment scanning into `(id, arrival_no, [step indices])` → Python `sorted()` on segment ids → a plain inner `for` loop applying the three-way rule → building tensors from Python lists; the two share no intermediate. Besides the statement example (`check_example`) there are four rule probes (cross-segment leak, single-step segments, all-truncated, all-terminated), the \(T=0\) empty convention, and the ascending-id identity gather; then an 11-case deterministic battery (out-of-order / ascending / single-step segments / T=1 / all-truncated / all-terminated / mixed multi-segment) comparing all seven outputs position by position, plus one **oracle-independent** structural invariant probe: input flag legality, \(\sum lengths=T\), the `starts` prefix-sum accounting, `sum(dones)=K`, "training segment \(e\)'s values slice equals the arrival-order slice of the e-th smallest id" (note this must pair arrival-order indices with the arrival-order values and training-order indices with the output values — mixing the two index spaces was this probe's original bug), the done-position bootstrap counts matching the flag counts, and \(nv_i=V_{i+1}\) at every non-done position. Nothing is random anywhere; all episode data is explicit input.

## Complexity

\(O(T + K\log K)\) (the `argsort` over segment ids); no Python loops and no branch synchronization, a single gather; \(O(T)\) memory with \(T\le 4096\).

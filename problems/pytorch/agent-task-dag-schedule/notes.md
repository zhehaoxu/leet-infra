# 解题说明 · 任务 DAG 调度

## 三个输出其实是三个问题

- `order` 是**执行协议**：真正下发给 worker 的次序，必须合法且唯一；
- `waves` 是**并行度规划**：同时最多能跑几个，决定池子大小；
- `crit` 是**性能下界**：无论加多少 worker，总耗时都不会低于它。

把它们放在同一题里，是因为三个答案共享同一份图信息，却各有各的坑：只算拓扑序会漏掉关键路径，只算关键路径会漏掉波次。

## 拓扑序为什么要定死并列

Kahn 算法里「就绪集合」通常是个队列，而出队顺序取决于遍历顺序，同一张图能排出几十种合法结果。判题要逐元素比，就必须把并列压成一个确定规则：**取编号最小的就绪任务**。这等价于用小顶堆，也等价于「每次扫描一遍、找第一个所有前驱都已完成的任务」——后者更慢但更容易验证，正好拿来做 oracle。

顺带一个常见 bug：把「入度为 0」当作「立刻可执行」，于是 3 个源点一次性全排到前面，掩盖了它们其实可以并行的事实。

## 波次 = 最长前驱链

`level[v] = 1 + max(level[u])`，取的是**最长**而不是最短：如果 A 有两层的前驱链，它最早也只能在第 2 波执行。写成最短链会让「前驱必须全部完成」的约束失效——那是最容易在 review 里漏掉的一行。

波次划分同时给出最大并行度 `max(len(wave))`。注意它只是「图本身的宽度」，真实系统的并发还受 worker 数与显存约束。

## 关键路径为什么必须带权

不带权时「最长链」就是 hop 数，恰好等于 `max(level) + 1`，与波次数重复，题目就退化了。带上 `cost` 之后，菱形 `0 -> 1 -> 3`（5+1）与 `0 -> 2 -> 3`（2+1）必须选前者，这类结构正是分布式任务里「短任务走并行、长任务走关键路径」的来源。

实现上关键路径与 `level` 可以一趟算完：出队时把 `best[u] + cost[u]` 推给后继取 `max`，最后 `max(best[v] + cost[v])`。

## 复杂度与真实系统

O(V + E log V)（堆）或 O(V²)（朴素扫描）。真实调度器还要处理：任务动态追加、运行时耗时未知（用历史分位数预估）、失败重试与幂等、跨机器数据传输成本——但那些都建立在「拓扑序 + 波次 + 关键路径」这三块骨架上。

# 详解：Soft-NMS 置信度连续衰减

## 出处

- Bodla et al., *SoftNMS: Improved Non-Maximum Suppression Algorithm*（ICCV 2017, arXiv:1704.04503）。原文的动机是硬 NMS 在**近距离成对目标**（互相遮挡的行人）上会把第二真值直接吃掉；软版把"删框"换成"按重叠度连续压低置信度"，并给出线性（分段）与高斯两种衰减核。
- 具体常数与式子形状以 starter docstring 为唯一判题口径：线性核用**严格大于**的硬阈值门控并乘 \((1-\text{IoU})\)，高斯核无条件乘 \(\exp(-\text{IoU}^2/\sigma)\) 且完全不看阈值。这套两核形状与 detectron2 等检测框架里的 `SOFT_NMS` 后处理一致；论文里同一高斯核的温度记作 \(t\)，本仓库沿用更常见的 \(\sigma\)。
- IoU 内核复用本仓库 `iou-compute` 口径，不做坐标口径转换（cxcywh 不在本题）。

## 完整推导与下标约定

**下标约定**：原始下标 \(i\in\{0,\dots,N-1\}\)，当前分数向量 \(s\in\mathbb R^N\)（初值即输入 scores），活跃集 \(A\)（初值为全集）。第 \(k\) 轮选中 \(\arg\max_{i\in A}s_i\)（并列取最小 \(i\)），记入列序 \(M\)。

**单轮更新的精确式**：设本轮选中 \(b\)，则对每个 \(j\in A\setminus\{b\}\)：
\[\text{linear: } s_j\leftarrow s_j\cdot\begin{cases}1-\mathrm{IoU}(b,j),&\mathrm{IoU}(b,j)>\text{iou\_thr}\\[2pt]1,&\text{否则}\end{cases}
\qquad
\text{gaussian: } s_j\leftarrow s_j\cdot e^{-\mathrm{IoU}(b,j)^2/\sigma}\]
随后 \(A\leftarrow A\cap\{j:s_j\ge \text{score\_thr}\}\)，且 \(b\) 从 \(A\) 中移除（**入列即出局，永不复现**）。

**为什么必然停机**：每轮 \(A\) 至少少一个元素（选中的 \(b\)），剔除只会让它更小，所以轮数 \(\le N\)。衰减因子恒 ∈ \([0,1]\)（linear 的 \(1-\text{IoU}\) 在 IoU=1 时恰为 0，分数归零后必被 `score_thr` 剔除；gaussian 的指数恒正），故每个 \(s_j\) **单调不增**——这是"入列分数 ≤ 原始分数"的证明，也是 `score_thr` 只需在衰减后检查一次的理由。

**输出顺序为什么不是输入分数降序**：示例给出 `keep_indices=[0,2,1]` 而非 `[0,1,2]`。框 1 在第 1 轮被压到 0.2555，低于本来更低的框 2（0.7），于是第 2 轮赢家换人。**这正是 soft-NMS 的行为特征**：低分但独立的框可以排到"高分但与已选框重叠"的框前面。硬 NMS 里没有这个现象，因为它不做数值改写，输出序恒等于存活框的原分数降序。

**两个核的形状差异**：linear 是**分段**的——\(\text{IoU}\le\) 阈值时因子恰为 1（完全不动），越过阈值才跳变到 \(1-\text{IoU}\)；这保留了硬 NMS 的"低重叠不惩罚"直觉，代价是在阈值处不连续（判题的 0.5/0.5 与 0.499999 两个用例就踩在这个不连续点上）。gaussian 处处衰减、无阈值，IoU=0 时因子恰为 \(e^0=1\)，IoU=1 时是 \(e^{-1/\sigma}\)（\(\sigma=0.5\) 即 0.1353）——**永远不为 0**，所以 gaussian 下"完全重合的框"仍能以极小分数存活（除非被 `score_thr` 剔除）。

**并列与 \(-\infty\) 掩蔽**：把非活跃位填 \(-\infty\) 后 `argmax` 返回**首个**最大值下标，天然满足"并列取最小原始下标"。等价地，oracle 用从左到右扫描 + 严格 `>` 更新 best，同一语义的两种实现。注意 \(-\infty\) 必须只在掩蔽位出现，且循环条件要保证 \(A=\varnothing\) 时不再调用 argmax（全 \(-\infty\) 时 argmax 仍返回 0，会选出已删除的框）。

**`score_thr` 不做预筛**：判题有 \(N=1\)、scores=[0.0] 的用例，它**必须**返回 `[0]`。可见 `score_thr` 只作用于"某轮衰减之后"，首轮赢家无条件入列——与 docstring 的"N≥1 时首轮最高分框必被保留"一致。写成"先把低于阈值的框全删再迭代"会直接判错。

**剔除必须是 `active &=`**：若把阈值判断写成 `active = cur >= score_thr`（赋值而非与），已选中的框会因分数仍高而**复活**并被二次入列——这是本类实现最常见的越界错误。同理，衰减只应作用在活跃位上（用 `torch.where(active, ...)`），否则虽不影响输出，但会把"分数已被淘汰的框"重新算一遍，掩盖上面的 bug。

## 核心与易错点

1. **先记录、后衰减**：入列分数是"被选中那一刻"的值；顺序颠倒会把选中框自己也乘一遍因子。
2. **linear 的严格大于**：\(\text{IoU}=\text{iou\_thr}\) 不衰减（判题用 IoU 恰为 0.5 的框对钉死这点）。
3. **gaussian 不看 iou_thr**：IoU≈0.005 也必须衰减；反过来 IoU=0 时因子恰为 1，不相交框分数逐位不变（`torch.equal` 级）。
4. **sigma 的"忽略"不是"校验"**：linear 下 sigma=-5 也必须正常返回。
5. **`score_thr` 是严格小于才删**：等于阈值保留。
6. **选中即出局**，永不复现；剔除只能收窄活跃集。
7. **N=0** 返回 long 与 float 两个 (0,) 空张量（dtype 也要对，判题查 dtype）。
8. **错误面**：非法 method ValueError；gaussian 且 sigma≤0 ValueError；其余参数越界（如 iou_thr 在 gaussian 下被传入）不得报错。

## 与邻近题的区别

- **vs `nms`（硬版，本仓库题）**：硬版按分数降序贪心、命中 `IoU > iou_thresh` 就**删框**，只返回下标、分数永不改动；soft-NMS 保留抑制条件同为"严格大于"，但把删除换成乘 \((1-\text{IoU})\)，因此额外返回"入列那一刻的分数"，且输出顺序可能与原分数降序不同。本批次示例的对照（硬版 `[0,2]` vs 软版 `[0,2,1]`）就是这道题的判别锚点。
- **vs `iou-compute` / `iou-variant-losses`**：那两题算 IoU 本身（或其回归损失）；本题把 IoU 当**打分函数**用于置信度调制，方向是分数端而非坐标端。IoU 内核与 `nms`、`iou-variant-losses` 同口径，可直接对照。
- **vs `topk-select` / `sort-argsort`**：本题输出顺序**不是**分数的排序结果（见上文"为什么顺序会变"），不能用"排序 + 截断"近似——判题的 `[0,2,1]` 恰好在原分数降序 `[0,1,2]` 之外。

## 对拍口径与复杂度

- oracle `_oracle` 是**结构完全不同的实现**：Python 列表 + 显式 while、逐个 `max` 扫描、逐框乘因子、逐框判阈值；IoU 用内置 `max/min` 的标量版 `_py_iou`。索引序列用 `tolist()` 精确比对（顺序与并列语义全被钉住），分数用 \(10^{-5}\) allclose。
- 12 组固定种子随机框 × {linear, gaussian} × {默认参数, 自定义 iou_thr=0.55/sigma=0.3/score_thr=0.05}，覆盖"低阈值多衰减""高阈值几乎不衰减"两个极端。
- 判别性用例专抓语义而非数值：不相交框组 → 输出恒为原分数降序、分数逐位不变（`torch.equal`）；IoU 恰 0.5 的框对 → 阈值 0.5/0.3/0.499999 三种取值的衰减/不衰减边界；微重叠（IoU≈0.005）→ gaussian 衰减而 linear 不衰减的**对照断言**；极端 `score_thr` → 只剩首轮赢家；\(N\in\{0,1\}\) 与非法 method/sigma 的错误面。
- 复杂度：预计算 IoU 矩阵 \(O(N^2)\)（内存也是 \(O(N^2)\)），每轮 \(O(N)\) 选择 + \(O(N)\) 衰减，共 \(\le N\) 轮 → 总时间 \(O(N^2)\)。逐轮重算 IoU 的实现会把常数放大 \(N\) 倍但仍同阶；oracle 的纯 Python 版是 \(O(N^3)\) 级（每轮对每框重算 IoU 的标量函数被反复调用），这是它只做小规模用例的原因。

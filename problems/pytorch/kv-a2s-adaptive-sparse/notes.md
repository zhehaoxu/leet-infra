# 解题说明 · A2S 自适应稀疏

## 两个解耦的机制

这道题把「候选从哪来」与「取多少个」拆成两步，这是理解 A2S 的关键：

- **候选从哪来**：为了省掉当步的全量打分，候选只能是上一步的 top-\(k\)。注意力在相邻解码步之间高度相关，所以这个先验通常很准。
- **取多少个**：候选定了之后，用**当步**分数在候选内排序并累计到 \(p\) 的质量，得到自适应的 \(n\)。注意力集中的步 \(n\) 很小，分散的步 \(n\) 会顶到候选上限。

如果两步都做对，结果是「用上一步的索引 + 当步的少量比较」就完成稀疏选择。任何一步写错都会退化：候选用当步全量 → 省不下打分；排序用上一步分数 → 变成固定 top-k。

## 为什么 n 必须自适应

固定 n 的问题是双向的浪费。注意力集中在少数 token 时，多算的那些 key 对输出几乎没有贡献，纯属白费带宽；注意力分散时，固定 n 只能覆盖一半质量，精度直接掉。质量阈值 \(p\) 把「够不够」变成可度量的标准：累计到 \(p\) 就停。这也让 \(p\) 成为一个单调的旋钮——\(p\) 越大，\(n\) 越大，精度/延迟的权衡变成一维搜索。

## 近似性的代价

候选集来自上一步就必然有漏检：某一步注意力突然跳到上一步没选中的 token 上（新实体、新指令、格式突变），A2S 会因为候选里没有它而完全看不到。这不是 bug，而是「省一次全量打分」的固有成本；工程上用「定期做一次全量刷新」或「sink 位始终保留」来兜底。

题目用 `pattern_reuse_limits_recall` 把这条代价钉死：当步分数最高的 token 如果不在上一的 top-\(k\) 里，就必须不入选。

## 边界与并列

- 当步总质量为 0（极端稀疏或全零输入）：累计恒为 0，`>= pT` 在 \(m=1\) 即成立，于是 \(n=1\)。这保证了「至少选一个」的语义，也避免除零。
- 候选数在早期步受有效列限制：解码刚开始时有效列可能少于 \(k\)，此时候选数就是有效列数，`n` 的上界随之收缩。
- 所有排序都是「降序 + 并列取小下标」，与全库一致；浮点比较留 \(10^{-12}\) 容差，避免累加误差让边界用例随机翻面。

## 复杂度

每步 \(O(k\log k)\)（候选内排序）而不是 \(O(L\log L)\)（全量排序），这是稀疏化的主要收益。累计质量是 \(O(n)\le O(k)\)。总时间 \(O(Sk\log k)\)，空间 \(O(SL)\)（输出掩码）。

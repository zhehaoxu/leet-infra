# 推测解码：在线后缀自动机与最长后缀匹配

## 题目描述

Suffix Decoding / REST 这类方法把「历史出现过的后缀」当成免费的草稿来源：给定当前上下文，去历史里找**最长的、能对上的后缀**，然后把它后面跟着的那几个 token 当作草稿。要在线做这件事（生成过程中不断把新 token 塞进索引、随时查询），需要一个支持增量的结构，后缀自动机（SAM）就是标准答案：状态数 \(O(N)\)、建机 \(O(N)\)、查询 \(O(P)\)。

SAM 的核心不是「把子串存下来」，而是**把子串按 endpos 集合等价类压缩**：两个子串的 endpos（在原串中所有出现位置的结尾集合）相同，就说明它们在任何上下文里都同进同出，可以合并成一个状态。于是：

- 每个状态 \(s\) 代表一族长度连续的子串，长度范围是 \((\text{len}[\text{link}[s]],\ \text{len}[s]]\)；
- 不同子串总数 = \(\sum_{s\ne \text{root}} \big(\text{len}[s]-\text{len}[\text{link}[s]]\big)\)；
- 状态数不超过 \(2N-1\)（最小 DFA 的上界）。

建机是增量的：每加一个字符，就新建一个状态、沿后缀链接补转移；如果某条转移指向的状态「长度不匹配」，就**克隆**它——这是 SAM 唯一容易写错的地方，也是本题专门用重复串来考的。

查询侧同样是增量的：维护「当前匹配到的状态 + 当前匹配长度」，每来一个字符，若能转移就前进，不能就沿 link 回退到能转移的祖先（回退时匹配长度同步收缩为 `len[link]`），回到初始状态仍无法转移就把长度归零。这样每一步的答案就是「以当前位置结尾的最长后缀，且该后缀是原串的子串」。

## 任务

实现 `solve(text, pattern)`：

- 输入：`text`（`(N,)` int64，语料，\(N\ge 1\)）；`pattern`（`(P,)` int64，查询，可为空）。
- 输出：
  - `n_states`（int64 标量）：自动机状态数（含初始状态）；
  - `distinct`（int64 标量）：`text` 的不同子串数；
  - `match_len`（`(P,)` int64）：`match_len[i]` 是 `pattern[:i+1]` 的最长后缀中、仍为 `text` 子串的长度。
- `text` 为空或任一输入非一维，抛 `ValueError`。
- 复杂度要求：建机 \(O(N)\)、查询 \(O(P)\)，不能对每个位置暴力枚举后缀。

## 示例

```
text    = [1, 2]
pattern = [1, 2, 1, 3]

建机后状态（root 记 S0）：
  S0: len 0
  S1: len 1, link S0   （"1"）
  S2: len 2, link S0   （"2" / "12" 合并成一族：长度范围 (0, 2]）

n_states = 3
distinct = (1-0) + (2-0) = 3        # "1", "2", "12"

查询：
  "1"   -> 转移存在，match_len = 1
  "12"  -> 继续前进，      match_len = 2
  "121" -> 沿 link 回退，  match_len = 1   （"1" 是子串，"21"/"121" 不是）
  "1213"-> 回退到 root 仍无转移，match_len = 0

match_len = [1, 2, 1, 0]
```

## 约束

- **状态数不等于子串数**：S2 同时代表 "2" 与 "12"，因为它们的 endpos 都是 `{2}`；用「每个子串一个状态」的 trie 会退化成 \(O(N^2)\) 节点。
- **克隆必须发生**：新字符让某个状态的 endpos 集合分裂时，必须克隆出一个短状态并把一部分转移改指过去，否则状态数会虚高、`distinct` 会算错。本题用 `[1,2,2]` 明确要求出现分裂（状态数 5 > n+1）。
- **回退时 `match_len` 要跟着收缩**：沿 link 跳到 \(t\) 之后，当前匹配长度应直接取 `len[t]`，而不是减去某个数。
- **查询长度可以为 0**：`pattern` 为空时返回空张量，但 `n_states`/`distinct` 仍要正常给出。
- 词表大小不限（token id 可以任意大），用字典转移而不是按字母表开数组。

# 解题说明 · 后缀自动机

## 为什么不是 trie

如果为每个后缀建一条 trie 路径，节点数是 \(1+2+\dots+N = O(N^2)\)；即使只存子串，最坏也是 \(O(N^2)\)。SAM 的关键压缩是：**endpos 相同的子串合并**。endpos 相同意味着它们在任何上下文里出现的位置完全一致，后续行为也一致，因此可以在同一个状态上存放一族长度连续的子串。

于是「一个状态」携带三样信息：`len`（这一族里最长子串的长度）、`link`（上一层等价类，代表更短的那批后缀）、`trans`（转移表）。`link` 链就是「把当前后缀不断削短」的路径，它天然是一条从长到短的后缀链，这正是查询侧能 \(O(1)\) 摊还回退的原因。

## 增量的三个动作

每来一个字符 `c`：

1. 新建状态 `cur`，`len[cur] = len[last] + 1`；
2. 从 `last` 沿 `link` 往上，把所有「还没有 `c` 转移」的状态指向 `cur`；
3. 找到第一个已经有 `c` 转移的祖先 `p`，它指向 `q`：
   - 如果 `len[p] + 1 == len[q]`，直接 `link[cur] = q`；
   - 否则 `q` 的 endpos 集合被新字符「切开」了，需要克隆出一个 `len = len[p]+1` 的 `clone`，把 `q` 的部分转移和 link 转移过去，再把 `link[q]` 与 `link[cur]` 都设成 `clone`。

第 3 步的分裂是 SAM 唯一容易漏的分支。漏掉它时，`distinct` 会偏大（把同一批子串算了两遍），状态数也会偏小。

## 查询侧的回退

维护 `(state, best)`。来一个字符 `c`：

- 若 `state` 有 `c` 转移：前进，`best += 1`；
- 否则沿 `link` 不断回退，直到有转移或回到 root；每回退一步 `best = len[state]`（新的 state 的最长长度就是还能保留的匹配长度）；
- 回到 root 仍无转移：`state = root`，`best = 0`。

`best` 的含义是「以当前位置结尾、且出现在语料里的最长后缀长度」——正好是 suffix decoding 想要的「能对多长的后缀」。真实实现里它决定草稿长度，一旦 `best` 不够就退回 n-gram 池或直接不投机。

## 容量与老化

SAM 本身不淘汰状态（状态数是 \(O(N)\) 的硬上界，但长上下文里 \(N\) 会一直涨）。工程上 REST / Suffix Decoding 会定期重建或按哈希分片，把「容量管理」放在自动机之外，因此本题只考自动机本身的正确性，容量与老化放到 `spec-ngram-pool-aging` 里单独考。

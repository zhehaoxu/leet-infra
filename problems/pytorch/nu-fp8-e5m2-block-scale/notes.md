# 详解：块尺度为什么取「最小的不溢出 2 的幂」，以及次正规区什么时候才可达

## 出处

E5M2/E4M3 来自 OCP《FP8 Data Type Specification》，H100 的 Transformer Engine 与 MI300x 的 FP8 路径都实现了这两种格式；OCP Microscaling（MX）把「一块共享一个指数」写成 E8M0 的块尺度（块长 32），DeepSeek-V3 系列的权重/激活用 128×128 与 1×128 的 tile-wise FP8 缩放，KV cache 的块量化同理。面试问这条链路的点是：为什么尺度必须是 2 的幂（乘法不引入额外舍入）、absmax 定标会不会被一个离群点拖垮、以及 E5M2 与 E4M3 的取舍。

## 尺度的定义决定了一切边界

规定 \(e\) 是「满足 \(m\le57344\cdot2^e\) 的最小整数」，好处是：

- absmax 一定被完整保留（不会削半），且块内其它元素相对格点的位置被放大到最好的分辨率；
- \(\text{scale}\) 是 2 的幂，所以 `x / scale` 与 `q * scale` 都是**精确**操作，量化误差只来自那一次舍入。

最容易翻车的是把它写成 `e = ceil(log2(m / 57344))`：当 \(m/\text{MAX}\) 正好是 2 的幂时，`log2` 的浮点误差可能给出 `k + 2e-16`，`ceil` 于是得到 \(k+1\)，尺度大一倍，absmax 被舍成上一格点的下界。正确做法是用 `math.frexp`：\(m = f\cdot2^E\)（\(0.5\le f<1\)），若 \(f\) 恰好等于 0.5 则 \(e=E-1\)，否则 \(e=E\)；或者干脆像 oracle 那样从 \(-127\) 循环搜索。

## ties-to-even 要按位模式判，不是按值

E5M2 的格点按位模式 `E*4 + M` 连续编号（次正规占 `0..3`，正规从 `E=1` 起），所以「尾数域 \(M\) 为偶」等价于「位模式为偶」。oracle 枚举全部幅值并缓存编号，`bisect` 找到插入位置后比较左右两支：严格近的一侧胜，等距时取编号为偶的那侧。若改用「\(M\) 是偶数」去判，就得先把值反解回 \((E,M)\)，正规与次正规要分开处理，很容易写错。

## 次正规区在 block=1 时根本不可达

一个反直觉的事实：`block=1` 时尺度完全自适应（\(2^e\le|x|/28672\) 附近），归一化后的 \(t\) 总是落在 \([28672,57344]\) 区间，那里离 \(2^{-16}\) 的次正规网格十万八千里。要触发次正规，必须让块尺度由一个正常量级的 absmax 定住、同时块内出现极小的元素——例如 `x = [1.0, 1.5*2^-31]`、`block=2`：absmax=1 给出 \(e=-15\)、scale=\(2^{-15}\)，第二个元素除以尺度后是 \(1.5\cdot2^{-16}\)，恰好落在次正规格点 \(2^{-16}\) 与 \(2\cdot2^{-16}\) 正中，ties-to-even 取 \(M=2\) 得 \(2^{-30}\)。实现时把这条单独写成用例，比写一百行随机数据更能验证网格。

## 核心与易错点

- **`0.6` 的期望值**：`block=5` 时 0.6 的最近格点是 0.625（不是 0.5），因为它离 \(5\cdot2^{-13}\) 网格上的 0.625 更近。手算时要先把尺度算出来，不能凭「E5M2 精度很低」的印象猜。
- **inf 与 NaN 的整块语义**：absmax 是 inf 或块里有 NaN 时**整块**输出 NaN。写成「逐元素判断」会把 `[inf, 1.0]` 变成 `[inf, 1.0]`，与本仓库「非有限值污染整块」的口径冲突（`nu-kahan-compensated-sum` 用退化，这里用整块 NaN，因为量化本身没有"跳过"的余地）。
- **不要指望 torch 的饱和行为**：E5M2 溢出到 inf，而本题的尺度保证不溢出，所以输出里既没有 inf 也没有饱和值。`x.to(torch.float8_e5m2)` 与网格 snap 在正规/次正规区逐位一致，可以放心当第二 oracle，但它不会替你做尺度。
- **\(e\) 的夹取**：\([-127,127]\) 是给极端 absmax 的保险；夹过之后 absmax 可能超过 \(57344\cdot2^e\)，此时量化结果落在网格上限而不是 inf。
- **零的符号**：输出统一 +0.0，避免 `-0.0` 在逐位对拍里制造噪声。

## 与邻近题的区别

`fp8-quantize` 处理 E4M3（3 位尾数、最大 448、饱和规则显式）且通常是整体对称量化，本题是 E5M2 + 分块 2 的幂尺度；`quant-mx-microscaling` 的块尺度是 E8M0 且要显式编码进输出，`quant-blockfp-tile` 处理 tile 选择。本题的独有考点是「最小不溢出尺度」的精确判定与次正规网格的 ties。

## 对拍口径与复杂度

oracle 用「网格枚举 + bisect + 位模式奇偶」，尺度另用循环搜索，两条路径都与参考解（frexp 定标 + binade 步长 + `torch.round`）不同，并要求逐位相等。对拍覆盖 \(10^{-45}\)、\(10^{38}\)、随机正态、恰好的 \(57344\cdot2^k\) 边界与 `block` 取 1/3/7/32/200。时间 \(O(N)\)，每个块一次 absmax 归约。

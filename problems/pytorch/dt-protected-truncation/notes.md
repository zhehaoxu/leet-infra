# 解析：先分配配额，再保序选位置

## 参考方法

先验证选项与预算，检查特殊位置能否全部放入。按序列 ID 收集两侧普通位置，得到初始数量。只删指定侧时一次减去溢出量；`longest_first` 则按剩余数量逐次减一，相同选第二侧。

得到两侧最终配额后，才决定删哪里。头尾模式分别取前缀和后缀；删除中部时把奇数配额多出的一位给前缀。参考解使用 `indices[len(indices)-q:]` 处理后缀，使 q=0 得到空列表，而不是 Python 的 `indices[-0:]` 全列表。

全部特殊位置与两侧保留位置放入集合，排序后同时索引三个输入列表。由于选择基于位置而非 token 值，重复 ID 不会误受保护。

## 为什么正确

每次计数减少对应一次合法的普通 token 删除，且总删除数恰等于溢出量。特殊位置超预算或指定侧不足是仅有的容量失败情形；两侧均可删时，只要特殊位置能放入，就有足够的普通 token 可删。

每侧选取的前后片段不重叠，因为配额不超过该侧长度。三组位置分别属于特殊位置、序列 0 和序列 1，彼此不相交。按原下标排序同时保持序列内顺序、特殊位置的相对位置以及字段对齐。

## 独立 oracle

参考实现按规则逐次递减计数。测试不复用这条路径：枚举所有满足预算的两侧保留配额，选择差值绝对值最小的一对；若有同差值结果，优先第一侧配额较大。这相当于受各侧容量限制的均衡分配，并复现“相同删除第二侧”。指定侧策略则固定另一侧数量。

位置 oracle 也不拼相同切片：按距最近端点的距离排序位置，距离相同时前端优先，取足够数量，再恢复原顺序。最终输出连同输入不变性一起检查。

## 测试记录

`--selftest dt-protected-truncation --mode submit` 实跑 **15/15 ACCEPTED**。覆盖同长 tie、两种指定侧、零配额、原长内预算、ID 碰撞、交错归属、中部奇数配额、空输入、全特殊、单侧和极不均衡、全部小规模计数/预算组合、最大长度、固定种子随机、不可能预算和未知选项。

题面样例由参考解执行并与独立 oracle 对拍后记录，不依赖手算输出。

## 复杂度与范围

令 L 为原始长度。计数递减最多 L 次；参考解排序保留位置，时间 `O(L log L)`、额外空间 `O(L)`。可以用顺序扫描保留标记省去排序，但不影响契约。

这是工程教学的确定性截断规则，不是某个外部 tokenizer 的逐位复刻。特殊 token 已被显式标记；实际 tokenizer 通常先给正文分配扣除模板开销的预算，再插入模板。中部保留与交错归属是本题扩展。

已核验 [tokenizers 0.23.3 源码包](https://files.pythonhosted.org/packages/e0/7c/2cabb2174e772636683008f2c5621949b645da7d303c596589e84516a184/tokenizers-0.23.3.tar.gz) 的 `tokenizers/src/utils/truncation.rs` 第 70–158 行，并实跑原生接口：普通长度 (2,2)、正文预算 3 时，原生保留 (1,2)，本题保留 (2,1)。原生算法先按原始长度分短长侧，而本题明确每步比较剩余数量。原生还对恰好清空指定侧等情形有额外行为；本题按自己的容量规则，允许将指定侧清空。两者不能混称。

# cache-aware 粘性路由：前缀命中与队列深度联合代价

## 问题

多副本推理服务的前置路由要同时讨好两个目标：

- **命中前缀缓存**：同一个前缀只会在某个副本上被算过一次，送去别的副本就要重算整个 prefill。命中越长，省下的 TTFT 越多。
- **别把某个副本堆爆**：所有请求都追着同一个「缓存最全」的副本跑，它的队列会无限增长，尾延迟崩掉。

工业界（Mooncake、SGLang router、vLLM production-stack）的做法就是把它们写成一个**加权代价**：`α · 未命中块数 + β · 队列深度`，选代价最小的副本。本题就是这个代价函数的确定性版本，额外规定并列取小副本号，并把每次路由后的缓存与队列状态都推进下去。

## 任务

实现 `solve(cache, queries, queue, alpha, beta)`：

- 输入：
  - `cache` `(R, C)` int64，第 r 行是副本 r 已缓存的前缀块哈希（`-1` 只是补位）；
  - `queries` `(M, L)` int64，第 j 行是请求 j 的前缀块哈希序列（遇到 `-1` 即序列结束）；
  - `queue` `(R,)` int64 各副本当前排队深度；`alpha`、`beta` 为代价权重（均 `>= 0`）。
- 请求按行顺序逐个处理，对请求 j、副本 r：
  - `matched` = 请求前缀里**从头开始连续**命中副本 r 缓存的块数（一旦断开就停）；
  - `cost = alpha * (len_j - matched) + beta * queue[r]`。
- 选 `cost` 最小的副本，并列取副本号小的；随后 `queue[chosen] += 1`，并把该请求**全部**前缀块加进该副本的缓存。
- 输出：`chosen` `(M,)`、`hits` `(M,)`、`final_queue` `(R,)`、`total_cost` float32 标量（被选中副本的代价之和）。

## 示例

```
cache   = [[10, 11, 12], [10, 20, 21]]     副本 0 缓存 {10,11,12}，副本 1 缓存 {10,20,21}
queries = [[10, 11, 5],  [10, 20, 21]]
queue   = [0, 0],  alpha = 1.0,  beta = 1.0

q0 = [10,11,5]: r0 命中 2 块 -> cost = 1*(3-2) + 1*0 = 1
                r1 命中 1 块 -> cost = 1*(3-1) + 1*0 = 2   -> 选 r0，queue = [1,0]
q1 = [10,20,21]: r0 命中 1 块 -> cost = 2 + 1 = 3
                 r1 命中 3 块 -> cost = 0 + 0 = 0          -> 选 r1，queue = [1,1]

chosen      = [0, 1]
hits        = [2, 3]
final_queue = [1, 1]
total_cost  = 1.0
```

## 约束

- **命中必须是前缀连续的**：`[10, 99, 11]` 在缓存 `{10, 11}` 上只算命中 1 块，后面的 11 不算——分页前缀缓存只能复用从第一块开始的连续段。
- **未命中代价用块数而不是比例**：`len_j - matched` 直接对应要重算的块数；用比例会让长请求的权重被压扁。
- **路由之后要写回缓存**：被选中的副本立刻持有该请求的全部前缀块，所以下一个有相同前缀的请求会命中它——这正是「粘性」的来源。
- **队列只增不减**：本题不模拟请求完成；队列深度就是「已分配的请求数」，用来表达负载。
- **并列取小副本号**，保证结果与实现无关。
- **`alpha = 0` 退化为纯负载均衡**（按队列深度轮转），**`beta = 0` 退化为纯缓存命中**，两种极端都要能跑通。

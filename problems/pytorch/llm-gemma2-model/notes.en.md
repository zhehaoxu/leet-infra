# Deep Dive: Assembling the Full Gemma2 Model

## Where it comes from

- Gemma Team, *Gemma 2: Improving Open Language Models at a Practical Size*, Google DeepMind, 2024, arXiv **2408.00118**. Three model-level signatures: alternating local/global attention across even and odd layers, tanh soft-capping of both attention logits and final logits, and a distillation-based training recipe. This problem takes the first two plus the assembly rules.
- The executable spec is `transformers==5.20.2`, `transformers/models/gemma2/modeling_gemma2.py` and `configuration_gemma2.py`: `Gemma2Config` defaults `layer_types[i] = "sliding_attention" if (i+1) is odd else "full_attention"`, `tie_word_embeddings=True`, `attn_logit_softcapping=50.0`, `final_logit_softcapping=30.0`, `query_pre_attn_scalar=256`, `head_dim=256`; `Gemma2Model` scales the embedding by `hidden_size**0.5`, scales attention by `query_pre_attn_scalar**-0.5`, and applies the softcap before the mask.
- Division of labour inside the library: `llm-gemma2-layer` (order 525) is a **single layer** (cos/sin given, returns the layer output and attention weights) and involves neither embedding scaling, the layer-type sequence, the LM head nor the final softcap; `llm-qwen2-model` (order 113) is a whole Qwen2 model but takes `head_dim` from the caller, never shares `lm_head`, and has no softcaps or layer-type alternation, nor does it accept config derivation. What is unique here is the assembly chain **config-derived dimensions and layer types plus LM-head tying**.
- Division of labour with `llm-yarn-rope-scaling` (order 524): that problem only produces `inv_freq` / the scaling factor / the full cos-sin table; this one uses plain RoPE (`rope_theta`) and does no extrapolation.

## Core points and pitfalls

1. **Derive `head_dim`, but never fudge it**. The default here is `hidden // num_attention_heads`; in a real `Gemma2Config` `head_dim` is an explicit field (default 256, and for the 9B model `hidden/heads = 224 ≠ 256`), so both cases occur in practice. The derived value must match the number of rows in `q_weight`, otherwise raise — HF's `getattr(config, "head_dim", hidden // heads)` would silently pick a wrong dimension, which is not allowed here. `head_dim` must be even, or RoPE's `rotate_half` has nothing to pair with.
2. **A non-divisible KV head count must raise**. HF computes `num_attention_heads // num_key_value_heads` with integer division, so 3 heads with 2 groups silently collapses to 1 group; this problem rejects it.
3. **Alternation starts with sliding**. `layer_types[i] = sliding if (i+1) % 2 else full`, so layer 0 is already a sliding layer; starting with full makes every layer use the wrong mask.
4. **The sliding window includes the current token**. The condition is \(\text{kv} > \text{q} - \text{window}\), and a window of 1 means each position sees only itself; writing \(\ge\) admits one extra position, and the `window_off_by_one` mutation is caught by five checks at once.
5. **The softcap comes before the mask**. HF's eager path is `logits * scale` → `cap*tanh(logits/cap)` → `logits + mask` (with `finfo.min` at masked positions). Masking first and softcapping after turns the \(-\infty\) of masked positions into \(-cap\), which softmax converts into a non-zero weight — the whole layer is then wrong.
6. **The attention scale is not \(1/\sqrt{h_d}\)** but `query_pre_attn_scalar**-0.5`. Gemma2 decouples the scaling from the head dimension through this field; copying Llama's `head_dim**-0.5` yields different weights.
7. **The order inside the dual post-norm**: RMSNorm the **sublayer output** first, then add the residual (`x = residual + RMSNorm(sublayer(x))`), not the other way around. A pre-norm arrangement is wrong here.
8. **The norm gain is \(1+w\)**. Gemma2's norm weights are zero-centered so that `w=0` means identity; using \(w\) directly zeroes every gain.
9. **The embedding scale applies only at the entrance**: `X = embed[ids] * sqrt(hidden)`; nothing is multiplied after the final RMSNorm. Dropping it throws off the magnitude of every logit.
10. **LM-head tying**: when tied, `embed_weight` serves as the LM head (one matrix read twice) and a separate `lm_head_weight` is illegal; when untied, a missing head must raise. Tying is numerically identical to passing an independent matrix that happens to equal the embedding, but the contract requires exactly one of the two.
11. **The final softcap comes after the LM head**: compute logits from the hidden state first, then `cap*tanh(logits/cap)`. Squashing the hidden state before projecting is wrong.
12. **GeGLU uses the tanh approximation**: `gelu(gate, approximate="tanh") * up`, which is visibly different from the exact erf version.
13. **Precision convention**: compute in float64 and return float32; when comparing against HF (which runs entirely in float32) use a 2e-5 tolerance.

## How it is judged

- `_oracle` rewrites the whole model with a triple numpy loop over batch/head/position: hand-written RoPE rotation, per-position enumeration of the legal kv indices followed by a softmax, and a hand-written tanh GELU — no code shared with the torch implementation. The config derivation rules are rewritten independently as well.
- Ten `check_*` functions: the hand-computable example, equivalence of the default derivations (omitting every derivable key must be bitwise identical), LM-head tying, narrowing the window plus "window ≥ S degenerates to causal full attention", causal prefix stability (a longer sequence must not rewrite prefix logits), the two softcap levels, the GQA grouping map, randomized oracle configs (four configs, plus an independent head and a float32 input), comparison against the full HF model (three explicit configs, one all-defaults config, one untied config), and 53 invalid inputs.
- The HF comparison calls `Gemma2ForCausalLM` (eager) **without an attention mask**, letting HF build the masks with `create_causal_mask` / `create_sliding_window_causal_mask` — so the layer-type alternation and the window boundary are validated against HF's own masking utilities rather than a private copy.
- All 18 mutations are caught: dropping the embedding scale, skipping RoPE on k, interleaved GQA duplication, softcap after the mask, an off-by-one window, no causal mask, post-norm on the residual, softcap before the LM head, ignoring tying, ignoring `layer_types`, using \(w\) as the gain, exact GELU, no final norm, ignoring an explicit `head_dim`, no final softcap, no attention scaling, and no norm on the FF output.
- Invalid inputs only catch `ValueError`: a non-dict config / unknown key / missing `num_attention_heads`, mismatched `hidden_size` or `vocab_size`, a head count of 0/bool/float, an odd or zero `head_dim`, a non-dividing KV head count, a layer-count mismatch, wrong `layer_types` length/value/type, a window of 0/bool/float, `query_pre_attn_scalar` of 0/NaN/bool, softcaps of 0/negative/string/`inf`, a non-positive `rms_norm_eps` or `rope_theta`, a non-bool `tie`, a tying state inconsistent with the head, wrong weight shapes or dtypes, and input ids that are not tensors / are floating / 1-D / empty / out of range.

## Complexity

- Per layer: q/k/v projections \(O(B S h (H_q+2H_{kv}) d)\), attention \(O(B H_q S^2 d)\), o_proj \(O(B S h H_q d)\), and the three GeGLU matmuls \(O(2 B S h I)\).
- Total time \(O\!\left(L\cdot\left(B S h (H_q+2H_{kv})d + B H_q S^2 d + 2 B S h I\right)\right)\); the main extra memory is the attention weights, \(O(B H_q S^2)\) for full-attention layers and \(O(B H_q S\cdot\text{window})\) for sliding ones.

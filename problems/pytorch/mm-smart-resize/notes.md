# Smart Resize：对齐、一次性分支与槽位账

## 实现路径

先检查正整数、预算次序与长宽比。因子是 `patch_size * merge_size`，不是单独的 patch 边长；这保证 patch 网格两边都能被 merge 整除。

首次 `round` 后才选择缩小或放大分支，缩放系数始终使用原始面积。缩小对每条边施加 `max(factor, ...)`；放大则向上取整。最后从尺寸推导 patch 数和视觉槽位数，槽位数还要除以 merge 面积，而不是 merge 边长。

时间与额外空间复杂度均为 $O(1)$。没有像素张量、插值或真实模型执行。

## 为什么预算不是硬保证

极端窄长图像的短边不能继续缩小；将短边钳制到一个 factor 可能使面积再次超过上限。向下取整也可能使面积低于下限。代码不执行第二轮修正，所以 `in_budget` 必须根据最终面积计算，不能固定为真或强行裁剪输出。

`H=28,W=5600,p=14,m=2,L=U=3136` 得到 `(28,784)`，面积 21952，视觉槽位 28。这个例子同时验证长宽比 200 的等号边界。

## 浮点顺序也是契约

Python 的 ties-to-even 与普通“四舍五入”不同。平方根后的量化边界同样受二进制浮点影响：`H=442,W=884,p=5,m=2,L=1300,U=7200` 的上游输出为 `(50,110)`，而精确实数化简会得到 `(60,120)`。本题选择忠实复现指定上游浮点运算顺序，而不是定义一个优化面积的整数搜索算法。

因此不要把连续除法改写成另一个数学等价但浮点舍入不同的表达式，也不要对 `floor` 输入加 epsilon。

## 独立验证与来源

来源是本地已安装的 `transformers==5.20.2`，文件 `transformers/models/qwen2_vl/image_processing_qwen2_vl.py`，函数 `smart_resize`（第 63–89 行）。测试里的尺寸表由该函数实跑固化，覆盖向上/向下/不缩放、奇数格点、短边最小值及浮点边界，而不是在测试中复制参考实现公式。

其余测试用转置对称性、已对齐恒等、ties-to-even 的奇偶规律、同 factor 不同 patch/merge 分解，以及面积/patch/槽位乘积守恒进行校验。题目不依赖 transformers 运行，也不声称与独立 `qwen-vl-utils` 的不同版本一致。

## 1. 切分的是计算，不只是存储

权重采用 PyTorch 的 `[out_features, in_features]` 布局。因此，虽然名为 column parallel，切分的却是权重的**行**（axis 0）：每个 rank 持有一段输出特征。各局部矩阵乘法产生 `[B, O/P]`，沿特征轴拼接，恢复全局特征顺序下的 `[B, O]`。

Row parallel 则切分权重的**列**以及对应的输入特征。把矩阵乘法的收缩下标分段可得：

\[
xW^{\mathsf T}=\sum_{r=0}^{P-1}x^{(r)}(W^{(r)})^{\mathsf T}.
\]

每个局部乘积已经是 `[B, O]`。拼接、取平均或只保留某个 rank 都不对，参考解使用 SUM 累加。先拼回权重再调用一次稠密矩阵乘法，也没有实现本题要求的分片计算。

## 2. 词表归属与稳定交叉熵

分片宽度为 `V // P`，用整数除法确定目标标签所属 rank，用余数确定其局部下标。归属映射必须覆盖**全部**词表 ID，而不只是当前 batch 的标签。行置换后，ID 以新行序为准；同步置换权重行并重映射标签，损失应保持不变。

先计算各 rank 的局部 logits。对每个样本跨 rank 归约局部最大值，得到共同的平移量。先减去该值再取指数，分片内求和后，再对这些 batch 向量跨 rank 做 SUM。各分片独立 softmax 的分母是错误的，归一化必须覆盖整个词表。

对于分子，每个 rank 在安全的局部下标处 gather，随后把不属于该 rank 的样本贡献置零，再做 SUM。截断下标只是为了避免非拥有者越界访问，不能把它当成新的标签；必须先掩码再归约。

使用 `log(global_exp_sum) - shifted_target_logit`。它在数学上等价于 log-sum-exp 减目标 logit，但避免把巨大的共同偏移加回来后，因相减而丢失较小的对数项。即使所有 logits 都是 `1e16`，损失仍应为 `log(V)`。约为正负 `10000` 的 logits 也必须先平移，避免指数溢出或下溢。不要通过分片视图原地修改 logits 或输入。

## 3. 开销与通信含义

设 batch 为 `B`，输入宽度为 `I`，输出宽度为 `O`，rank 数为 `P`，vocab 模式下 `O=V`。

- 所有模拟 rank 的矩阵乘法总算术量为 `O(B*O*I)`；均匀切分后，每个 rank 约承担其 `1/P`。
- Column 拼接 `B*O` 个输出值。Row 对 `P` 个 `[B, O]` 局部结果求和，额外归约量为 `O(P*B*O)`。
- Vocab 另需 `O(B*V)` 逐元素运算和 batch 向量的跨 rank 归约。概念上需要一次 MAX、两次 SUM；CE 本身不需要收集整个词表的 logits，本题只是为了检查才要求返回拼接结果。
- 不计输入与视图元数据，column/row 的张量工作空间为 `O(B*O)`。单进程 vocab 参考解同时保留局部与拼接后的 logits，并堆叠局部最大值，张量空间为 `O(B*V + B*P)`，另有 `O(V)` 的标签归属字典。权重分片使用视图；也允许复制，但会增加权重存储。

这些是模拟的运算量与存储量，不是网络时延或集合通信带宽估算。

## 4. 范围与验证

本题只覆盖 CPU 前向的切分、拼接、归约等价性，以及逐样本词表交叉熵。不涉及进程组、NCCL、偏置、embedding 查表、不均匀词表补齐、反向通信或生产级显存优化。不支持的模式及不可整除的切分维度明确要求抛出 `ValueError`；其他输入由契约保证合法。

测试直接使用 `x @ W.T` 和稠密 PyTorch CE 作为独立数值参考，覆盖非方阵、单 rank、单类别、分片边界标签、重映射标签、float64 极端偏移、float32/非连续输入、分片的精确内容与 dtype，以及输入不变性。稠密 CE 适合作为测试判据，不是提交实现中词表并行计算的替代品。

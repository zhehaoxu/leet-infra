# 解题思路

## 面试官意图

集合通信原语是分布式训练的「字母表」。面试官问「All-Gather 和 All-Reduce 有什么区别」「张量并行里
哪一步是 all-gather」，答不上来就说明只会调 API、不懂数据怎么在卡间流动。本题把最基础的一个原语
拆成纯函数让你实现，后续 `reduce-scatter` / `all-reduce` 拼起整套。

## 语义

$W$ 个 rank 各持一份等长分片，All-Gather 把**所有分片按 rank 顺序拼接**，且**每个 rank 都得到同一份
完整结果**。用纯函数建模即：输入 `shards`（长度 $W$ 的列表），输出也是长度 $W$ 的列表，每项都是
`torch.cat(shards, dim=0)`。

## 与其他原语的对比（贯穿本合集）

| 原语 | 输入（每 rank） | 输出（每 rank） | 结果是否各 rank 相同 |
|------|----------------|----------------|----------------------|
| All-Gather | 一片 $S/W$ | 完整 $S$（拼接） | 相同 |
| Reduce-Scatter | 完整 $S$ | 归约后的**一片** | 不同（各拿一段） |
| All-Reduce | 完整 $S$ | 归约后的**完整 $S$** | 相同 |

All-Gather **不做归约**（不加不求和），只是把数据搬到一起——所以它的输出体积是输入的 $W$ 倍。

## 真实场景

- **张量并行（Megatron）**：列并行 Linear 的输出是「每卡一个列块」，用一个 All-Gather 拼成完整激活。
- **推理 TP**：各卡算出的部分 logits 经 All-Gather 汇成整条。

## 常见错误

- 拼接顺序不按 rank（用 set / 乱序），导致 `full` 顺序错。
- 误做了求和（那是 All-Reduce）。
- 返回单个张量而非「每 rank 一份」的列表——本题契约要求返回长度 $W$ 的列表。

## 判题口径

`test_cases.py` 用 `torch.cat(shards,0)` 作参考，校验：每 rank 结果相同且按 rank 顺序、单 rank 退化、
二维分片沿 dim0 拼接、以及**不修改输入**。

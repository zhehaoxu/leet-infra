# 分布式：DDP 静态梯度分桶与就绪时间

## 题目描述

DDP 将多个参数的梯度分桶，以摊薄集合通信开销。本题是**教学用的静态容量分桶模型**，并非复刻 PyTorch 的分桶器或通信调度器。

参数注册顺序不能决定梯度实际完成的顺序。这里明确选择参数下标逆序作为**装桶顺序**，仅此而已；梯度何时可用由输入的各 rank 就绪时间决定。完整输入输出契约见 starter。

## 静态装桶

从最后一个参数下标向前遍历。只要累计大小不超过容量就继续加入，恰好等于容量也允许。加入下一个梯度会超限时，先封当前桶，再开新桶。单个梯度超过容量时，先封此前的非空桶，再让该梯度独占一桶。不拆分梯度，也不按就绪时间重排参数。

虽然参数名为 `bucket_cap_mb`，其单位实际是 **MiB**，字节容量为 `int(bucket_cap_mb * 1024**2)`。梯度大小为正整数字节数，换算后的容量为正。允许参数列表为空。

## 就绪时间与共同桶序

记 \(B_k\) 为第 \(k\) 个桶，\(t_{r,i}\) 为输入给出的 rank \(r\) 上参数 \(i\) 的梯度就绪时间：

\[
R_{r,k}=\max_{i\in B_k}t_{r,i},\qquad
G_k=\max_r R_{r,k},\qquad
E_k=\max_{0\le j\le k}G_j.
\]

- \(R\)：某 rank 上，桶内所有梯度都就绪后，该桶才就绪。
- \(G\)：所有 rank 都已就绪，需要等待最慢的 rank。
- \(E\)：满足共同桶序的**全局同步可入队时间**。后面的桶即使提前就绪，也不能越过前面的桶。多个桶可以具有相同的可入队时间。

这些值不是实际的本地入队时刻，也不是网络通信完成时刻。题目没有给出或推断任何通信耗时。没有参数时，每个 rank 对应一个空的就绪时间行，其余结果列表也为空。

## 没有根节点或起始归属 rank

每个 rank 都参与每个桶的 all-reduce，并得到归约结果。All-reduce 不指定根节点或起始归属 rank：即使采用环算法，也是所有 rank 参与，不能把第 \(k\) 个桶分配给 rank \(k\bmod W\)。

真实 DDP 可能重建桶，按 dtype/device 分组，并在反向计算继续进行时异步同步。桶的字节容量满足要求，并不意味着梯度已经就绪。本题不模拟这些运行时机制。

## 示例：参考解实测输出

以下数值由示例测试实际打印。五个梯度依次为 3、2、4、1、2 MiB，输入中以字节表示。

```text
param_sizes = [3145728, 2097152, 4194304, 1048576, 2097152]
bucket_cap_mb = 5.0, world_size = 2
ready_times = [[1.0, 2.0, 4.0, 3.0, 8.0], [2.0, 3.0, 6.0, 1.0, 5.0]]

{
  'buckets': [[4, 3], [2], [1, 0]],
  'bucket_ready_times': [[8.0, 4.0, 2.0], [5.0, 6.0, 3.0]],
  'global_ready_times': [8.0, 6.0, 3.0],
  'enqueue_times': [8.0, 8.0, 8.0]
}
```

桶 1 要等 rank 1 到时间 6 才全局就绪，但仍不能越过桶 0，因为桶 0 的 rank 0 到时间 8 才就绪。桶 2 虽然更早就绪，也会被同一顺序约束阻塞。

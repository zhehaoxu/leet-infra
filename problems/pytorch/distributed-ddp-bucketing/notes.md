## 1. 把桶归属与可用时间分开

先只根据参数下标逆序和给定的字节容量规则确定桶成员。这是教学模型的约定，不代表 autograd 总按参数注册顺序的逆序完成梯度。分支、共享参数和执行图都可能导致不同的就绪模式，本题以输入时间为准。

维护当前桶及其累计字节数。如果下一个梯度会让非空桶超限，先封桶；恰好等于容量则可以加入。单个梯度超限时，立即独占并封成一个桶，不能和前面的半满桶或后面的梯度共桶。不要产生空桶，也不要按大小或时间重排成员。

`bucket_cap_mb` 使用 MiB：乘以 `1024**2` 后，将正值截断为整数。四舍五入或使用十进制 MB 都会改变分桶边界。参数不可拆分。契约保证大小为正整数、换算后的容量及 rank 数为正、就绪时间有限且非负；不额外承诺非法输入的处理行为。

## 2. 区分三层时间汇总

对于某 rank 上的桶，取桶内所有参数就绪时间的最大值。即使成员顺序固定，也不能只取最先或最后访问的成员时间。

对于全局就绪时间，取该桶在**全部** rank 上就绪时间的最大值。不同桶最慢的 rank 可能不同，不存在代表 rank 或某个桶专属的 rank。若有 `K` 个桶、`W` 个 rank，局部就绪矩阵应为 `[W, K]`，不是 `[K, W]`。

最后从左到右扫描全局就绪时间，保留迄今最大值。这个前缀最大值表示遵守共同桶序的最早全局同步可入队时间。例如 `[1, 9, 5, 3]` 应变为 `[1, 9, 9, 9]`：桶 2 和桶 3 不能越过桶 1。这里既不是前缀和，也不是排序。可入队时间相等不意味着网络通信耗时为零，只是本题没有建模耗时。

参数为空时，不应对空集合求最大值。返回空桶列表、空全局/可入队时间列表，并为每个 rank 保留一个空的局部就绪行。

## 3. 为什么没有起始归属 rank

All-reduce 合并所有 rank 的贡献，并让所有 rank 得到归约结果；它不像有根 reduce 或 broadcast 那样指定根节点。环状 all-reduce 在 rank 之间分配数据块的工作，不会让桶 `k` 归属于 rank `k % world_size`。

因此，两张卡上的五个桶仍然要求两张卡参与全部五次归约。改变 rank 数或就绪时间可以改变可入队时间，但不能改变本题仅由大小决定的桶成员。

## 4. 诚实界定运行时范围

模型中的 `enqueue_times` 是全局同步可入队时间，并非真实 reducer 每个进程的精确调用时刻。一个进程可能在其他进程尚未就绪时就异步提交集合通信。匹配的集合通信顺序仍然重要，但真实实现不必执行本教学汇总所暗示的全局屏障。

真实 DDP 可能根据观测行为重建桶，按 dtype/device 分组，并让异步同步与反向计算重叠。容量描述的是成员划分，不是“字节装满就代表梯度就绪”的触发条件。本题不包含 dtype/device 分桶、通信耗时、网络拓扑、带宽模型或通信计算重叠的模拟。

## 5. 复杂度与独立验证

设参数数为 `N`、桶数为 `K <= N`。装桶耗时 `O(N)`；局部就绪时间需要检查每个 rank 的全部参数，耗时 `O(W*N)`；全局最大值为 `O(W*K)`；前缀扫描为 `O(K)`。总时间为 `O(W*N + W)`，其中包含 `N=0` 时构造 `W` 个空行的开销。返回结果占用 `O(N + W*K + W)` 空间；除结果列表外，参考解只需常数个标量记录状态。

测试判据刻意不复制流式装桶器：通过累计字节数枚举连续前缀的终点，选择最长合法前缀。预期可入队时间直接从当前及之前所有桶的底层梯度时间求最大值，而不是照抄前缀最大递推。测试覆盖非逆序就绪、较慢 rank、被阻塞的后续桶、恰好满容量、中间的超大梯度、MiB 小数与向下取整、零时间、空输入、单 rank，以及两 rank 上五个桶。

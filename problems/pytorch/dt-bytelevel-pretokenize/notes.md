# 解题思路与核验记录

## 1. 保留正则的顺序，而不是简单按字符类别切段

维护原文游标，每轮先尝试七种小写缩写。若未命中，再考虑可选的一个 ASCII 空格，检查其后的字符属于字母、数字还是“其他非空白”，并贪心取同类连续串。

`unicodedata.category` 的首字母足以识别 `L` 和 `N`。不要用 `isalpha` / `isdigit` 的组合替换契约，也不要做 NFC：预组合的 `é` 和 `e` 加组合重音有不同切分。emoji、组合标记、连接符及部分控制字符可以连续属于“其他”分支。

缩写优先仅作用于当前匹配起点。例如原文 `!!'s 's` 的执行结果是：

```python
[("!!'", 0, 3), ('s', 3, 4), ("Ġ'", 4, 6), ('s', 6, 7)]
```

不能先在全文找出所有缩写再切剩余部分。

## 2. 手写空白 lookahead

只有前三类分支都不适用时才进入空白逻辑。用题目给定的 25 字符集合，而不是 `isspace()`：Python 将 `U+001C–U+001F` 视为空白，但本题正则不是。

对于当前连续空白串：

- 到达原文末尾时整段取走；末尾的负向前瞻成功。
- 位于内部且长度大于 1 时，贪心匹配退回一个字符，下一位置仍为空白，因而负向前瞻成功。
- 内部只有一个空白时，倒数第二支无法匹配，最后一支取走该字符。

被留下的最后一个字符可能由下一轮的字母分支吸收，也可能单独输出。例如实际执行：

```python
text = 'a  b\t\t!'
output = [('a', 0, 1), ('Ġ', 1, 2), ('Ġb', 2, 4), ('ĉ', 4, 5), ('ĉ', 5, 6), ('!', 6, 7)]
```

## 3. 先记录原文偏移，再编码

建立固定的 256 项表，保留指定的三段字节范围，其余字节从 `U+0100` 起顺序映射。对每个已经确定的原文切片执行 UTF-8 编码并查表。输出下标直接来自原文游标，不能由编码字符串的长度累加。

设原文长度为 $n$，扫描和编码总时间为 $O(n)$，含输出的空间为 $O(n)$；字节表大小恒定。一个合法标量最多产生 4 个 UTF-8 字节。

## 4. 实际来源与 fixture 生成

实际读取了 [tokenizers 0.23.3 的 PyPI 源码包](https://files.pythonhosted.org/packages/e0/7c/2cabb2174e772636683008f2c5621949b645da7d303c596589e84516a184/tokenizers-0.23.3.tar.gz)，通过 `urllib.request`、`io.BytesIO`、`tarfile` 在内存中检查，没有保存或解压包文件：

- `tokenizers/src/pre_tokenizers/byte_level.rs:13–39`：字节映射。
- 同文件 `41–45`：原 GPT-2 正则，大小写敏感。
- 同文件 `119–145`：先切分，再做 UTF-8 字节映射；前缀空格受开关控制。

一次性核验使用本地 `.venv-eval`：Python **3.12.12**、`unicodedata` **15.0.0**、`regex` **2026.9.29**、`tokenizers` **0.23.3**。

测试中的 **58 条冻结 fixture** 均实际执行了两条独立路径并断言结果一致：

1. `regex.finditer` 运行题目原式，取其码点 `start/end`，将匹配片段 UTF-8 编码并按来源表映射。
2. `ByteLevel(add_prefix_space=False, use_regex=True).pre_tokenize_str`，将其结果整理成三元组。

其中 34 条是定向样本，24 条是 `random.Random(4572026)` 的固定随机串；每串长度由 `randrange(1, 33)` 产生，字符池与生成顺序记录在 `test_cases.py` 头部。冻结后又将全部 58 条与两条实际路径及参考解逐项核对。交付代码和测试不导入上述第三方包，也没有复制参考扫描器当 oracle。

本题依据上述 `ByteLevel` 原式，而不是邻近 `TikTokenConverter` 的默认正则；不能将二者混为一谈。跨 Unicode 版本的新分类不在本题承诺范围内。

## 5. 完整映射与可达字节的区别

测试冻结完整 256 项映射及其逆表，检查双射、每片段逆解、连续偏移及全文恢复。用 240 个 Unicode 15.0 已定义标量覆盖本题输入可产生的全部 **241 种字节值**，另逐字符验证实际输出映射。

不能声称合法文本能覆盖全部 256 个 UTF-8 字节值：

- `C0`、`C1`、`F5–FF` 共 13 个字节不可能出现在合法标量的 UTF-8 中。
- `F1`、`F2` 对应的码点范围在 Unicode 15.0 中未分配；在本题“已定义字符”的限制下也不可达。

因此，完整 256 项表的静态双射校验不等于求解器输出覆盖了全部 256 项。这是对覆盖要求中不可实现部分的明确说明，不是改用非法 UTF-8 进行测试。

# Solution Notes and Verification

## 1. Preserve branch order, not merely character classes

Maintain a source cursor. First try the seven lowercase contractions. Otherwise, consider at most one optional ASCII space, classify the following character as a letter, number, or other non-whitespace character, and greedily consume that class.

The first letter of `unicodedata.category` identifies `L` and `N`. Do not substitute a combination of `isalpha` / `isdigit`, and do not apply NFC: precomposed `é` and `e` followed by a combining accent split differently. Emoji, combining marks, joiners, and some controls can form one “other” run.

Contraction priority applies only at the current match start. Executing the source text `!!'s 's` produces:

```python
[("!!'", 0, 3), ('s', 3, 4), ("Ġ'", 4, 6), ('s', 6, 7)]
```

Finding all contractions globally before splitting the rest would be incorrect.

## 2. Implement the whitespace lookahead

Enter whitespace handling only when the preceding three run branches do not apply. Use the exact 25-character set from the statement, not `isspace()`: Python considers `U+001C–U+001F` whitespace, but this regex does not.

For the current whitespace run:

- At end of input, take the whole run; the final negative lookahead succeeds.
- Internally, if the run has more than one character, backtrack by one. The next character is still whitespace, satisfying the negative lookahead.
- For one internal whitespace, the penultimate branch fails and the final branch consumes that character.

The last character left behind may prefix a subsequent letter run or become a separate piece. Actual execution:

```python
text = 'a  b\t\t!'
output = [('a', 0, 1), ('Ġ', 1, 2), ('Ġb', 2, 4), ('ĉ', 4, 5), ('ĉ', 5, 6), ('!', 6, 7)]
```

## 3. Record source offsets before encoding

Build the fixed 256-entry table, preserving the three specified byte ranges and assigning the remaining bytes consecutive characters from `U+0100`. UTF-8 encode each already-determined source slice and look up its bytes. Output offsets come directly from the source cursor, never from accumulated encoded lengths.

For source length $n$, scanning and encoding take $O(n)$ time and $O(n)$ space including output. The byte table is constant-sized. A valid scalar produces at most 4 UTF-8 bytes.

## 5. Full mapping versus reachable bytes

The tests freeze all 256 mapping entries and their inverse, check bijectivity, decode every output piece, verify contiguous offsets, and recover the full source. A 240-character corpus of Unicode 15.0 defined scalars covers all **241 byte values** reachable under this input contract. Each character also independently exercises the actual output mapping.

It is impossible to claim coverage of all 256 byte values through valid UTF-8 text:

- `C0`, `C1`, and `F5–FF`, totaling 13 byte values, never occur in UTF-8 encodings of valid scalars.
- The code-point ranges requiring `F1` and `F2` are unassigned in Unicode 15.0, so those bytes are also unreachable under the defined-character restriction.

Thus, checking the complete table's static bijection is not the same as covering all 256 entries in solver output. This explicitly records the impossible part of the requested coverage rather than testing invalid UTF-8.

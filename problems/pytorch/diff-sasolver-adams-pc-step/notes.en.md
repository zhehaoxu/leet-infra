## Normalization (judge domain vs upstream)

- **Explicit noise**: the official `randn_tensor(generator)` draws every step; replaced by an explicit `noise` input, required on every call (with tau = 0 the noise term is 0 but `last_noise` is still stashed — matching the official state machine, since the next call's corrector consumes it).
- **Split tau**: the official `tau_func(timestep)` is evaluated at the **pre-shift** `timestep_list[-1]` (= previous timestep) for the corrector and at the **post-shift** one (= current timestep) for the predictor. The judge domain has no embedded clock, so it becomes two explicit inputs: `tau_corrector` (previous step's value) and `tau` (current step's value), both validated as finite and non-negative.
- **Externalized state**: the official `self.model_outputs / self.last_sample / self.last_noise / self.lower_order_nums / self.this_corrector_order`; all packed into the `state` dict. `step_index` is auto-incremented upstream; explicit input here.
- **Explicit orders / lower_order_final**: config constants upstream; inputs here, with the warmup formulas kept verbatim.
- **No inlined table construction**: unlike 754/755 there is no auxiliary sigma table — `sigmas` is passed through as-is (the upstream `set_timesteps` output is all-positive), and lambda is computed pointwise on the fly.
- Official verbatim formulas are kept: the two-log lambda path (not swapped for −log sigma), the unmerged `exp`/`sqrt` forms, and the **two different** order-2 corrections for predictor and corrector.

## Key mechanics

1. **Triple time shift**: everything the corrector consumes comes from the **previous call** — `this_corrector_order` (computed by the previous warmup and stashed), `last_sample` (the sample after the previous corrector but before its predictor), and `last_noise` (the noise injected by the previous predictor). The predictor uses only **this call's** values (order tp, sample corrected, noise noise). A mutation hotspot.
2. **The two sides' histories differ by one slot**: the corrector's model-output list = pre-shift history + [x0] (x0 is "just obtained, not yet filed"), while the predictor's = post-shift history (x0 already at the tail). The **−1** in M = max(predictor_order, corrector_order − 1) exists precisely to make room for the corrector's x0.
3. **The lambda identity**: under the VE convention, lambda = log alpha − log(sigma·alpha) ≡ −log sigma and e^lambda ≡ 1/sigma. Two direct dividends: (a) the order-1 coefficient (tau = 0) has the closed form coefs[0] = e^{lambda_t} − e^{lambda_s0} = 1/sigma_target − 1/sigma_source; (b) the doc example can be fully rationalized (sigma chosen as Pythagorean values 4/3 and 3/4 so that sqrt(sigma²+1) is rational). The official two-log path is mathematically redundant but kept verbatim as the judging criterion.
4. **The two order-2 corrections are not the same formula**: the predictor's (L1024-1045) delta has denominator `(lambda_s0 − lambda(sigmas[step_index−1]))` (an adjacent lambda gap) and numerator `h²/2 − …/(1+tau²)²` (no h); the corrector's (L1164-1181) numerator is `h/2 − …/((1+tau²)²·h)` (with h). Copy-paste confusion is easy — one mutation for each.
5. **The two warmup caps**: `tp ≤ lower_order_nums + 1` and `tc ≤ lower_order_nums + 2` (the corrector gets +1 because it consumes "the order computed last call" and thus takes effect one call later). Together with M this guarantees the None head is never read: tp−1 ≤ min(i, M) and tc−1 ≤ min(i, M) (tc ≤ corr ≤ M+1 is guaranteed by M's definition). The `N − step_index` in `lower_order_final` makes **the final step's predictor always drop to order 1**.
6. **Mid-chain cold starts are legal**: `state=None` with `step_index>0` mirrors the official image-to-image path (`last_sample is None` → `use_corrector=False`): no corrector, and warmup climbs from order 1 again.
7. **The official table is all-positive**: no upstream schedule ends in 0 (the non-karras tail appends the small positive sigma(t=0); karras/exponential/flow duplicate the last positive value) — so the "strictly positive" validation is grounded and lambda never hits −inf.

## Alignment blind spot: the oracle eats solve's state

The multi-step loop comparison passes the `state` returned by solve verbatim to both solve and the oracle — so **a wrong state still compares green**: `m-state-last-sample` (stashing the raw input sample instead of `corrected` as `last_sample`) SURVIVED the first round, 19/19. The corrector computes a wrong `corrected` from the wrong `last_sample`, but the oracle computes the same wrong value from the same wrong state. Fix: add **independent state-content assertions** in the loop (not routed through the oracle) — `state.last_sample == this call's corrected_sample` (or == this call's input sample when no corrector ran), `state.last_noise == this call's input noise`, `state.model_outputs[-1] == this call's pred_original_sample` — after which 4 loop cases catch it together. The lesson ranks with 754's "confirm the selftest is green before mutating": **comparison tests must distinguish tested values from passed-through values; passed-through values need their own oracle-independent assertions**.

## Dedup

- **`diff-unipc-pc-step`**: also a predictor-corrector pair. But UniPC's coefficients come from **solving a linear system** (rhos = solve(R, b), Vandermonde-type), while this problem's coefficients are **Lagrange polynomials × closed-form exponential integrals** (hand-written formulas for degrees 0-3); UniPC has no warmup state machine (orders are call-time constants), no noise injection / tau, and no "previous call's order" triple shift. The two sides' history asymmetry also differs mechanistically (UniPC: lambda indices off by one slot; here: the shift timing off by one beat).
- **`diff-deis-multistep-coef` / `diff-dpm-solver-order-schedule`**: single-side predictor families, no corrector, no noise.
- **`diff-heun-predictor-corrector`**: a single-step derivative-averaging PC, no multi-order history, no lambda-node interpolation.
- **754/755 KDPM2**: a two-call interleaved-sigma-table state machine, single-order derivatives, no multistep history.
- **`diff-euler-ancestral-step` (522)**: single-call Euler ancestral; the noise split is in the same domain but there is no corrector / multi-order machinery.

## Pitfalls

- **The two identities of `this_corrector_order`**: the one in the returned dict is the **new value computed by this call's warmup** (stashed for the next call), while the corrector coefficient list's length is the **old value stashed by the previous call** — the comparison assertions must count by "the order actually used this call"; writing `range(this_corrector_order)` first caused an IndexError under 3rd-order configs.
- **Final-step order drop vs hand-calc intuition**: on a length-3 table one hand-computes tp = 2 at step 1, but `lower_order_final` makes tp = min(2, N−1) = 1 — the example numbers were wrong once until re-reading upstream L1329-1330.
- **The oracle must receive solve's state** (torch tensors), not the oracle's own numpy state (same discipline as 755); `_close` must handle (1,2) shapes (the early `float()` form blew up on multi-element tensors).
- **`steps = 1` is not in the judge domain**: a length-2 sigmas table is rejected by the "N ≥ 2" validation — random-evidence scripts must start their step count at 2.
- **The h = 0 boundary**: with a karras-style duplicated tail, the final predictor step has h = 0 → coefficients and noise term all 0 and prev ≡ corrected (a mathematical identity, pinned by a test); but `lower_order_final=False` plus a mid-table adjacent-equal pair would make the order-2 correction divide by h = 0 (Python float division raises ZeroDivisionError; the official torch yields nan) — a criterion boundary outside the judge domain (upstream schedules only duplicate the tail).

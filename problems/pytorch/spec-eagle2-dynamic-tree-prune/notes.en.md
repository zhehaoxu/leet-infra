# In Depth: EAGLE-2 Dynamic Draft Tree Re-ranking and Pruning

## Origin
Li et al., *EAGLE-2: Finding Optimal Substructures for Context-dependent Distributions in Fast Speculative Decoding* (arXiv:2406.16858, reference implementation [SafeAILab/EAGLE](https://github.com/SafeAILab/EAGLE)). Its Algorithm 1 has two steps: first run the draft network over the static tree once and read off each candidate token's top-probability as a **conditional acceptance rate**; then expand candidates level by level from shallow to deep, re-rank them by the cumulative product along the root path $V(v)=\prod_j c_j$, keep only (remaining budget) nodes per level, prune everything else together with its subtree, and finally flatten the survivors into one tree-attention verification call of the target model. The paper's Lemma 1 is the accounting used here: the expected number of tokens emitted per iteration equals $1+\sum_{v\in\mathcal S}\prod_j c_j$ — "the token the target always produces plus the per-node cumulative acceptance rates"; this problem's `E` is exactly that expression.

## Intuition: why a static tree needs re-ranking
A static tree grows according to the draft network's **beam shape**: every node independently takes its own top-$k$, so branches whose parent is itself very unlikely to be accepted still occupy verification slots. The target's verification budget (how many tokens one tree-attention forward can process in parallel) is a hard constraint, so the slots should go to the nodes with the largest $V$. EAGLE-2's observation is that **the second forward of the same draft network already yields those top-probabilities** at essentially no cost, which is why "draft first, re-rank by cumulative confidence afterwards" is a free lunch — and the main source of its gain over EAGLE-1's fixed-width trees.

## Formula and monotonicity
$V(\text{root})=1$ and $V(v)=V(\text{parent}(v))\cdot acc[v]$, so along any root-to-leaf path $V$ is **non-increasing** (because $acc\le1$). That monotonicity is useful twice: (1) pruning is "cut the whole subtree" — if $v$ is not kept, none of its descendants can be worth more; (2) if instead one takes a *global* top-$m$ by $V$ over the whole tree, the resulting set is automatically ancestor-closed (a parent never has a smaller $V$ than its child), so no repair step is needed. This problem, however, pins the paper's original **level-wise greedy**: the candidates at level $d$ are all children of the nodes kept at level $d-1$, sorted by $(-V,\text{index})$, and the first $\min(\text{remaining budget},\ \text{candidates})$ are kept.

## Key pitfalls
1. **Level-wise greedy is not global top-k.** When a level offers fewer candidates than the remaining budget, the greedy keeps the whole level and passes the leftover deeper, so a mediocre node of a shallow level can out-vote the best node of a deeper level. Example: level 1 = $\{V{=}0.9,\;V{=}0.5\}$, level 2 = $\{0.63,0.54\}$, budget 3 — the greedy takes $\{0.9,0.5,0.63\}$ (sum 2.03) while a global top-3 takes $\{0.9,0.63,0.54\}$ (sum 2.07). The statement prescribes the greedy, and `check_sparse_level_greedy_not_global_topk` nails that down.
2. **If the parent was not kept, the child cannot be taken however high its score** — candidates must only be expanded from the previously kept set, otherwise the selection is not ancestor-closed and no tree-attention mask can be built from it.
3. **Tie-breaking**: equal $V$ (e.g. all $acc=1$, when every node has $V\equiv1$) must be resolved by the smaller node index, otherwise the answer is not unique; the implementations use the ascending key $(-V, v)$.
4. **Do not drop the $+1$ in $E$**: the target forward fixes one token whether or not a draft was accepted (Lemma 1's mandatory first token); forgetting it makes the degenerate input $k=0$ report the absurd $E=0$.
5. The expression has the same shape as 177's $F(\mathcal T)=\sum_v f(v)$ but plays the **opposite role**: there it is the objective of a shape-search DP, here the shape is given, only the retained set is decided, and $E$ is a reported quantity rather than an optimized one.

## Division of labour inside the collection
`spec-medusa-tree-verify` (175) performs the typical-acceptance **decision** on given candidate paths; `spec-sequoia-sample-verify` (176) does the per-position multi-branch **residual shrink**; `spec-sequoia-optimal-tree` (177) and `spec-sequoia-depth-bounded-dp` (283) are **offline shape DP**; `spec-specinfer-token-tree-verify` (285) is **online level-wise acceptance with fallback**. This problem occupies the slot between offline and online — tree re-ranking: no coins are tossed, no distribution is modified, no acceptance is decided; it only answers "who gets a verification slot".

## Verification approach
The reference solution expands with an explicit "nodes kept at the current level" frontier, derives $V$ in a single topological pass (`V[v]=V[parent[v]]*acc[v]`) and slices a `sort`ed candidate list. The judge's `_oracle` takes three different roads: (1) $V$ and the level of each node are obtained by **walking up the parent chain node by node** and then multiplying `acc` top-down (no DP reuse); (2) all nodes are **bucketed by level** and the buckets are scanned shallow-to-deep, filtering candidates by "is the parent already selected" (no frontier is maintained); (3) the top-$n$ step uses `heapq.nlargest` instead of a sorted slice, and the expectation is summed with `math.fsum` in a different order. Closed forms and invariants provide further cross-checks: a chain degenerates to prefix products of `acc`, all-$acc{=}1$ gives $E=1+|sel|$, $k=0$/$gmax=0$ gives an empty set with $E=1$, and every randomized case additionally asserts ancestor closure, $|sel|\le\min(k,M-1)$ and level $\le gmax$. Index tensors are compared with `torch.equal`, the expectation with `allclose(atol=1e-5, rtol=1e-5)`.

## Complexity
$O(M\log M)$ (the total work of the per-level sorts is bounded by $M$) and $O(M)$ space; milliseconds for $M\le200$.

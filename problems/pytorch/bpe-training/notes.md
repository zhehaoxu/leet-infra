# BPE 训练 详解

## 为什么是 BPE

词表太大（整词）会 OOV 爆炸、太小（单字符）序列又太长。BPE 折中：以字符为初始词表，**贪心地把最常共现的相邻对合并成新符号**，反复 $K$ 次得到 $K$ 个子词。高频词（如 `the`、`ing`）会被合成单个 token，低频词保持碎片——既控词表大小又天然偏向常见模式。GPT-2 用 5 万级 merge、LLaMA/Qwen 沿用同族（有的用 BPE-variant「unigram/WordPiece」，思想相通）。

## 三步循环

```
统计相邻对(词频加权) → 选最大对(并列取字典序最小) → 全词不重叠替换
```

关键细节，全是丢分点：

1. **词频加权**：计数不是「有多少个词含这对」，而是每词按频率累加。`newer:6` 里的 `e r` 直接 +6，不是 +1。
2. **并列字典序最小**：多个对同频时，`min(pairs, key=lambda p: (-cnt[p], p))`。`p` 是二元组，先比第一个符号再比第二个。**不钉死这条，训练结果不唯一**，判题会崩。
3. **不重叠、从左到右**：合并 `('a','a')` 于 `a a a` 得到 `aa a`（消耗两格、跳过），不是三个两两。用 `i+=2` 的贪心扫描。
4. **`</w>` 当普通符号**：允许 `w` 与 `</w>` 合成 `w</w>`，所以词尾能被并进子词（示例里 `er</w>`）。合并后符号是字符串拼接，可多字符。

## 训练 / 编码是一对

本题只产出**规则序列**；下游 `bpe-encoding` 拿同一序列，对未见词「按规则**优先级**（学习次序=rank）依次应用最靠前的可用对」。所以训练返回的**顺序**本身就是信息，别排序、别去重。

## 复杂度提示（非必须）

朴素每轮全量重扫语料是 $O(K\cdot|\text{语料}|)$。教学题规模很小不必优化；真实实现会维护 pair→词集合的倒排与计数增量更新，避免每轮全表扫描。

## 关联

- 下游：`bpe-encoding`（用这里学的 merges 编码）。
- 对照：operators 里的 `one-hot-encoding`/`embedding-lookup` 是分词之后的环节。

# 分词：从零训练 BPE 合并规则

## 题目描述

Byte-Pair Encoding（BPE）是 GPT-2/LLaMA/Qwen 等主流 LLM 的分词基础。核心思想：从字符出发，**反复合并语料里出现最频繁的相邻符号对**，直到学出足够多的子词。本题实现它的**训练**环节——从带词频的语料里贪心地学出前 $K$ 条合并规则。这是「编码」（`bpe-encoding`）的上游：编码就是按这里的规则次序去应用。

## 算法（务必逐条按此实现，保证唯一解）

给定「词 → 词频」的语料与合并次数 $K$：

1. **预处理**：每个词拆成字符，并在末尾追加边界符 `</w>`。例：`"low"` → 符号序列 `["l","o","w","</w>"]`。若两个词预处理后符号序列相同，词频相加。
2. **统计相邻对**：对每个词的**当前**符号序列，统计所有相邻二元组 `(s_i, s_{i+1})`，每个词的贡献按它的**词频加权**（出现 `f` 次的词，其每对相邻符号计数 `+f`）。
3. **选最优对**：取计数最大的对；**并列时取字典序最小**（先比第一个符号、再比第二个）。记为一条合并规则。
4. **应用合并**：把每个词里所有**从左到右、不重叠**出现的该对 `a b` 替换成拼接符号 `a+b`（`a+b` 是字符串直接连接，可能得到多字符符号如 `"er"`、`"er</w>"`）。同一词内多次出现要全部合并（贪心扫描：命中就合并并跳过两格）。
5. 重复 2–4 共 $K$ 轮（若某轮已无任何相邻对可统计则提前停止）。输出这 $K$（或更少）条规则，**按学习顺序**。

> 边界符 `</w>` 当作普通符号参与配对（因此 `"w"` 与 `"</w>"` 可被合并成 `"w</w>"`）。

## 规则

实现 `solve(word_freqs, num_merges)`：

- `word_freqs`：形如 `[("low", 5), ("lowest", 2), ...]` 的列表（或等价的二元序列）。
- `num_merges`：要学的规则数 $K$。
- 返回**二元组列表** `[(first, second), ...]`（每项是被选中的相邻对，按学习顺序；用 tuple 或 2 元素 list 均可，判题会规范化为 tuple 比较）。

## 示例

语料 `[("low",5), ("lowest",2), ("newer",6), ("wider",3)]`：

- `num_merges=4` → `[('e','r'), ('er','</w>'), ('l','o'), ('lo','w')]`
- `num_merges=8` → 上面 4 条后再接 `[('e','w'), ('ew','er</w>'), ('n','ewer</w>'), ('low','</w>')]`

解释：`('e','r')` 计数最大（newer 的 `e r` 出现 6 次），故第 0 条；合并后 newer 含 `er`，与结尾 `</w>` 组成的 `('er','</w>')` 计数 9（newer 6 + wider 3）成为第 1 条，依此类推。

## 约束

- 词只含小写字母；`num_merges ≥ 0`；词频为正整数
- 并列**必须**按字典序取最小对（否则答案不唯一）——这是本题最大的坑
- 纯 Python 字符串/字典运算，无随机、无 torch；返回顺序即学习顺序

# 推测解码：接受率到加速比的解析账与最优 γ

## 题目描述

推测解码的收益完全可以用两个量算清：**每步期望吐出多少 token**，以及**这一步花了多少时间**。工程上常见两种误判——「接受率 80% 说明能快 80%」和「草稿越长越好」，都能用这道题的式子一句话拆穿。

设 target 每步的时延为 1（归一化），draft 每生成一个 token 的时延为 \(c\)（`cost_ratio`）。一步推测解码要算 \(\gamma\) 个草稿 token、再做一次 target forward，因此这一步的时延是 \(1 + \gamma c\)。

期望吐词数来自逐位接受率 \(\alpha_1,\dots,\alpha_\gamma\)：第 \(\gamma\) 位之后还能再吐一个「免费的」bonus token（target 自己在最后一个位置采样），所以

\[
e(\gamma) = 1 + \sum_{i=1}^{\gamma}\ \prod_{j=1}^{i}\alpha_j
\]

第一项是无论如何都有的那一个 token，第 \(i\) 项是「前 \(i\) 个草稿全部被接受」的概率——因为一旦某位被拒，后面就不可能吐出来。

加速比就是把「多吐的词」摊到「多花的时间」上：

\[
s(\gamma) = \frac{e(\gamma)}{1 + \gamma c},\qquad s(0) = 1
\]

\(\gamma = 0\) 表示不投机（只做 target forward），自然得到基准加速比 1。逐位接受率恒为 \(\alpha\) 时，\(e(\gamma)\) 退化为等比级数 \(\frac{1-\alpha^{\gamma+1}}{1-\alpha}\)。

真实的旋钮是 \(\gamma\)：加长草稿让分子涨（但涨得越来越慢，因为 \(\prod\alpha_j\) 指数衰减），分母线性涨。所以 \(s(\gamma)\) 通常有内点最优，而不是「越长越好」。

## 任务

实现 `solve(alphas, cost_ratio)`：

- 输入：`alphas`（`(G,)` float32，逐位接受率，取值 \([0,1]\)，\(\gamma\) 的上界为 \(G\)）；`cost_ratio`（float，\(\ge 0\)）。
- 输出：
  - `expected`（`(G+1,)` float32）：\(\gamma = 0..G\) 的 \(e(\gamma)\)；
  - `speedup`（`(G+1,)` float32）：对应的 \(s(\gamma)\)；
  - `best_gamma`（int64 标量）：\(s\) 的最大值下标，**并列取最小 \(\gamma\)**；
  - `best_speedup`（float32 标量）：该最大值。
- 内部用 float64 计算后转 float32；`alphas` 为空、越界或 `cost_ratio < 0` 抛 `ValueError`。

## 示例

```
alphas = [0.8, 0.6, 0.5]，cost_ratio = 0.1

γ = 0：e = 1                                  s = 1 / 1.0  = 1.0000
γ = 1：e = 1 + 0.8            = 1.8           s = 1.8 / 1.1 = 1.6364
γ = 2：e = 1.8 + 0.8*0.6      = 2.28          s = 2.28/ 1.2 = 1.9000
γ = 3：e = 2.28 + 0.8*0.6*0.5 = 2.52          s = 2.52/ 1.3 = 1.9385

expected    = [1.0, 1.8, 2.28, 2.52]
speedup     = [1.0, 1.6364, 1.9, 1.9385]
best_gamma  = 3
best_speedup= 1.9385
```

注意从 \(\gamma=2\) 到 \(\gamma=3\) 期望只多吐 0.24 个 token，却多花 0.1 个单位时间——收益已经接近被时延吃掉。

## 约束

- **分母是 \(1+\gamma c\) 而不是 \(1+\gamma c\) 的某个变体**：草稿的 \(\gamma\) 个 token 是一个 token 一个 token 生成的（自回归），不能按一条 forward 计。
- **bonus token 必然计入**：\(e(0)=1\)、\(s(0)=1\)；把 \(e\) 写成「接受 token 数」而漏掉 bonus，会让所有加速比系统偏低。
- **并列取最小 \(\gamma\)**：`cost_ratio = 1` 且全接受时所有 \(\gamma\) 的加速比都是 1，此时应返回 0（不投机）而不是最大 \(\gamma\)。
- **逐位接受率不是同一个 \(\alpha\)**：早期位置通常更容易被接受，用单一 \(\alpha\) 的平均值会高估长草稿的收益。
- 求最大值时不要用「先增后减，取到下降就停」的过早退出：\(s\) 在有噪声的接受率下不保证单峰。

# 详解：一次段内 max 同时堵住上溢与下溢，而内置 norm 并不帮你缩放

## 出处

这套写法不是发明，是标准库几十年前的常规：netlib BLAS 的 `DNRM2` 从 1988 年版起就是「先扫出最大幅值、缩放后再累加平方」的两趟结构（源码里那对 `xtrap` 参数就是为它准备的）；C99 明确希望 `hypot` 不因中间平方而上溢下溢，glibc 的实现靠位分类做到，所以 `math.hypot(3e154, 4e154)` 给 \(5\times10^{154}\)、`math.hypot(3e-200, 4e-200)` 给 \(5\times10^{-200}\)，而 `torch.linalg.norm` 与 `numpy.linalg.norm` 在这两组数上都给 `inf` 和 `0.0`。深度学习里踩这个坑的位置很具体：梯度裁剪、权重范数监控、混合精度下的除零保护，量级天然比训练数据更极端，而 `clip_grad_norm_` 这类实现一旦在 float16 上直接平方就会把「该不该裁」判断成「已经是 inf 了」。

## 缩放为什么双向都安全

\(|x_i|/m\in[0,1]\)，于是 \((|x_i|/m)^p\in[0,1]\)：任一项都不会上溢，而取到 max 的那一项**恰好是 \(1.0\)**，所以段和至少是 \(1.0\)，绝对不可能整体下溢成 \(0\)。这是比「避免 inf」更强的保证——朴素写法在 \(10^{-200}\) 量级上的错不是精度损失，而是把非零答案变成 \(0\)，后续任何 `1/norm` 都会炸。最后把 \(m\) 乘回去只是给一个已经良定的数换尺度。

对 \(p=\infty\) 走的是同一条路的极端形式：缩放因子本身就是答案，幂次没有意义。\(0<p<1\) 时结果不再满足三角不等式（拟范数），但恒等式与算法都不受影响，本题因此允许 \(p=0.5\)。

## 五种退化情形为什么要排序

优先级是 **NaN > inf > 全零 > 空段 > 常规**，每一条都对应一个具体的失败模式：

- NaN 排在 inf 前面，与 `torch.linalg.norm` 的实际行为一致（实测同时含 NaN 与 \(\pm\infty\) 的段给 NaN），但本题要求把这个优先级写成显式判定，而不是让它在缩放链路上「自然涌现」——一旦 \(m\) 变成 NaN，后续 `where` 的分支顺序稍有差别就会让同一段时而 NaN、时而 \(+\infty\)。判定用 `isnan().sum() > 0`，不靠算术传染。
- 含 \(\pm\infty\) 直接给 \(+\infty\)：范数对符号不敏感，\(-\infty\) 也是无穷大。
- \(m=0\) 必须单独给 \(0.0\)：否则 \(|x_i|/m\) 全是 \(0/0=\) NaN，一个全零向量会被算成 NaN——这是这道题最容易写错的一行。
- 空段给 \(0.0\) 而不是抛错：这里靠显式分支返回，**不是**因为归约天然安全——`torch.zeros(0).amax()` 会直接 RuntimeError，必须先判长度。

## 核心与易错点

- **`amax` 会传播 NaN**，所以「先取 max 再判」是可行的分流手段，但拿到的 max 是 NaN 而不是真正的最大值，别再用它去缩放。
- **不要用 `INF * 0.0` 造 NaN**：读代码的人会以为是笔误，写常量 `float('nan')` 或用 `torch.full_like`。
- **中间量必须 float64**：float32 下 \(2\times10^{38}\) 的平方当场是 inf，而 `torch.linalg.norm` 就直接卡在这里；缩放把每一项压到 \([0,1]\)，所以只要段最大值本身还在 float32 范围内就安全，实测 `[2e38, 2e38]` 在 float32 下得到有限的 \(2.8284\times10^{38}\)。
- **结果超出 float32 时转成 inf 是允许的**：`[3e38, 3e38]` 输入 float32 输出 inf，判题只看「不能是 NaN」。
- **`keepdim` 与 `dim=None` 的组合**：整体归约返回 0-D 张量，此时 `keepdim` 不起作用；被归约轴长度为 0 时输出形状由其余轴决定，值全为 \(0\)。
- **符号零**：`[-0.0, 0.0]` 的范数是 \(0.0\)，取绝对值之后符号自然消失，不需要特判。

## 与邻近题的区别

`reduce-axis` 关心轴归约的形状与广播规则，不处理数值尺度；`quant-blockfp-tile` 与 `quant-mx-microscaling` 也做「按块取 max 当共享指数」，但那是量化尺度、不是归约；`logsumexp` 用同样的「减最大值」思想处理 `exp` 的上溢，本题处理的是**幂**的上溢与下溢；`nu-welford-online-variance` 解决的是累加顺序带来的舍入漂移，那是精度问题而不是可表示范围问题。本题的独有切口是「下溢同样是错」，以及五种退化值的显式优先级。

## 对拍口径与复杂度

oracle 完全不用缩放：`Decimal` 以 60 位有效精度直接累加 \(\sum|x_i|^p\) 再开 \(p\) 次方（幂与开方都在 Decimal 里算，不经过 float64 的中间舍入），再用 `movedim` 把被归约轴搬到最后逐段喂进去，与参考解的张量缩放路径毫无重叠。比较用相对容差，NaN 用 `isnan`、无穷用 `==` 短路。用例覆盖 \(p\in\{0.5,1,2,3,8,\infty\}\)、\(10^{150}\) 与 \(10^{-150}\) 两端的随机数据、混合量级段、各 dim/keepdim 组合、五种退化值、空轴、float32 极端值与非法入参。复杂度 \(O(\text{numel})\)：一次 `abs`、一次 `amax`、一次逐元素除法与一次幂求和。

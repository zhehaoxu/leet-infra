# olmOCR 图片元素 union-find 容差合并账

allenai/olmocr 的 `olmocr/prompts/anchor.py` 在为 VLM 生成 PDF 页锚文本
（`pdfreport` 引擎）前，先用 `_merge_image_elements` 把相邻（含小间隙）的
图片 XObject 合并成一个元素——同一张插图在 PDF 里常被切成多块放置，提取
器逐块记录后需要按 bbox 容差并回整图，否则锚文本里会出现一堆碎片化的
`[Image ...]` 行。本题要求逐条复刻这个合并账。

## 接口

```python
solve(images: list, tolerance: float = 0.5) -> list[dict]
```

- `images`：每项 `[name, x0, y0, x1, y1]`（bbox 为 PDF 页面坐标）；
- `tolerance`：合并容差，官方默认 `0.5`；
- 返回每个连通分量一项的 `{"name": ..., "bbox": [x0, y0, x1, y1]}` 列表，
  **输出顺序 = 各分量最小原始下标的升序**。

## 规则

1. **重叠判定**：两框的分离距离
   - `h_dist = max(0, max(两框 x0) - min(两框 x1))`
   - `v_dist = max(0, max(两框 y0) - min(两框 y1))`

   两者**同时** `<= tolerance` 判为重叠。这是闭区间：触碰
   （`h_dist = 0`）与恰好 `gap == tolerance` 都算重叠；一个方向贴近、
   另一个方向远离则不算。包含关系两方向距离均为 0，必然重叠。
2. **合并是传递闭包**：按下标双重循环 `i < j`，重叠即 `union(i, j)`。
   A~B、B~C 而 A、C 自身不相邻时，三者仍在同一分量（union-find 实现，
   路径压缩与根的选择只影响内部表示，不影响分量成员）。
3. **分量内聚合**（成员按下标升序）：
   - `bbox` 取全体成员的外包矩形（逐维 min/max）；
   - `name` 取最小下标成员的名字，其余成员名按**下标升序**用 `"+"`
     依次追加——与 union 发生的方向无关，下标小的名字恒在前。
4. 空输入返回 `[]`；单元素返回其自身（名字与 bbox 原样）。

## 样例

```python
solve([["a", 0, 0, 1, 1], ["b", 1.5, 0, 2, 1]])
# h_dist = max(0, 1.5 - 1) = 0.5 <= 0.5 → 合并
# → [{"name": "a+b", "bbox": [0, 0, 2, 1]}]

solve([["z", 0.8, 0.8, 2, 2], ["a", 0, 0, 1, 1]])
# 名字按下标序拼接，z 在 0 号位
# → [{"name": "z+a", "bbox": [0, 0, 2, 2]}]

solve([["p", 0.8, 0.8, 2, 2], ["q", 0, 0, 1, 1], ["r", 10, 10, 11, 11]])
# 分量 {0,1} 的 min 下标 0 < 分量 {2} 的 min 下标 2
# → [{"name": "p+q", ...}, {"name": "r", ...}]
```

## 提示

- 名字拼接顺序、bbox 逐维 min/max、输出分组顺序三者都由"原始下标"驱动，
  与 union-find 的内部根无关。
- `h_dist` 的 `max(0, ...)` 截断只对**负值**生效（即两框在 x 方向有实际
  重叠时距离记 0）——去掉截断在此判定里不可观察（负值同样 `<= tol`），
  但 min/max 写反立刻可观察。
- 官方调用点（`_linearize_pdf_report`）里合并结果随后参与锚文本长度预算，
  超预算路径含 `random.shuffle`，不在本题范围内。

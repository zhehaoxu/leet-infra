# 解题笔记：Aho–Corasick 多模式替换

## 来源与边界

多模式检测采用 Aho 与 Corasick 于 1975 年提出的经典 Aho–Corasick 算法：以 trie、失败链接及输出集合同时查找多个关键词。本题的**最左、同起点最长、同长取最小下标，以及一次性替换**是明确附加的题目规则，不声称它们属于原论文的替换语义，也不对应某个具体库的默认行为。

## 1. 建立 trie 并保留重复下标

每条边对应一个 Python 字符。节点保存子节点映射、失败链接及模式下标列表。插入模式时，在终点追加下标，而不是只记录一个布尔值或去重后的模式字符串。重复模式应共享路径，但必须保留各自的下标。

必须在处理空文本等快捷返回之前检查空模式并抛出 `ValueError`。

## 2. BFS 构建失败链接和继承输出

根的直接子节点的失败链接指向根。按 BFS 处理边时，从父节点的失败状态开始寻找相同字符的转移；不存在则沿失败链接继续回退，最终可回到根。

为子节点设置失败链接后，把失败目标的输出列表追加到子节点输出中。BFS 保证更浅状态的输出已完整，因此后缀链上的所有模式均可被报告。仅记录当前 trie 终点会漏掉后缀匹配。

示例 1 中，扫描到 `she` 的结尾时，输出包含 `she` 的下标 1 和两份 `he` 的下标 0、3。

## 3. 单次扫描原文，随后整理匹配

保持自动机状态逐字符读取原文。遇到没有转移的字符时沿失败链接回退；读取一个字符后，对当前状态的全部输出生成匹配。

若已读取的 code point 数为 $e$，模式长度为 $\ell$，则原文匹配区间为 $[e-\ell,e)$。扫描过程中不要插入替换文本。最后将全部匹配按 `(start, end, index)` 排序，得到 `all_matches`。

## 4. 独立执行选择和替换

为了选择，另按 `(start, -end, index)` 排序：同一起点下，较大的终点就是更长的匹配。保留首个 `start >= consumed` 的记录并令 `consumed = end`。不要原地重排需要返回的 `all_matches`。

该顺序恰好实现契约中的三层优先级。一个选中区间之后，起点在其内部的匹配全部不合法；相邻匹配仍可选。它不是全局最长优先，也不是最大覆盖长度优化问题。

最后从左到右拼接“未覆盖原文 + 对应替换字符串”，并追加原文尾部。`ushers` 示例的真实输出为 `uSrs`，只选中 `(1, 4, 1)`。Unicode 示例输出为 `CE`，选中区间是 `(0, 2, 1)`、`(2, 3, 0)`、`(3, 5, 2)`。删除形成的新邻接关系也不能触发第二次替换。

## 复杂度

令 $P$ 为模式总长度，$S$ 为 trie 状态数（$S\le P+1$），$L$ 为最长模式长度（无模式时取 0），$H$ 为继承后所有节点输出列表的总条目数，$N$ 为原文长度，$Z$ 为全部匹配数，$R$ 为结果字符串长度。

在字典操作均摊常数时间的模型下，本参考实现使用稀疏转移，并在 BFS 建链时显式回退；保守的构建界为 $O(P+SL+H)$，不能忽略继承输出的复制。扫描为 $O(N+Z)$，两次排序为 $O(Z\log(Z+1))$，拼接为 $O(N+R)$。含返回值的空间为 $O(S+H+Z+R)$。空输入还需要常数开销。

## 独立验证

15 个 `check_*` 覆盖失败输出继承、多级回退、后缀与重叠、重复模式平局、最左优先、最长优先、Unicode/组合字符、空输入、空替换、非级联、输入不变及非法空模式。上界用例使用 500 字符、30 个模式；随机用例固定种子 8201，共 180 组。

测试 oracle 不构建自动机：逐位置用 `startswith` 枚举全部匹配；另外逐字符推进原文位置，在该位置独立挑选最长模式进行替换，而不是复用参考解的匹配排序和筛选流程。返回容器、三元组和整数类型也单独检查。

# Self-Consistency 多数投票账：答案归一化与票仓聚合

## 题目描述

Self-consistency（Wang et al. 2022, arXiv:2203.11171）是推理期最朴素的免费午餐：同一个问题
采样 N 次，把 N 条输出里的**最终答案**抽出来做多数投票，得票最高者胜。工程上它的痛点不在
投票本身，而在**答案归一化**——"42"、" 42 "、"42."、"$42"、"42%" 在人眼里是同一个答案，
在字符串世界里是五个。归一化规则定松了票仓分裂，定紧了误合并。

> 为保证判题**确定性**，输入 `samples` 已由调用方截取为答案段（而非整句 CoT）；
> 归一化规则在题面**逐条钉死**，不允许实现自行发挥（如把 "1/2" 与 "0.5" 数学合并）。

## 规则

- 实现 `solve(samples, weights=None)`：
  - `samples: list[str]`，每条候选的答案段；
  - `weights: None 或 list[float]`，与 `samples` 等长的票重，缺省全 1。
- **归一化规则（依次执行）**：
  1. 去首尾空白；
  2. 全部转小写；
  3. 去千位逗号：仅当逗号**前后都是数字**时删除（"12,345" → "12345"）；
  4. 去尾随句点（仅一个，"42." → "42"）；
  5. 分数统一为 `"a/b"`：`"a ÷ b"` 与 `"a / b"`（斜杠两侧空格任意）都写作 `"a/b"`，
     其中 a、b 是正整数且前后无其他数字（字母操作数如 "a/2" 不套用此规则）；
  6. 百分号剥离："42%" → "42"；
  7. 货币符号剥离：前导 "$" 剥离；
  8. 其余字符原样保留——**不做数学等价合并**，"1/2" 与 "0.5" 是不同答案。
- **计票**：`tally` 是「归一化答案 → 累计票重」的 dict，键按**首次出现顺序**排列；
  `winner` 取票重最大者（**并列取首次出现者**，即严格大于才覆盖）；
  `vote_share = winner 票重 / 总票重`（总票重为 0 时取 0.0）。
- 返回 dict：`normalized`（逐条归一化结果）、`tally`、`winner`、`vote_share`、`n_candidates`。
- 校验：`weights` 与 `samples` 长度不匹配、票重为负 → `ValueError`。

## 示例

```
输入：samples = ["1,234.", "1234", "1/2", "1 ÷ 2", "$1,234"]
  归一化：["1234", "1234", "1/2", "1/2", "1234"]
  tally = {"1234": 3.0, "1/2": 2.0}
输出：winner = "1234", vote_share = 0.6, n_candidates = 2
```

## 约束

- 纯 Python 字符串处理即可（torch 无关）；`samples` 可为空列表（返回空账本、`winner=None`）
- 票重可为 0（全零时 `vote_share = 0.0`，`winner` 仍按首次出现规则给出）但不可为负
- 归一化必须严格按规则 1→7 的顺序执行（顺序影响结果，如 "$1,234" 需先删逗号再剥 $）

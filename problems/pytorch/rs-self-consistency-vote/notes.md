# 解题说明 · Self-Consistency 多数投票账

## 设计取向：规则字面化，不猜语义

self-consistency 的原始论文用 EqQA 风格的答案抽取 + 精确匹配计票；本实现把「工程中实际会遇到的
格式噪声」收敛成 8 条**可独立判定的规则**，全部按字面执行：

- 规则 3 的千位逗号**只看局部上下文**（前后都是数字），不校验分组长度是否为 3——所以 "1,2"
  也会变成 "12"。这是刻意的：判题要的是规则的可预测性，不是智能。
- 规则 5 的分数统一只作用域于**纯整数操作数**：`(?<!\d)(\d+)\s*(?:/|÷)\s*(?<!\d)(\d+)(?!\d)`。
  "A/2"、"10 %空格" 等边界都是为了让 oracle 与 solution 能逐条对拍。
- 规则 8 明确**不**做数学等价（"1/2" ≠ "0.5"）：一旦引入数值解析，浮点比较、精度、无穷多种
  写法都会破坏确定性。真实系统里这一步通常交给更强的 answer-extraction 模型，而不是正则。

## 计票的三个确定性细节

1. **键序 = 首次出现序**：`tally` 用普通 dict 按插入序增长（Python 3.7+ 保序），测试直接断言
   `list(tally.keys())`，任何按字母序/计数值重排键的实现都会被抓。
2. **并列取首次出现**：扫描 `tally.items()` 用**严格大于**才覆盖 winner——票重并列时先出现者
   胜。用 `max(tally, key=...)` 的实现要注意 `max` 遇到并列会取**第一个**最大者，行为恰好一致，
   但若 key 里掺了次级排序（如字母序）就会偏离。
3. **vote_share 分母是总票重**（`sum(weights)`），不是样本数。全零票重是合法输入：share 取
   0.0，winner 仍按首次出现给出——分母为 0 的除法需要显式分支。

## Oracle 与变异测试

- `test_cases.py` 里的 `_normalize_oracle` 是**独立手写实现**（千位逗号用逐字符扫描、分数统一用
  span 预扫描重建），与 solution 的 regex 写法互为印证，避免「同一份正则的自我确认」。
  注意判题环境以 `check_*(solve)` 形式注入 solve，顶层 `from solution import _normalize` 会
  `ModuleNotFoundError`，所以 oracle 必须自带。
- 关键边界用例：`"1,2"` → `"12"`（规则 3 字面语义）；`"A/2"` 与 `"a ÷ 2"` 不合并（字母操作数
  不套分数规则）；`"10 %"` → `"10 "`（% 剥离不看前导空格，残留尾空格是规则的忠实结果）。
- 变异测试 9 条有效变异全抓（去空格/去 lower/千位逗号全删/不去尾点/分数规则删除/% 不剥/$ 不剥/
  并列取末次/share 分母改样本数）；`dict.fromkeys([])` 为无效变异（构造不出可观察差异）。

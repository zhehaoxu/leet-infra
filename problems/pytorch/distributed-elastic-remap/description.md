# 分布式：弹性容错 rank 重映射与分片迁移

## 题目描述

部分 rank 故障后，为幸存 rank 重新编号，并从检查点恢复故障 rank 原先负责的参数分片。原有 `world_size` 个 rank 各持有一个等大的分片，总参数字节数为 `param_bytes`。

**恢复前提：存在一致的持久化检查点，其中包含每个故障分片。** 幸存者保留自身在同一检查点状态下的分片，故障分片从该检查点读取。若某份唯一数据只在已经丢失的内存中、没有持久化副本，本题的重映射无法恢复它。

## 重映射与恢复规则

1. 将故障 ID 去重；输入顺序不影响结果，重复 ID 不重复恢复。
2. 幸存 rank 按**旧 ID 升序**保留并重新编号为 \(0,1,\ldots,W'-1\)，其中 \(W'\) 是幸存 rank 数。旧 ID 的映射中，故障位置记为 -1。
3. 将**排序去重后的故障 ID**对应的检查点分片依次分配：从新 rank 0 开始轮询，第 \(i\) 个故障分片交给新 rank \(i\bmod W'\)，索引从 0 开始。目的列表使用新 ID，不是旧 ID。
4. 幸存者原有分片不搬动。`migration_bytes` **只统计故障分片的检查点恢复载荷**。

令故障 ID 集合为 \(F\)，每个原始分片大小为 \(s=\text{param_bytes}/\text{world_size}\)，则

\[
W'=\text{world_size}-|F|,
\qquad \text{migration bytes}=|F|s.
\]

原始分片必须等大，故总字节数应整除原 rank 数；无故障时无需恢复；若全部故障，则没有接收者，不能按此模型继续。具体类型、取值范围与 `ValueError` 约定见 starter。

这是确定性的检查点恢复账本，**不是 torchelastic 的真实 rank 重新分配算法**，也不模拟完整重启或所有分片按新 world size 重新切分。

## 示例

```text
world_size=4, failed_ranks=[1, 3], param_bytes=16
幸存旧 rank [0, 2] -> 新 rank [0, 1]
故障检查点 shard 1 -> 新 rank 0，shard 3 -> 新 rank 1
每分片 4 字节，只恢复两个故障分片，共 8 字节
返回 (2, [0, -1, 1, -1], [0, 1], 8)
```

```text
world_size=8, failed_ranks=[7, 2, 5, 0, 4], param_bytes=64
幸存旧 rank [1, 3, 6] -> 新 rank [0, 1, 2]
故障分片排序为 [0, 2, 4, 5, 7]，恢复目的为 [0, 1, 2, 0, 1]
返回 (3, [-1, 0, -1, 1, -1, -1, 2, -1], [0, 1, 2, 0, 1], 40)
```

第二个示例中，每个幸存 rank 额外接收的分片数为 `[2, 2, 1]`。只有故障分片增加恢复载荷，幸存者已有的三个分片不计入迁移字节数。

# 详解：SparseGPT 逐列剪枝与 Hessian 误差补偿

## 出处
补偿公式来自 OBS（Optimal Brain Surgeon）的闭式更新，SparseGPT（Frantar & Alistarh, *SparseGPT: Massive Language Models Can Be Accurately Pruned in One-Shot*, 2023, arXiv 2301.00774）把它做成逐列、不必重算 Hessian 的一次性流程，并用 Cholesky 增量维护 \(H^{-1}\)；GPTQ（Frantar et al., 2022）在量化场景下用的是同一套误差补偿骨架，区别是「被替换成量化值」而不是 0。本合集里 `sparsity-rowwise-prune` 只做局部幅值剪枝、不算补偿，`quant-gptq-column-quantize` 是全量逐列量化——本题考「先掩码、再把误差推给右侧列」这一环。

## 核心与易错点
1. **顺序扫描、就地更新**：`cur` 必须是**更新后**的当前列，不能回读原始 `weight`，否则左侧的补偿全部丢失。
2. **除以对角元**：\(e\) 要除以 \([H^{-1}]_{jj}\)，而不是 \(|W_{:,j}|\) 或对角元 \(H_{jj}\)；对倒数的直觉（有人会写成 \(H_{jj}\)）是最常见的公式错。
3. **误差项用当前值减掩码值**：\(cur-Q\) 在掩码为 0 时就是 `cur` 本身（被剪的值），在掩码为 1 时为 0；因此全保留时 \(e\equiv0\)，整个算法退化为恒等。
4. **外积方向**：\(e\in\mathbb{R}^{R}\)、\([H^{-1}]_{j,j+1:}\in\mathbb{R}^{C-j-1}\)，结果是 \((R,C-j-1)\) 的秩 1 修正；维度写反会在非方阵上直接报错或悄悄广播错。
5. **最后一列的误差无处安放**：它会被丢弃，这也是为什么剪枝应尽量往右侧「推」——真实现里还会按列重排（block-wise）来控制误差累积。
6. **掩码位置必须严格为 0**：补偿只改动未被掩码的列，不能把刚置零的列又填回去。

## 对拍口径
参考解 `clone` 后在 Python 循环里逐列更新。判题 `_oracle` 用纯 Python 双重列表按定义逐步重算（不共享任何张量操作），逐位对拍。独立断言：全 1 掩码结果与输入逐位一致；全 0 掩码输出全 0（每列轮到自己时都被清零）；`Hinv=I` 时结果恰好等于 `weight*mask`（无列间耦合的退化）；所有掩码位严格为 0；用 \(H=XX^\top+\lambda I\) 构造真实 Hessian 后，断言 \(\|W_{out}X-WX\|_F\) **严格小于**朴素掩码的 \(\|(W\odot m)X-WX\|_F\)——补偿确实在吸收误差；输出 dtype/shape 正确。

## 复杂度
\(O(RC^2)\)（每列一次长度 \(C-j\) 的外积更新）；显存与 `weight` 同阶。

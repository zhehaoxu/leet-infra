# In Depth: MARS Variance-Reduced Momentum with Trust Ratio

## Source

- The algorithm: Yuan et al., *MARS: Unleashing the Power of Variance Reduction for Training Large Models*, arXiv:**2411.10438** (verified; note that the todo registration wrote 2411.10970, which is not this paper), official implementation `AGI-Arena/MARS`, presented at ICML 2025. This problem implements the paper's Eqs. (3.10)–(3.12) and Algorithm 2, the **MARS-AdamW instantiation**: the STB-style variance-reduced estimate \(c_t=g_t+\gamma\frac{\beta_1}{1-\beta_1}(g_t-g_{t-1})\) (the reference folds the coefficient into \(\gamma'\)), plus the Eq. (3.5) norm-clip trust ratio \(\rho_t=\min(1,1/\|c_t\|_F)\). The judge environment is offline; **the algorithm is defined by the problem statement and starter comments**.
- Library side: kozistr/pytorch_optimizer ships `MARS` (exact file and attribute naming **to be re-sourced**). Key engineering conventions of the reference implementation: `last_grad` zero-initialized (first step \(g_0:=0\)), trust ratio on the whole-tensor Frobenius norm, and optional `ams_bound` (the reference's AMSGrad-style running maximum of the second moment, the paper's "adaptive clipping of the second moment").
- One-line summary: **MARS swaps Adam's driving signal from \(g\) to "extrapolated momentum-corrected + tensor-normalized" \(c̃\)**. Momentum no longer looks only at the current gradient but also at how it changed relative to the last step; the trust ratio pulls an over-excited estimate back into the unit ball as a whole.

## Full derivation and index convention

At step \(t\) (per-parameter counter starting from 1), three components divide the labor:

- **The variance-reduction term \(\gamma'(g_t-g_{t-1})\)**: the Adam-flavored form of STB (STochastic recursive gradient) ideas. Plain momentum \(m_t=\beta_1m_{t-1}+(1-\beta_1)g_t\) is an exponential average of \(g\); MARS **extrapolates** the gradient one slot before feeding momentum: \(c_t=g_t+\gamma'(g_t-g_{t-1})\). When the gradient is stationary, \(g_t\approx g_{t-1}\) and \(c_t\approx g_t\) (no disturbance); when it jitters, the difference term amplifies "change" information while the momentum average keeps the variance down — the paper's core claim is that this lowers Adam's update variance. The coefficient \(\gamma'=\gamma\beta_1/(1-\beta_1)\) ties the paper's \(\gamma\) to the momentum correction: as \(\beta_1\to1\) the extrapolation gets more aggressive; as \(\beta_1\to0\) momentum has no memory and the coefficient shrinks proportionally.
- **The trust ratio \(\rho_t=\min(1,1/\|c_t\|_F)\)**: **one scalar per tensor** (not per coordinate, not per batch). If \(\|c\|_F\le1\) then \(\rho=1\) (no-op); if \(\|c\|_F>1\) then \(c̃=c/\|c\|_F\) (back into the unit ball). Equivalently \(c/\max(1,\|c\|_F)\), isomorphic to global norm clipping — except the clipped object is the **estimate**, not the gradient itself. Crucially \(c̃\) feeds **both** moments, so after a clipped first step \(\|m_1\|_F=(1-\beta_1)\|c̃\|_F=(1-\beta_1)\) holds exactly (the judge uses this as a pin).
- **The `last_g` ledger**: at the end of every step `last_g ← g`, and **only when that parameter actually had a gradient** — a parameter skipped by `grad is None` does not touch the ledger, so empty steps contribute no phantom differences. The first step assumes \(g_0:=0\) (the natural consequence of zero-initialized state), hence \(c_1=(1+\gamma')g_1\): step one already carries the 22.5% extrapolation. That is a convention, not a bug — the example and the oracle both match it.

Shared with opt-adamw: decoupled weight decay first, the \(1-\beta^t\) bias-correction positions, ε added after correction — all follow the opt-adamw convention. The only fork is the **driving signal**: \(g\to c̃\). Therefore with `gamma=0` (estimate degenerates to \(g\)) and the trust ratio never triggered (\(\|g\|_F<1\) throughout), MARS must equal native AdamW bit-for-bit — the judge's \(10^{-7}\) comparison pins both "the estimate is right" and "the AdamW skeleton is right".

Optional `ams_bound`: \(v_{\max}\leftarrow\max(v_{\max},v)\), denominator base is the running maximum. Semantically this is **adaptive clipping of the second moment**: no later denominator may fall below the historical peak, i.e. a monotone upper bound on the adaptive step size. It works at the other end of the chain from the trust ratio (one clips the estimate's norm, the other clips the second moment along time), and they compose.

## Key points and common mistakes

1. **The \(\gamma'\) conversion**: \(\gamma'=\gamma\beta_1/(1-\beta_1)\). Using \(\gamma\) directly as the difference coefficient, or writing the denominator as \(1-\beta_1^t\), gives different algorithms. With \(\beta_1=0.9\), \(\gamma'=2.25\gamma\) — the default \(\gamma=0.025\) gives \(\gamma'=0.225\). The judged example is pinned to 0.225.
2. **Clip before the moment estimates, and \(c̃\) feeds both \(m\) and \(v\)**. Clipping only \(m\)'s input while \(v\) consumes raw \(c^2\) keeps the unclipped spikes in the second moment — contradicts Eqs. (3.10)–(3.12) and fails the random-sequence comparison.
3. **The trust ratio is a per-tensor scalar.** Per-coordinate \(\max(1,|c_i|)\) is a different clip (inf-norm); concatenating across parameters is yet another. Here it is **one Frobenius norm per parameter tensor**, with 1-D and multi-dimensional on the same path — no "element-wise" branch for 1-D.
4. **The \(g_0:=0\) first-step convention.** Initializing `last_g` to the first gradient (so the first difference is 0) is another reasonable algorithm, but not this problem's convention — the judged first-step trajectory follows \((1+\gamma')g_1\).
5. **`last_g` updates only on gradient-bearing steps.** A skipped step (`grad is None`) neither updates the ledger nor advances the counter; hoisting the `last_g` update out of the parameter loop feeds phantom differences into the next active step.
6. **Trust ratio after weight decay, before moment estimates.** Decay acts on \(\theta\) and never affects \(c\); feeding decayed "gradients" into \(c\) is meaningless.
7. **Bias correction uses the parameter's own step counter.** Per-parameter counters start at 1; `grad is None` steps do not advance \(t\) (same semantics as native AdamW's `state['step']`).
8. **`ams_bound`'s `v_max` is per-parameter**, updated after \(v\) and read as the denominator base after that; zero-initialized.

## Differences from neighboring problems

- **vs `opt-adamw`**: degenerates bit-for-bit with gamma=0 and small gradients; the entire difference lives in the driving signal — AdamW eats \(g\), MARS eats \(g+\gamma'\Delta g\) normalized per tensor. MARS tracks AdamW closely on stationary stretches and gets reshaped by \(\rho\) and the difference term on turning steps.
- **vs `opt-sophia2` / `opt-copt`**: all three carry a "trust/bounding" component, at different layers — Sophia's bound is an **element-wise** clip on the curvature-preconditioned \(m/H\); COPT is a **tensor-wide scalar gate** multiplied into the Adam direction followed by an element-wise clip; MARS is a **tensor-wide scalar rescale** applied to the **input of the moment estimates** (the update direction itself carries no clip, so \(|\Delta\theta|\) has no hard lr·constant bound). Ask "which link of the chain gets clipped" to tell them apart.
- **vs `opt-radam` (RAdam)**: both say "variance reduction" about different objects — RAdam fixes the **second-moment denominator's** estimation variance (rectifying the adaptive step early in training), MARS fixes the **gradient estimate's** variance (STB extrapolation). RAdam touches the \(v\) convention, MARS touches the \(c\) convention.
- **vs `opt-lookahead`**: Lookahead does multi-step folding at the wrapper level without touching the single-step update; MARS reshapes the driving signal within a single step. Orthogonal and composable (MARS inside, Lookahead outside).

## Cross-check convention and complexity

- Main criterion: the independent recompute \(\_oracle\_mars\) — no Optimizer class, pure torch recomputation in the stated order (\(c\), trust ratio, both EMAs, bias correction all independently expressed), step-by-step over a 15-step random sequence with `allclose(atol=1e-5, rtol=1e-5)`; 1-D parameters go through float64 scalar loops in the oracle, sharing only the formula with the reference's float32 vectorized path.
- Hard reference: with `gamma=0` and small gradients, bit-for-bit match with **native `torch.optim.AdamW`** (\(10^{-7}\)).
- Structural assertions: a first step with \(\|c\|_F>1\) gives \(\|c̃\|_F=1\) and \(\|m_1\|_F=(1-\beta_1)\) exactly; a `grad is None` parameter stays bit-identical (including `last_g` untouched by empty steps); with `ams_bound` the denominator never falls below the historical peak.
- Complexity: \(O(\text{numel})\) per parameter per step; over AdamW it adds one difference, one norm reduction and one conditional rescale; state carries an extra `last_g` (plus \(v_{\max}\) under `ams_bound`) — roughly 1.5–2× Adam's memory.

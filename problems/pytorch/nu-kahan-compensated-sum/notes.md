# 详解：补偿求和的分支条件与「非有限值必须退化」

## 出处

Kahan 在 1965 年的内部技术笔记里给出了补偿求和，Babuska 与 Neumaier 先后把它改进成现在的形式（Higham 的《Accuracy and Stability of Numerical Algorithms》里有完整推导）。NumPy 的 `np.sum` 在 float64 上默认走 pairwise（`math.fsum` 则另走一条精确路径），CUDA 的 `cub::DeviceReduce` 也是分块归并。面试里被问的场景通常是：「为什么 loss 累加到后期会漂」「all-reduce 为什么不能简单 tree-reduce 一把梭」「fp16 求和为什么要有个 scale」。能把四种模式的误差来源讲清楚，比记住公式更值钱。

## 四种模式各自在防什么

一次 double 加法 \(s+v\) 的舍入误差恰好是「被丢掉的那些低位」，补偿求和的全部技巧就是把它算出来并留着：

- `kahan` 的 \(c=(t-s)-y\) 靠的是 Sterbenz 引理：当 \(|y|\le|s|\) 时 \(t\) 与 \(s\) 相差不超过一倍，\(t-s\) 可以精确表示，于是 \(c\) 恰好等于被丢掉的部分。但它要求 \(|y|\le|s|\)（即新元素不超过当前部分和），否则 \(t-s\) 会把 \(y\) 的低位一起吞掉。
- `kahan_babuska`（Neumaier）用 \(|s|\ge|v|\) 显式判分支，两种情况分别写 \((s-t)+v\) 与 \((v-t)+s\)，所以「大数吃掉小数」与「小数累到大数上」两条路径都有补偿。示例里 \([10^{16},1,-10^{16},1]\) 只有它给出真值 2。
- `pairwise` 放弃逐步补偿，改成「缩短加法链长度」：长度为 \(n\) 的顺序累加误差界是 \(n\cdot\epsilon\)，二分归并的树深只有 \(\log_2(n/\text{block})\)，于是误差界降到 \((\text{block}+\log_2(n/\text{block}))\epsilon\) 量级。这也是 `block` 存在的原因——块内仍是一次顺序累加。

## 核心与易错点

- **返回 `s` 还是 `s+c`**：朴素 Kahan 按定义只返回 \(s\)（\(c\) 是给下一步用的），Neumaier 必须返回 \(s+c\)。把 Kahan 也写成 \(s+c\) 会让它在示例上给出与 naive 不同的值，判题立刻挂。
- **分支比较的对象**：Neumaier 比较的是 \(|s|\ge|v|\)（加数与部分和），不是 \(|t|\) 或 \(|y|\)；写成 \(|t|\ge|v|\) 在 \(t=s\) 的场合会走错分支。
- **非有限值必须整体退化为 naive**：补偿项里必然出现 `s - t`，而 `inf - inf = nan`。若不给 \([+\infty, 1.0]\) 特殊处理，裸写补偿会返回 NaN，正确答案却是 \(+\infty\)。本题因此规定「展平后出现过非有限值就用顺序累加」，这条规则同时让 \(+\infty\) 与 \(-\infty\) 同时出现时自然得到 NaN。
- **`pairwise` 不一定更好**：`block=2` 时两块和恰好互相抵消，结果 0.0 比 naive 的 1.0 更差。这是测试里刻意保留的一条，用来打掉「pairwise 永远更准」的错觉——它改善的是误差界而不是运气。
- **空张量**：`numel == 0` 时四种模式都给 0.0，`pairwise` 不能因为递归切分而抛异常。
- **先转 float64**：float32 输入必须升精度后再累加，否则 ulp 变成 1e-7 量级，示例上的整数关系全部失效。

## 与邻近题的区别

`cumsum-scan` 要求保留每一个前缀和（无法用一条补偿链覆盖全部输出），`reduce-axis` 考的是轴归约的形状语义与广播而非精度，`fp16-loss-scaling` 处理的是动态尺度而不是加法顺序误差。本题的独有考点是「同一份数据、四种模式、三个不同整数」，以及非有限值下的退化约定。

## 对拍口径与复杂度

oracle 用 `math.fsum`——CPython 里用 Shewchuk 的部分和数组精确跟踪所有量级、最后一次舍入的实现，与参考解的四条路径都不同；良态数据上四种模式都必须在 1e-12 相对误差内命中，示例数据则要求逐位相等（1.0/1.0/2.0/0.0）。`beats_naive` 用例把 1.0 与一万个 1e-16 相加：朴素结果是 1.0（1e-16 远小于 ulp(1.0)=2.2e-16，全被吞），Neumaier 与 fsum 差在 1e-15 以内且严格优于 naive。时间 \(O(n)\)，`pairwise` 递归归并的额外空间 \(O(n/\text{block})\)。

## Core and pitfalls

- **The two quota regimes are not two spellings of one thing.** Mask mode eats the **per-step quantity** \(q_{\min(t,N-1)}\) from 310-311; uniform mode eats the **cumulative target** \(\lceil (t+1)L/N\rceil\) from 273 and subtracts what is already committed at 274. For \(L=10,N=6\): per-step table \([2,2,2,2,1,1]\), prefix sums \([2,4,6,8,9,10]\), cumulative targets \([2,4,5,7,9,10]\) (increments \([2,2,1,2,2,1]\)). They agree only when \(N\mid L\).
- **`high_conf.sum() >= num_to_transfer` is `>=`, and the commit set is every above-threshold position** (321-322) — possibly far more than the quota. A quota of 0 (the tail when \(N>L\), `base=0` with the remainder already spent) still takes this branch, so "one above threshold, one committed". The top-k fallback instead clamps with `k = min(num_to_transfer, active.sum())` (324) and skips when `k=0` (325) — an empty row there can mean either "quota not needed" or "this row has no masks at all".
- **`masks_remaining` is a global test** (305, `active_block.any()` with no batch reduction), but it only decides whether to enter the `if` at 309; inside, rows are still computed separately. No mask anywhere in the block → `transfer` is empty for the step even if every confidence clears the threshold; one maskless row → only that row empties.
- **The `editing_threshold` switch means opposite things in the two modes.** 330 is `is not None and > 0.0`: `0.0` and negatives **disable** editing (the class docstring at 63 states "`None`, `0.0`, or negative disables editing"); 281 checks only `is not None`: `0.0` and negatives **enable** editing, where `confidence > 0.0` is nearly always true and the editing set degenerates to `committed & (tokens != sample)`.
- **Uniform mode's `committed` is the state *before* the step, and \(t == 0\) forces it empty** (266-267 also reset on a shape mismatch). Ranking pushes committed positions to the back via `masked_fill(-inf)` at 276 and gets ranks from the `argsort(..., descending=True).argsort(...)` at 277; that is why 278 must AND in `~committed` — writing only `ranks < needed` would re-count committed positions against the quota.
- **The union at 278 never truncates the threshold term**: uniform mode is likewise "quota ∪ above-threshold", same root as the `>=` branch of mask mode, but here both halves can fire on the same position — `needed` only constrains the ranking half.
- **The last re-noising happens on the updated state** (287 assigns `self._committed = committed | transfer_index` first, 291 only then uses it in `torch.where`). So positions committed this very step are not wiped by `randint`, and neither are edited positions (they were already in `committed`). Writing `where(committed, ...)` re-randomises the whole batch just committed.
- **`prompt_mask` is read only in the mask-mode editing branch** (333-335); uniform mode never looks at it. Conversely `committed`/`random_tokens` are never read in mask mode. The two modes' ignored inputs are complementary.
- **Every comparison happens in float32**: `.to(dtype=torch.float32)` appears at 269, 315 and 338. Take a float64 `sampled_probs = [0.9500000000000001, 0.96, 0.5, 0.4]` with `threshold = 0.95`: compared in float64, the above-threshold set is \(\{0,1\}\); downcast first (0.9500000000000001 → \(0.949999988079071\), exactly the float32-cast threshold) and only \(\{1\}\) survives. With \(L=4,N=4\) (per-step quota 1) both take the `>=` branch, but the first commits one extra position; the measured difference is `transfer_index[0][0]`.
- **The comparison value of an unselected position is \(-\infty\), not 0** (316, 339). Filling with 0 would let a `threshold < 0` input count inactive positions as above threshold; `-inf` also guarantees they rank behind every real probability in any top-k.
- **Ties are taken in ascending index order.** Upstream 326 uses `torch.topk`, whose tie order is undocumented; measured on CPU float32, the set produced by `(v.argsort(descending=True).argsort(dim=-1) < k)` matched `topk(v, k).indices` on all 4914 random steps (\(L\in\{5..16\}\), \(N\in\{2..7\}\), three thresholds, with `-inf` fills and exact ties), so this problem pins the tie rule down to "smaller index wins".
- **`minimal_topk` is a dead parameter**: after being read from config at 243-244, `step` never references it again (grep hits only 75, 194, 230, 243, 244). No "commit at least k" floor exists; both `quota` and the top-k branch can yield an empty row.
- **`timesteps` is a descending array while `step` treats its argument as an index** (78/96 build `arange(N-1,-1,-1)`, 259-262 does `int(timestep)` directly, and 266 uses `step_index == 0` to mean "start of the block"). The two conventions contradict each other: feeding the descending array would clear `committed` on the block's **last** step. This problem follows the docstring at 209 ("Current step index within the block's refinement schedule") and takes the 0-based step index reading.

## Differences from upstream

- Upstream `step` takes `model_output` (logits of shape \((B,L,V)\)) as its first argument and does temperature/top-k/top-p/`multinomial` sampling internally at 247-255. This problem hands you the sampling result (`sampled_tokens`, `sampled_probs`) and keeps logits, temperature, `top_p`, `top_k` and `sampling_method` out of the statement. One aside from the same code: the greedy branch at 162-166 (`temperature == 0.0` or `not use_multinomial`) never calls `_top_k_filtering`/`_top_p_filtering`, so `top_p`/`top_k` are inert under greedy.
- Upstream generates its re-noising tokens with `torch.randint` at 288-290; here they arrive as the `random_tokens` input, so no `generator` belongs in the statement.
- Upstream hides `_committed` and `_transfer_schedule` in instance state, reset implicitly in two places — `set_timesteps` (100) and `step_index == 0` (266). Here `committed` is an explicit argument that is merely ignored at \(t == 0\), and a single step is stateless.
- Upstream reads the quota table from `self._transfer_schedule`, and when that is `None` (second condition at 309, i.e. `set_timesteps` never called) the whole step transfers nothing. Here the table is computed from \(L,N\) and \(N\ge1\) is required, so the empty-tensor path for `num_inference_steps <= 0` (104-105) cannot occur.
- Upstream validates nothing about the value range of `sampled_probs`, tensor shapes, or finiteness of `threshold` (`step` contains no `raise` at all; it relies on `sample.shape` and `mask_token_id` implicitly holding). Here shapes must agree, \(p\in[0,1]\), finite, scalar inputs must be Python ints (`bool` illegal), and violations raise `ValueError`.
- Upstream returns a six-tuple or a `BlockRefinementSchedulerOutput` (293-302, 351-360) that echoes `sampled_tokens`, `sampled_probs` and `pred_logits` for the next self-conditioning step; here only the three decision outputs come back.
- Upstream lets `prompt_mask` broadcast and never checks `mask_token_id` for non-negativity; here `prompt_mask` must be exactly \((L,)\).
- The statement excludes `check_eos_finished` (362-410), `check_block_should_continue` (412-454) and `add_noise` (456-518): the first two are loop-termination tests (EOS settled, post-processing step cap) and the third is training-side forward mask construction — none is part of the single-step commit decision.

## Relation to other problems

- `diff-amused-topk-remask` is also the discrete side of "commit a part each step, re-mask the rest", but there the quota comes from `MaskScheduler.sample_topk`'s probability-mass cut and the re-masking inside `step`; here the quota is a spread of the block length and there is no distribution truncation at all, only ranks and two thresholds.
- `diff-entropy-bound-unmask` decides "which positions to unmask this step" for a masked LM via entropy/confidence ranking plus a length table; that is a single-regime ordering problem, while the point here is precisely that **the two regimes use different quotas**.
- `diff-vq-diffusion-posterior`, `diff-ddpm-step` and the other continuous/latent scheduler problems are about the coefficients inside an update formula; this one has no coefficients — purely discrete decisions (int64 and bool outputs, element-wise comparison, zero tolerance).
- The `dt-*` family (`dt-chat-template`, `dt-bytelevel-pretokenize`, ...) covers tokenisation and template assembly, which has nothing to do with "which positions commit this step".
- No other problem in the collection covers the semi-autoregressive block-parallel decoding family yet; if `check_eos_finished`/`add_noise` (362-410 and 456-518 of the same file) are ever ported, they should become their own problems rather than being folded into this one.

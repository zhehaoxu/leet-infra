# 详解：为什么 \(p=r\) 就无偏，以及 fwd/bwd 偏置各自在救什么

## 出处

随机舍入进入深度学习视野是从 Gupta、Agrawal 等人的《Training Deep Networks with Finite Precision》(2012) 开始的，此后 Graphcore IPU、Intel XPU 一类硬件把 SR 做成可选的舍入模式；「前向偏向零、反向远离零」这一对称偏置来自 OSDP（Groze 等，2023）的思路——前向的量化误差可以被激活分布吸收，而反向的梯度累加一旦系统性下偏就会让权重永远长不满。面试里能讲清「截断为什么是有偏的、SR 为什么无偏、什么情况下故意要偏」比背公式更少见也更值钱。

## 无偏性只有一行

记 \(lo\) 与 \(hi=lo+\Delta\) 是相邻两个格点、$x = lo + r\Delta$。以概率 \(p\) 取 \(hi\)、以 \(1-p\) 取 \(lo\)，则
$$\mathbb E[\text{out}]=lo+p\Delta=lo+r\Delta=x$$
所以 `sr` 的 \(p=r\) 不是"经验最优"，而是**唯一**能让期望等于真值的选择。反过来 `fwd` 的 \(p=\max(0,2r-1)\) 让 \(r\le0.5\) 恒取 \(lo\)，期望 \(lo+p\Delta\le x\)；`bwd` 的 \(p=\min(1,2r)\) 让 \(r\ge0.5\) 恒取 \(hi\)，期望 \(\ge x\)。两者都是有意引入的偏置：前者把小的激活残差整个抹掉以省动态范围，后者保证梯度累加的下偏不会吃掉小梯度。

## \(r\) 为什么可以写成 \((u32\,\&\,\texttt{0xFFFF})/65536\)

bf16 = float32 的高 16 位，因此「相邻两个 bf16 之间」正好对应高 16 位整数 +1，也就是说格点在**整数**空间是均匀的。低 16 位除以 \(2^{16}\) 就直接是「在本 ulp 内的相对位置」，不需要先取指数算 binade 步长。这一个观察同时给出 \(lo\)（截断）、\(hi\)（加一再截断）和 \(r\)，也天然覆盖次正规与负数（符号位单独占最高位，\(r\) 描述的仍是幅值方向）。

## 核心与易错点

- **判定必须是严格小于 `u < p`**：\(u\in[0,1)\) 且 \(p\) 可能恰好等于 \(u\)。用 `<=` 会让 `fwd` 在 \(p=0,\,u=0\) 时进位，破坏「小残差一律截断」的语义；测试里专门给了 \(r=0.25,u=0.25\) 与 \(r=0.75,u=0.75\) 这种 \(u=p\) 的卡边界用例。
- **\(r=0\) 必须原样返回**：已经在网格上的值（含 ±0、±inf）不能被 \(hi\) 挪走。由于 \(p=0\)、判定严格小于，这一步在 `sr`/`fwd` 下自动成立，但 `bwd` 的 \(p=2r=0\) 也成立——真正要保证的是不要把 \(\pm0\) 的符号位弄丢。
- **进位会溢出成 inf**：\(|x|\) 贴近 bf16 上限时 \(hi\) 的指数进位得到 ±inf，本题不做饱和（与 `nu-fp8-e5m2-block-scale` 恰好相反，那里尺度保证永不溢出）。
- **\(u\) 与 \(x\) 同形状、不广播**：真实 kernel 里噪声是按元素从 Philox counter 取的，广播一份噪声会让同一段元素的误差完全相关，判题因此把它列为 ValueError 而不是帮忙展开。
- **别用 `torch.uniform`**：这个版本根本没有该算子（`torch.rand` 才是），而且随机数必须由入参给出，否则判题不可复现。

## 与邻近题的区别

`nu-bf16-rounding` 在同一网格上做确定性舍入（rne/rz/rna），本题在同一网格上做概率取舍；`fw-autocast-scaler` 与 `fp16-loss-scaling` 处理的是动态尺度，不涉及舍入方向；`ag-dropout-backward` 也带随机性但那是掩码、不是数值表示。本题的独有考点是「三种偏置方向」与「位模式整数空间均匀」这一结构。

## 对拍口径与复杂度

oracle 用 Python `struct.pack/unpack` 在纯标量上重做同一套位运算，完全不碰张量视图，与参考解的 `view(torch.int32)` 路径独立，逐位比对。偏置方向用 40000 个 \([1,3)\) 上的均匀样本断言均值符号与大小关系（`rz` 比 `fwd` 更负、`sr` 偏差绝对值小于 2e-4）。复杂度 \(O(N)\)，每个元素常数次位运算。

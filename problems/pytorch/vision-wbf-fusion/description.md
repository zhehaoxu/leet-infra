# 视觉检测：WBF 加权框融合

## 题目描述

模型集成做检测时，同一个目标会被多个模型（或同一模型的多个尺度/翻转）各预测一次，得到一堆互相重叠、分数不同的框。NMS 只保留分数最高的那个，其余直接丢弃——等于把多模型的证据扔掉了。WBF（Weighted Boxes Fusion, Solovyev et al., *Weighted boxes fusion: Ensembling boxes from different object detection models*, arXiv:1910.13302）换了个思路：把「互相重叠且同类别」的框聚成一簇，再用**置信度加权平均**合成一个框，最后按「有多少模型真的投了票」缩放置信度。

本题要求实现完整的 WBF 后处理：

- 按置信度从高到低处理每个框，为它找**同类别**、与簇当前融合框 IoU 最大且超过阈值的簇并入，否则新建一簇；
- 簇的融合框是成员框的置信度加权平均（不是算术平均，也不是取最大框）；
- 簇的融合置信度是成员分数的算术平均，再乘 \( \min(n, N_{\text{models}})/N_{\text{models}} \)（\(n\) 是簇内框数）——投赞成票的模型越少，分数被压得越低；
- 输出按融合置信度降序，同分按簇的创建顺序。

三个容易踩的点：合并判据是 **IoU 严格大于**阈值；候选簇只在**同类别**里找；并簇后融合框要**立即重算**，后续框是跟新融合框比 IoU。全 CPU、确定性、不调用随机数。

## 规则

完整签名、参数含义与默认值只写在 starter 的 docstring 里，那是唯一判题口径。

- 处理顺序：全部框按 `scores` **降序**，同分按原始下标升序（稳定排序）。
- 簇只在**相同 `labels`** 之间形成；不同类别的框哪怕几何完全一致也各自成簇。
- 对当前框，遍历已有簇中同类别的那些，计算它与每个簇**当前融合框**的 IoU，取 IoU **最大**者；只有当该最大值 **严格大于** `iou_thr` 时才并入（IoU 恰好等于阈值时**不**合并）。并列时并入创建顺序最早的簇。没有合格簇则新建一簇，簇顺序即首次出现顺序。
- 并入后立刻重算该簇的融合框，因此后续框比较的是更新后的融合框。
- 融合框 \(=\) 成员框按置信度加权平均：
  \[
  \bar{x}=\frac{\sum_k s_k x_k}{\sum_k s_k},
  \]
  四个坐标各自如此；当簇内置信度之和为 0 时退化为**等权平均**（避免 0/0）。
- 融合置信度：
  \[
  \bar{s}=\left(\frac{1}{n}\sum_{k=1}^{n} s_k\right)\cdot\frac{\min(n, N_{\text{models}})}{N_{\text{models}}},
  \]
  \(N_{\text{models}}\) 即参数 `num_models`（\( \ge 1 \) 的整数）。\(n\ge N_{\text{models}}\) 时不打折，\(n<N_{\text{models}}\) 时按比例打折。
- 输出顺序：按融合置信度**降序**，同分按簇创建顺序（稳定排序）。返回的框、分数 dtype 跟随 `boxes`（float32/float64），类别恒为 int64。
- 空输入返回三个空张量（形状为 \( (0,4) \)、\( (0,) \)、\( (0,) \)）。
- 非法输入一律抛 `ValueError`：`boxes` 非 float32/float64 或形状不是 \( (N,4) \)、`scores`/`labels` 形状或 dtype 不匹配（`labels` 必须整型）、`iou_thr` 不在 \( [0,1] \)、`num_models` 不是 \( \ge1 \) 的整数。

## 示例

四个框、两个类别，`iou_thr=0.55`、`num_models=1`：

```
A = [ 0, 0,10,10]  s=0.6  label 0
B = [ 1, 0,11,10]  s=0.6  label 0
C = [20,20,30,30]  s=0.9  label 0
D = [ 0, 0,10,10]  s=0.5  label 1
```

处理 C（0.9）先建簇 0；再处理 A（0.6）、B（0.6）：A 与 C 无交集，建簇 1；B 与簇 1 的融合框（此时就是 A）的 IoU 为 \(90/110\approx0.818>0.55\)，并入簇 1，融合框变为加权平均 \((0.5,0,10.5,10)\)、分数 \(0.6\)；D（0.5）label 为 1，单独成簇 2。

```
fused_boxes  = [[20,20,30,30], [0.5,0,10.5,10], [0,0,10,10]]
fused_scores = [0.9, 0.6, 0.5]
fused_labels = [0, 0, 1]
```

把 `num_models` 改成 2：单框簇乘 \( \min(1,2)/2=0.5 \)，两框簇乘 \( \min(2,2)/2=1 \)，于是 C、A+B、D 的分数变成 \(0.45,0.6,0.25\)，输出顺序也随之改变：

```
fused_boxes  = [[0.5,0,10.5,10], [20,20,30,30], [0,0,10,10]]
fused_scores = [0.6, 0.45, 0.25]
fused_labels = [0, 0, 1]
```

## 约束

- 返回 `(fused_boxes, fused_scores, fused_labels)`：形状 \( (K,4) \)、\( (K,) \)、\( (K,) \)，前两者 dtype 与 `boxes` 一致，后者 int64。
- 判题对框与分数用绝对容差 \(10^{-6}\)（float32）/ \(10^{-12}\)（float64），对类别用 `torch.equal`。
- 合并判据（严格 \(>\)）、最佳 IoU 簇的选择、并簇后立即重算、加权平均与置信度缩放、以及两处稳定排序的口径都是判题的一部分。
- CPU、确定性、不调用随机数；空输入、单框、全零置信度都必须按上述约定返回，而不是抛错。

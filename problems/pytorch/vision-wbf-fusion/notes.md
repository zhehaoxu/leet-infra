# 详解：视觉检测：WBF 加权框融合

## 出处

- 算法出处：Solovyev, Wang, Gabruseva, *Weighted boxes fusion: Ensembling boxes from different object detection models*, Image and Vision Computing 2021，arXiv:1910.13302。论文 Algorithm 1 给出「按置信度降序处理、与簇融合框 IoU 超过阈值则并入」的聚类流程，Algorithm 2 给出坐标与置信度的更新式。
- 置信度缩放的两个备选式：论文 Eq. (4) \( C=C\cdot\frac{\min(T,N)}{N} \) 与 Eq. (5) \( C=C\cdot\frac{T}{N} \)，其中 \(T\) 是簇内框数、\(N\) 是模型数；论文指出实践中用 Eq. (4)（因为 \(T>N\) 时不该继续放大）。本题采用 Eq. (4)，即 \( \bar{s}=\bar{s}_{\text{avg}}\cdot\frac{\min(n,N_{\text{models}})}{N_{\text{models}}} \)。
- 融合坐标：论文用置信度加权平均 \( X=\frac{\sum C_iX_i}{\sum C_i} \)，本题照此实现，并约定权重和为 0 时退化为等权平均。
- 工程参考：ZFTurbo/Weighted-Boxes-Fusion 的 `ensemble_boxes_wbf.py` 是同名实现的常见版本，其流程与论文一致；本题不依赖该库，判题环境只有 torch。
- CPU、纯确定性：排序、IoU、加权平均都是四则运算，没有随机数。

## 完整推导与下标约定

**处理顺序与稳定排序**。所有框按分数降序处理，同分按原始下标升序。参考实现用 `torch.argsort(-scores, stable=True)`，稳定排序保证同分时保留输入顺序。这个顺序决定了簇的创建顺序，也决定了「并入哪个簇」的并列打破方向，因此必须显式固定。

**簇的结构**。每个簇记 `label`、成员下标列表与**当前融合框**。遍历当前框时，只在 `label` 相同的簇里找：

\[
j^\*=\arg\max_{j:\ \text{label}_j=\text{label}}\ \mathrm{IoU}(b,\ \bar{B}_j),
\qquad
\text{若 } \mathrm{IoU}(b,\bar{B}_{j^\*}) > \tau \text{ 则并入 } j^\* .
\]

论文与工程实现都是「取 IoU 最大的簇」，而不是「取第一个超过阈值的簇」——因为多个簇都可能过阈值时，应该并到最像的那个。参考实现用 `best_iou` 初始化为 \( \tau \)，只在**严格大于**当前最优时替换，于是并列自然落到创建顺序最早的簇上。判题专门构造了一个框同时以 0.4091 与 0.4762 命中两个簇的用例：只有「取最大」才会并到后者（实测融合框 \(x_1=10.1/1.3\approx7.76923\)、分数 0.65），「取第一个」会得到完全不同的结果。

**阈值是严格大于**。用两个面积为 100 与 50、交集 50 的框把 IoU 做成**恰好 0.5**：`iou_thr=0.5` 时不合并（输出 2 个簇、分数 0.9/0.8），`iou_thr=0.49` 时合并成一个簇，融合框的 \(y_2=(10\times0.9+5\times0.8)/1.7=13/1.7\approx7.647059\)、分数 \(0.85\)。用 `>=` 写的实现在第一组就挂。

**并簇后立即重算融合框**。第 3 个框比较的对象是「已更新的融合框」，不是簇里第一个框。对示例来说 A、B 的两次比较没差别（簇 1 只有一个成员时融合框就是 A 本身），但对多次并入的簇，延迟重算会让后续框按旧框比较，链式合并的边界随之漂移。

**加权平均 vs 算术平均**。融合框四个坐标分别按 \( \frac{\sum s_kx_k}{\sum s_k} \) 计算。用 \(s=0.75\) 与 \(s=0.25\) 两个框（\( [0,0,10,10] \) 与 \( [2,2,12,12] \)）可把两者区分开：加权得 \( [0.5,0.5,10.5,10.5] \)，等权得 \( [1,1,11,11] \)，反权得 \( [1.5,1.5,11.5,11.5] \)。权重全 0 时约定退化为等权平均，避免 \(0/0\)。

**置信度缩放 Eq. (4)**。\( \bar{s}=\bar{s}_{\text{avg}}\cdot\min(n,N_{\text{models}})/N_{\text{models}} \)。它的语义是「投赞成票的模型数占比」：集成 4 个模型时，只有 1 个框的簇乘 1/4，4 个框的簇不折扣；若把 \(n\) 与 \(N_{\text{models}}\) 的位置写反（\( \min(N,n)/n \)），单框簇反而不受罚、多框簇被罚，语义完全相反。示例 \(N_{\text{models}}=2\) 时单框簇 0.45、双框簇 0.60、单框 0.25，输出顺序从 \( [0.9,0.6,0.5] \) 变成 \( [0.6,0.45,0.25] \)；\(N_{\text{models}}=4\) 时三簇分数是 \(0.3,0.225,0.125\)。

**两处都要稳的排序**。输入按分数降序（同分下标升序）与输出按融合分数降序（同分创建顺序）都用稳定排序。判题里有一个「0.75 与 0.25 平均得 0.5」的双框簇与一个 0.5 的单框簇同分的用例，两个簇的顺序必须按创建顺序给出 `[0,1]`。

**浮点末位会打破「数学上的同分」**。实测一个反直觉现象：置信度 0.9 与 0.7 的平均在 float32 下是 `0.7999999761`，而单框的 0.8 是 `0.8000000119`——两者数学上都是 0.8，却相差 1 ulp，排序因此翻转，输出标签从期望的 `[0,1]` 变成 `[1,0]`。这正是我们改用 0.75/0.25（二进制精确、均值恰为 0.5）来测并列的原因；也提醒实现者：不要用「浮点相等」去断言同分。

**dtype**。融合在 float64 里累加再转回输入 dtype，减少大簇累加的舍入；框与分数的 dtype 跟随 `boxes`，类别恒为 int64。

## 核心与易错点

1. **合并判据是严格大于**：IoU 恰好等于阈值不合并。用 `>=` 会在「IoU=0.5、thr=0.5」的用例上少一个簇。
2. **候选簇只在同类别里找**：不同类别的框哪怕坐标完全一致也必须各自成簇；示例里 D 与 A 坐标相同但 label 不同。
3. **取 IoU 最大的簇，不是第一个过阈值的簇**：判题的「一框命中两簇」用例专门区分这两种实现。
4. **并簇后立即重算融合框**：延迟重算会改变链式合并的边界。
5. **加权平均不是算术平均**：权重是置信度本身；等权/反权都能被 `check_weighted_fusion` 抓出来。
6. **权重和为 0 要退化**：全零置信度时用等权平均，别让 `0/0` 产生 NaN。
7. **缩放公式的方向**：\( \min(n,N_{\text{models}})/N_{\text{models}} \)，分子是框数、分母是模型数；写反会让「证据少」的簇反而得分高。
8. **两处稳定排序**：输入顺序决定簇的创建顺序，输出顺序决定最终结果；`argsort(..., stable=True)` 是必需的。
9. **`num_models` 必须是整数**：`2.5` 要抛 `ValueError`，不能静默截断。
10. **跳过已合并的框**：被并入的框不再作为独立簇出现；实现里以「是否新建簇」分支即可，不需要额外的删除步骤。

## 与邻近题的区别

- **vs `vision-anchor-match`（同批次）**：anchor 匹配发生在**训练前**，用 IoU 阈值把 anchor 打成正/负/忽略；WBF 发生在**推理后**，用 IoU 把已打分的框聚簇融合，输出仍是框与分数。
- **vs `searchsorted-bincount` 等算子题**：那些题只做数值原语；本题是「排序 + 贪心聚类 + 加权统计」的完整后处理流程。
- **vs `vision-map-coco`（同批次）**：mAP 也做贪心 IoU 匹配，但匹配是「预测→GT」一对一的去重以统计 TP/FP，不融合坐标、不缩放置信度。
- **vs `vision-rotated-nms`（同批次）**：旋转 NMS 也是 IoU 阈值 + 贪心，但它是**抑制**（保留一个、丢弃其余），WBF 是**融合**（保留全部证据的加权平均）；而且 NMS 的 IoU 是旋转框的，本题是轴对齐框。
- **vs `vision-fcos-centerness`（同批次）**：那道题给格点打标签并算软分数，不涉及多框之间的聚类。

## 对拍口径与复杂度

- **主 oracle**：`_oracle` 用纯 Python 列表实现同一流程——`sorted(range(N), key=lambda i: (-s, i))` 排序、显式维护 `[label, members, fused_box]`、用逐项 `sum(...)` 算加权和；参考解则用张量排序、字典式簇与 float64 张量加权和。覆盖 4 组配置：24 个随机框 3 类、6 个高度重叠的抖动框、`num_models=3` 与 `num_models=2` 的缩放。
- **判别性用例**：示例的双类别 + 融合（常量实测回填）、`num_models ∈ {1,2,4}` 三档的缩放与顺序翻转、IoU 恰为 0.5 的阈值严格性、同框不同类别、加权/等权/反权三种平均、一框命中两簇取最大 IoU、同分并列按创建顺序、空输入与单框、float64、10 组非法输入。
- **实测非显然事实**：\( \mathrm{IoU}=90/110\approx0.818 \) 的两个框合并后 \(x_1=x_2\) 都只挪半个像素；`iou_thr=0.49` 时双框合并的 \(y_2=13/1.7\approx7.647059\)（不是 7.5）；float32 下 0.9 与 0.7 的均值与单框 0.8 相差 1 ulp 足以翻转输出顺序。
- **复杂度**：朴素实现 \(O(N\cdot K)\) 次 IoU（\(K\) 为簇数，最坏 \(O(N^2)\)），每次并入重算融合框额外 \(O(n)\)。判题规模 \(N\le 24\)，远低于时限。工程实现会用网格/排序索引把候选簇剪到常数个，本题不要求。

# 详解：生命周期区间上的显存复用规划

## 出处
这类「给定生命周期区间、为每个值分配地址偏移」的问题在编译领域叫 **storage allocation**（与寄存器分配的 **interval graph coloring** 同源）：同一时刻存活的值必须落在不同地址，等价于给「生命周期图」——一张区间图——着色，而区间图是完美图，**尺寸相同**时最少颜色数恰为最大团大小（某一时刻同时存活数），按左端点贪心着色即可最优。尺寸不一时问题升级为带权版本，已知是 NP-hard，工程实现退化为启发式：TensorFlow grappler 的 memory optimizer、TorchScript 静态显存池都按「大张量先放、往最低可行偏移塞」分配。本题就是把这条启发式与其**可达性下界**一起考出来。与 `perf-allocator-block-fit` 分工：那题是在线分配器（有分配/释放时序、要合并空闲块），本题是**离线静态规划**（一次性拿到全部生命周期，无时序）。

## 核心与易错点
1. **约束只来自「生命周期重叠」**：不重叠的两个张量可以完全叠在同一段地址上，这与普通 bin packing 的本质区别。判断用半开区间 `max(s1,s2) < min(e1,e2)`，相等即视为不重叠。
2. **放置顺序固定为 size 降序**（并列按 start/end/下标）：优先安放大块，避免小块把地址空间切碎。换个顺序峰值就会变，判题按这个顺序对拍。
3. **「最小可行偏移」只需试少数候选**：0，以及每个已放置且重叠张量的末端。若最小可行偏移 `o>0` 却不在候选集里，那么 `o-align` 也必然可行（能挡住它的块一定结束在 `o`），矛盾——所以候选集是完备的。
4. **下界只是下界**：`lower_bound` 取「同时存活字节和」的最大值，按大小贪心可能因为空隙塞不进后来者而超出它；测试里专门给了 `peak=4 > lb=3` 的碎片用例，别把它当成最优解验证。
5. **对齐后的大小参与排序与比较**：`nbytes` 先向上取整再排序、再判峰值，否则 100 与 1 在对齐 64 时会给出错误顺序。
6. **返回偏移按输入顺序**：内部按 size 排序处理，输出要还原成原始下标，否则整张表错位。

## 对拍口径
参考解维护已放置列表，候选偏移取「0 ∪ 已放置且重叠块的末端」，逐个试探取第一个无冲突者。判题 `_oracle` 不生成候选集，而是**跳跃式右移**：从 0 开始，撞上哪个已放置块就直接跳到它的末端（多个冲突取最远末端），首次不冲突的位置即最小可行偏移；下界改用事件扫描（同刻先结算 end 再结算 start，半开区间口径）。两套结构在 40 组随机生命周期上逐项对拍；另设断言：偏移与大小都对齐、生命周期重叠者字节不重叠、每个张量左移一格必冲突（最小性）、`peak >= lower_bound`、生命周期顺序相接的三个张量全部复用偏移 0、完全重叠时按 size 依次累加、碎片用例 `peak=4 > lb=3`、对齐取整与空输入退化。

## 复杂度
参考解 `O(N²·C)`（`N` 个张量、每次至多 `N` 个候选、每个候选与 `O(N)` 个已放置块比较）；下界计算 `O(N²)`。判题 oracle 的跳跃搜索同样是多项式级，规模小、只看正确性。

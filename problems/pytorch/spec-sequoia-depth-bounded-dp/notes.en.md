# In Depth: Sequoia Optimal Draft Tree DP with a Depth Bound

## Origin
Chen et al., *Sequoia: Faster Lossless Large Language Model Acceleration via Dynamic Speculative Decoding* (arXiv:2402.12374, reference implementation [Infini-AI-Lab/Sequoia](https://github.com/Infini-AI-Lab/Sequoia)). The three layers of this problem map onto the paper as follows:
- **Expectation accounting**: the position-dependent acceptance model of §3.2 — a node $v$ is counted with probability equal to the product of the acceptance rates along the root$\to v$ path, so one iteration generates $F(\mathcal T)=\sum_{v\in\mathcal T}f(v)$ tokens in expectation (the target's own token is included, hence $f(\text{root})=1$).
- **Depth-bounded DP**: Appendix C.2.2, which adds a depth dimension on top of Algorithm 1's $T[n,b]$.
- **Cost objective**: the speedup $=G(n,d)/(t(n)+d\,c)$ of §3.3.1 Eq. (1); here the verification cost is taken constant in the tree size ($t_{\text v}$) and the drafting cost linear in the number of nodes ($n\,t_{\text d}$), so only the size $n$ has to be enumerated.
- **Acceptance as a 2D matrix indexed by depth**: in the paper's self-speculative decoding (the same model uses its first layers as the drafter), deeper speculative positions go through more layers, so acceptance is no longer a pure function of "which child am I" and needs $A[d][b]$.

## Core: why the absolute depth must enter the state
Algorithm 1 (problem 177) gets away with the two-dimensional $T[n,b]$ because it assumes a subtree's expectation is independent of the height at which it hangs: acceptance depends only on "the index of the child within its parent", so every subtree is isomorphic and $T_{\max}[m]$ can be reused. Once acceptance becomes $A[d][b]$, **a subtree of the same size $m$ is worth a different amount at depth 1 than at depth 3** (the per-level rates along its path differ), and translation invariance is lost. Hence the state
$$T[n,b,d]=\max F\ \text{over trees of size exactly }n\text{ whose root sits at absolute depth }d,\text{ with exactly }b\text{ children and total depth}\le D.$$
The transition keeps Sequoia's "peel the last child" trick: the root's $b$-th child together with its $m$-node subtree is peeled off, while the remaining $b-1$ children are still children of the same root (hence still at depth $d$, served by $T[n-m,b-1,d]$); the peeled subtree's root is at absolute depth $d+1$, is only counted if itself accepted (multiply by $A[d][b-1]$), and all of its descendants are shifted one level deeper (served by $T_{\max}[m,d+1]$).
Two easy mistakes: **(1)** writing $T_{\max}[m,d]$ or $T[n-m,b-1,d+1]$ swaps which dimension follows the shift, and then the depth cap never binds; **(2)** setting the base only at $T[1][0][0]$ — a root-only subtree is legal at *every* depth, so $T[1,0,d]=1$ must hold for all $d$, otherwise every $n\ge2$ becomes infeasible.

## How the depth cap cuts the feasible set
A tree with out-degree $\le B$ and depth $\le D$ has at most $1+B+B^2+\dots+B^D$ nodes; larger sizes must stay $-\infty$ and must never participate in the maximization — mixing $-\infty$ with a real $0$ value destroys the objective. The probes in the test suite are $D=1,B=2,N=4$ (the best size can only be $3$) and $D=0$ (only the root survives). Conversely, with $D\ge N-1$ the cap is vacuous; and if all rows of $A$ are additionally identical, the problem collapses back to 177's $T_{\max}[N]$ — exactly the **boundary of the division of labour** between the two problems: 177 has no depth dimension, no cost, and one-dimensional acceptance; this one has all three.

## Why a cost objective is still DP-able
$F(n)/(t_{\text v}+n\,t_{\text d})$ is **not** additive in $n$, so it cannot be pushed into the DP transition. The right shape is: DP the numerator $F(n)$ for every size, then enumerate $1\le n\le N$ once more to maximize the ratio (the denominator depends on $n$ alone). This is also why the return value carries $n_{\star}$: the ratio by itself does not tell you how to spend the budget. The "smallest $n$ on ties" rule is pure disambiguation (with $t_{\text d}=0$ and all-zero $A$ every size gives the same ratio, so an order must be fixed).

## Numerics and implementation pitfalls
- $A$ is a float32 tensor; convert with `A.tolist()` and run the recurrence in Python floats. Use `float("-inf")` as the infeasibility sentinel and test it with `== NEG` rather than a threshold, and never let $-\infty$ be multiplied (with acceptance $0$ that yields `nan`).
- The judge uses relative tolerance `1e-6*max(1,|b|)`: the DP and the brute force add up the same tree in different orders, and even when they pick different trees those trees have equal objective values, so the tolerance is comfortably enough.
- Complexity $O(N^2 B D)$ time and $O(NBD)$ space — milliseconds for $N\le32,B\le8,D\le31$. The DP enumerates states "(size, first-branch count, depth)", not trees, which is precisely its advantage over brute force.

## Verification approach
The reference solution is a bottom-up three-dimensional DP. The judge's `_oracle` takes a completely different road: it **recursively enumerates** every ordered tree with out-degree $\le B$, absolute depth $\le D$ and size $\le N$ (represented as nested tuples of child subtrees), evaluates each tree with an explicit stack that multiplies $A[\text{depth}-1][\text{index}-1]$ along the root$\to$node paths to obtain $F$, and then maximizes $F/(t_{\text v}+t_{\text d}|\mathcal T|)$ over trees directly (smallest size wins ties). Neither side shares subproblems: one is DP state transitions, the other structural enumeration plus path products. Cross-checks come from closed forms and degenerate families: $B=1$ with all rows equal to $[c]$ gives $F(n)=\sum_{i\le\min(n-1,D)}c^i$ (a geometric sum), all-zero $A$, $D=0$, all-one $A$ (then the optimal size is the largest feasible one, $\min(N,\,1+B+\dots+B^D)$), and "$A$'s rows identical $+\,D\ge N-1+\,t_{\text d}=0$" must reproduce 177's $T_{\max}[N]$.

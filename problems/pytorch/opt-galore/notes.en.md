# In Depth: GaLore Low-Rank Projected-Gradient AdamW

## Source
- Jiawei Zhao, Zhenyu Zhang, Beidi Chen, Zhangyang Wang, Anima Anandkumar, Yuandong Tian, *GaLore: Memory-Efficient LLM Training by Gradient Low-Rank Projection*, arXiv:2403.03507 (ICML 2024 Oral; title, authors and venue were re-checked on the arXiv listing while authoring this problem).
- Official implementation `jiaweizzhao/GaLore`: `galore_torch/galore_projector.py` (`GaLoreProjector.project/project_back/get_orthogonal_matrix`) and `galore_torch/adamw.py` (`GaLoreAdamW`). The following upstream details come verbatim from that source and are re-checkable: the basis-recompute condition is `self.ortho_matrix is None or iter % self.update_proj_gap == 0`; the `iter` passed by `GaLoreAdamW.step` is `state["step"]` **before** it is incremented (the number of completed per-parameter updates); `project_back` finally multiplies by a `scale`; and the vendored GaLoreAdamW adds `eps` to the **uncorrected** \(\sqrt v\) with step size \(lr\sqrt{bc_2}/bc_1\) — see the convention differences below.
- Scope differences from the paper/upstream (all of them are problem-local settings; the statement and starter.py are the sole ground truth): (i) the basis \(P\) is an explicit input (the paper computes it from the gradient via randomized SVD every gap steps — all randomness removed here); (ii) this problem uses a **single-sided projection** — the gradient is first flattened row-major into \(\mathbb{R}^d\) and \(P^\top g\) is taken, whereas upstream picks a left/right one-sided projection by the matrix's long/short edge or the two-sided `proj_type='full'`; (iii) no `scale` factor; (iv) bias correction and the placement of `eps` follow `torch.optim.AdamW` (which is what makes the \(P=I\) probe comparable to native AdamW). The paper's exact default hyper-parameters for rank/scale (e.g. the commonly quoted rank=128, scale=25) were not re-verified — 待回源.

## Full derivation and index conventions
Let a parameter \(p\in\mathbb{R}^{m\times n}\), \(d=mn\), with input basis \(P\in\mathbb{R}^{d\times r}\) (columns assumed orthonormal, \(P^\top P=I_r\), though the implementation must not rely on it). The index \(t\) means **the t-th actual update of that parameter** (\(t=1,2,\dots\); `grad is None` does not advance it; counted per parameter, same convention as the Adam family — it is *not* the global step). Write \(x_t=\operatorname{vec}(g_t)\in\mathbb{R}^d\) (row-major). Projection: \(\tilde g_t=P^\top x_t\in\mathbb{R}^r\). Projected-space moments:
\[ m_t=\beta_1 m_{t-1}+(1-\beta_1)\tilde g_t,\qquad v_t=\beta_2 v_{t-1}+(1-\beta_2)\,\tilde g_t\odot\tilde g_t, \]
bias corrections \(bc_1=1-\beta_1^{t}\), \(bc_2=1-\beta_2^{t}\), adaptive direction \(\hat u_t=(m_t/bc_1)\big/\big(\sqrt{v_t}/\sqrt{bc_2}+\epsilon\big)\in\mathbb{R}^r\). Map back and apply: \(\Delta_t=P\hat u_t\in\mathbb{R}^d\) reshaped to \((m,n)\); first the decoupled decay, then \(p_t=p_{t-1}(1-lr\cdot\text{wd})-lr\,\Delta_t\). Ledger schedule: \(U_t\) ("recompute the basis at step \(t\)") holds iff \((t-1)\bmod \text{gap}=0\). This is literally equivalent to upstream: upstream tests \(s\bmod\text{gap}=0\) or a missing basis with \(s=t-1\), and at \(t=1\) the basis is necessarily missing while \(0\bmod\text{gap}=0\) is always true — so "build at the first step, refresh every gap steps" is exactly that one congruence. The essence of the low-rank assumption: empirically training-gradient spectra decay fast (near low-rank), so with \(P\) spanning the top \(r\) directions, \(\Delta=P\hat u\) carries most of the update's energy, the \(m,v\) states need only \(r\) entries, and the (randomized) SVD is done once per gap steps so its cost is amortized.

## Core points and pitfalls
1. **The moments and the bias correction all live in \(\mathbb{R}^r\)**: the classic mistake is "run \(m,v\) in full space, then project" — the mathematics differs and the state memory is back to \(O(d)\). The explicit-loop oracle and the vectorised reference solution are structurally different exactly at this point, which kills such implementations.
2. **Left/right multiplication order**: \(P^\top g\) is \([r,d]\cdot[d]=[r]\); mapping back is \(P\hat u\), \([d,r]\cdot[r]=[d]\). Writing \(P\tilde g\) fails dimensionally unless \(r=d\) — a case that the \(P=I\) probe would happily mask, which is why the main case uses a non-square \(P\).
3. **Flatten/reshape both row-major**; forgetting the reshape on the way back breaks the in-place update or triggers broadcast errors.
4. **Do not re-orthonormalize the input \(P\)**: orthonormality is an input convention, not an implementation step; running QR/SVD again is slow and destroys the bitwise invariances the \(P=I\) and sign-flip probes rely on.
5. **The ledger stays out of the numerical path**: \(P\) is fixed throughout, the "recompute" is a would-be schedule only; folding gap parity into the update formula is wrong. Ledger assertions use `torch.equal` on integer sequences, and `recompute_at(t)` is cross-checked separately as a pure boolean schedule.
6. **Skip convention**: when `grad is None`, do not advance that parameter's \(t\), do not apply wd, do not touch the ledger; the decoupled wd happens before the moment estimates and acts in full space.
7. **r=0 comes for free**: a \([d,0]\cdot[0]\) matvec yields the zero vector, so the update is pure wd — no special case needed, but an explicit-loop implementation must tolerate empty inner products.

## Relation to neighbouring problems
- **opt-adafactor (184)**: both target optimizer-state memory, but Adafactor compresses the **representation of the second moment** — \(v\) factorised into row sums × column sums (\(O(m+n)\) state) while the gradient itself is used as-is; GaLore keeps the moment update elementwise but compresses the **subspace the gradient lives in**. One compresses state shape, the other signal dimension.
- **opt-muon (185)**: both act on the spectral shape of the update matrix, yet Muon **orthogonalises** the momentum matrix via Newton-Schulz (no external basis, acting on every singular direction), whereas GaLore **restricts** the update to a given subspace — orthogonality happens on the input side (\(P\) supplied), not through an iteration.
- **opt-prodigy (195)**: D-Adaptation removes the need to tune `lr` (estimating \(d\)), orthogonal to state compression; Prodigy never touches the gradient's representation and introduces no projection.
- **opt-cautious (194) / opt-copt (265)**: that pair modulates the update **direction** (element-/tensor-level sign-consistency gating); GaLore modulates the **dimension** (subspace restriction) — the mechanisms are fully orthogonal and stackable with any Adam variant (upstream is exactly GaLore + AdamW).

# 量化：DuQuant ZigZag 通道重排——算法详解

## 1. 离群通道与逐块量化

逐块量化给每块一组共享的 scale。若某个通道的幅值远大于同块其他通道，scale 会被它撑大，同块所有通道的有效位数都被浪费。DuQuant（arXiv:2406.01721）的思路是「双重变换」：先用块内正交旋转把离群值摊开，再用通道重排把大幅值通道均匀分到不同块。本题只取其中与数据无关、完全确定性的重排。

重排不改变权重的数值，只改变列的顺序；推理时激活侧要做同样的置换，因此上游把它实现为权重与输入的联合变换。本题只输出置换本身与重排后的权重，不涉及激活侧。

## 2. 算法步骤

给定 `W`（`O×H`）与块大小 `B`（`H % B == 0`），记 `G = H / B`：

1. 键值 `key_c = max_r |W[r, c]|`；
2. 对 `(c, key_c)` 按 `key` 降序做**稳定**排序；
3. 蛇形分配：游标从桶 0 出发向下走，走到桶 `G-1` 后折返向上，走到 0 后再折返，如此往复，把有序列逐个放进当前桶；
4. 每个桶内部再按 `key` 降序稳定排序；
5. 按桶顺序拼接下标，得到 `perm`。

第 2 步的全局排序保证「幅值排名相邻的列」被分到不同桶；第 4 步的桶内排序让每个块的列从大到小排列，便于后续块内量化与打包。蛇形（而不是固定 `c mod G`）让相邻两轮的方向相反，避免同一块总是拿到同一「斜线」上的列。

## 3. 为什么用最大绝对值做键

块内量化的误差主要被最大幅值决定（scale 由它定），所以用 `max_r |W[r,c]|` 衡量一列的「破坏力」，而不是均值或范数。上游 `permutation_zigzag` 里写的就是 `weight.abs().max(dim=0).values`；对 2-D 线性层权重即逐列最大绝对值。`permutation_random` 是它的随机对照实验分支，本题不实现。

## 4. 确定性边界

- 键值相等时，Python/`torch` 的稳定排序保持原下标升序；这一条必须在实现里写死，否则相同幅值的列顺序不可判。
- `B = 1`：`G = H`，每列一个桶，结果就是全局降序稳定排序；`B = H`：只有一个桶，结果也是全局降序稳定排序。
- `H` 不能被 `B` 整除时上游会静默越界/丢列，本题直接抛 `ValueError`。
- 上游的块内旋转用随机 QR（`get_rot` 里 `torch.randn` + `torch.linalg.qr`）生成，不可复现；`Rot.pkl` 也不随仓库分发。因此本题明确排除旋转，只保留重排。

## 5. 与本合集其他题的分工

- `quant-rptq-channel-reorder-group`：按**激活跨度**升序排序后连续切分成均衡组，再做组内量化；
- 本题：按**权重大小**降序后以蛇形**交错**分配到各块，块内再排序；只输出置换，不做量化；
- Hadamard/旋转类：`quarot-hadamard-quant` 与 `quant-hadamard-transform` 已覆盖旋转族，DuQuant 的旋转部分不重复；
- 与 `quant-squeezellm-sensitive-kmeans` 等码本题无交集：本题不产生任何码本。

## 6. 验证方法

- `check_example`：手算 2×6、`B=2` 示例，核对 `perm` 与重排后的权重。
- `check_permutation_and_copy`：`perm` 必须是 `0..H-1` 的排列，`permuted` 必须等于 `W[:, perm]`。
- `check_zigzag_pattern`：排序前三名分属三个不同块、接下来三名以相反块序再各进一块。
- `check_matches_oracle`：五种形状/块大小（含 `B=1`、`B=H`）与纯 Python oracle 对齐。
- `check_ties_stable`：相等键值保持原下标升序，并验证 `B=1` 与 `B=H` 的退化行为。
- `check_block_order`：每个块内部按键值降序。
- `check_validation`：维度、形状、类型、非有限值、`block_size` 非法时抛 `ValueError`。

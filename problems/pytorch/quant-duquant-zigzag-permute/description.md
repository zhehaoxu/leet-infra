# 量化：DuQuant ZigZag 通道重排

## 题目描述

逐块（block-wise）量化时，少数幅值极大的离群通道会把它们所在块的 scale 抬高，连累同块的其他通道。DuQuant（arXiv:2406.01721）用「双重变换」缓解这个问题：块内旋转打散离群值，再用 **ZigZag 通道重排**把大幅值通道均匀撒到各个块。本题只实现其中确定性的重排这一步。

给定权重矩阵 `W`（`O` 行 `H` 列）与块大小 `B`：

1. 每列的键值取该列的最大绝对值：

\[
key_c = \max_r |W_{r,c}|
\]

2. 把全部列按 `(key, 原下标)` 从大到小**稳定**排序，得到有序列表；
3. 令 `G = H / B`，把有序列表按蛇形轮流放进 `G` 个桶：先 `0,1,...,G-1`，再 `G-1,...,0`，再 `0,1,...`，直到放完；
4. 每个桶内部再按 `(key, 原下标)` 从大到小稳定排序；
5. 按桶 `0..G-1` 拼接得到置换 `perm`，重排结果为 `W[:, perm]`。

这样排名相邻的通道会落在不同的块里，蛇形方向保证每个块拿到的幅值总和尽量均衡。

## 任务

实现 `solve(W, block_size)`：

- `W`：float32 `(O, H)`，非空且有限；
- `block_size`：`int`，满足 `1 <= B <= H` 且 `H % B == 0`；
- 返回 `dict`：
  - `perm` int64 `(H,)`：新第 `i` 列来自原第 `perm[i]` 列；
  - `permuted` float32 `(O, H)`：`W[:, perm]`。

**约定**：键值只用于排序，内部用 float64 计算；输出 float32。键值相等时按原下标升序（稳定排序）。`W` 的维度/形状/类型非法、含非有限值，或 `block_size` 不是满足上述条件的整数时抛 `ValueError`。

## 示例

```
W = [[0.5, 3.0, 1.0, 2.0, 0.25, 4.0],
     [0.1, -2.5, 0.5, -1.0, 0.1, -3.5]]
block_size = 2 -> G = 3 blocks

column keys (max |W[:, c]|) = [0.5, 3.0, 1.0, 2.0, 0.25, 4.0]
sorted desc (idx, key)      = [(5, 4.0), (1, 3.0), (3, 2.0),
                               (2, 1.0), (0, 0.5), (4, 0.25)]
zigzag bucket sequence      = 0, 1, 2, 2, 1, 0
buckets = [[5, 4], [1, 0], [3, 2]] -> perm = [5, 4, 1, 0, 3, 2]
permuted = [[4.0, 0.25, 3.0, 0.5, 2.0, 1.0],
            [-3.5, 0.1, -2.5, 0.1, -1.0, 0.5]]
```

## 约束

- 桶数由 `G = H / B` 决定，`H` 必须能被 `B` 整除；`B = 1` 时退化为全局稳定排序，`B = H` 时只有一个桶、也是块内排序。
- 蛇形分配必须严格按 `0,1,...,G-1,G-1,...,0` 的折返顺序走，不能改成固定步长或取模。
- 桶内再排序是算法的一部分：上游先按全局幅值轮流分配，再让每个块内部保持幅值降序。
- 本题**只做通道置换**：不含 DuQuant 的块内旋转（依赖随机 QR 与 `Rot.pkl`）与可学习等价变换。

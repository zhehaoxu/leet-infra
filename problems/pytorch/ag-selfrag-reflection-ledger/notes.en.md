# notes (ag-selfrag-reflection-ledger)

## Sources

- Paper arXiv **2310.11511** (Self-RAG, ICLR'24 oral), §4 inference: reflection tokens (Retrieve / IsREL / ISSUP / ISUSE) are generated by the model itself, and at inference their **probabilities** drive two things — (a) the adaptive retrieval gate and (b) multi-evidence reranking (segment-level scores). The paper speaks of probabilities, but **the code implements the gate as a raw log-prob division** — see below.
- Code: `AkariAsai/self-rag` main — `retrieval_lm/run_short_form.py::call_model_rerank_w_scores_batch` (gate + three scores + aggregation in one function), `postprocess_answer_option_conditioned`; `retrieval_lm/utils.py` for `retrieval_tokens_names` / `rel_tokens_names` / `ground_tokens_names` / `utility_tokens_names` / `control_tokens` and `postprocess`. Fetched through the GitHub blob API for original bytes (raw curl sometimes gets SIGKILLed).
- CLI defaults: `--threshold None`, `--w_rel 1.0`, `--w_sup 1.0`, `--w_use 1.0` (**the function signature says 0.5**, argparse overrides to 1.0 — this task follows the signature default 0.5 and exposes all three weights), `--use_groundness` / `--use_utility` / `--use_seqscore` all off, `--ndocs 10`, `--mode default` (**not in `choices`**, behaves like adaptive).

## Official quirks (verified one by one)

1. **The retrieval gate is inverted**: `score_dict["[Retrieval]"] / (score_dict["[Retrieval]"] + score_dict["[No Retrieval]"]) > threshold` — log-probs are negative, so dividing negatives flips the ordering. When the model wants to retrieve (`lp[Retrieval]` large, near 0) the ratio is small; when it does not, the ratio approaches 1 and the gate fires. Only the exp-ed probability ratio matches the paper. This is the headline check (`check_retrieval_gate` pins both directions).
2. **A third state in the gate**: `ret_tokens` includes `[Continue to Use Evidence]`, but the ratio only uses two tokens; that token lands in `score_dict` and never affects the decision.
3. **Dead code**: `if id not in pred_log_probs[0]: score_dict[tok] = -100` is followed by `prob = pred_log_probs[0][id]` (**no else**), so a missing key writes the fallback and then indexes anyway → KeyError; the fallback can never save it. Folded into ValueError here.
4. **The missing-token fallback is exp(-100), not 0**: `prob = ... if id in ... else -100` then `np.exp(float(prob))` → 3.72e-44 (subnormal). With both relevance tokens missing the normalized score is exactly 0.5; with all three ground tokens missing at that position it is `1/3 + 0.5·1/3 = 0.5`. Writing the fallback as 0 turns this into 0/0 (ZeroDivisionError or NaN) — which is exactly how the `m-missing-zero` mutation gets caught.
5. **ground reads only the first ground-token position** (`break`); utility does **not** break (collects all then takes `[0]`, equivalent, purely a performance artefact). Both compute only when the token appeared at all, otherwise 0.0 (not 0.5).
6. **The utility weight table carries negatives**: `[-1, -0.5, 0, 0.5, 1]` — preferring `[Utility:1]` yields a negative score, and `final` can go negative (with `w_use=1.0`).
7. **ground and utility are switchable**: `use_groundness`/`use_utility` default to False → `grd_tokens=None` → that score is 0.0 even when the token appears in the evidence.
8. **The seq score is a length-normalized exp**: `exp(cumulative_logprob / max(len(token_ids), 1))`; `use_seqscore=False` by default.
9. **`results["no_retrieval"]` has no score**: it only stores `pred`. Both aggregation paths skip it by key, so with `do_retrieve=True` the first generation's answer is discarded; and the `len(results)==1` branch returns the **second** generation (the `pred` variable is reassigned) — the stored text and the returned text differ.
10. **The two postprocessors are asymmetric**: `utils.postprocess` strips the 14 control tokens plus `</s>` and then removes **one** leading space (empty string returned as ""); `postprocess_answer_option_conditioned` strips the control tokens plus `</s>`, `\n`, `<|endoftext|>` and does **not** touch the leading space. The closed path uses the latter; the open path postprocesses nothing at all (returns the raw text).
11. **Closed aggregation accumulates by answer text**: `answer2score.setdefault(answer, 0); answer2score[answer] += score`, so identical texts are summed; `sorted(..., reverse=True)` is stable → ties keep the first-appearing answer. The open path builds `path2score` and takes `sorted(...)[0][0]`, so ties keep `retrieval_0`.
12. **`overall_scores` is dead data**: the per-evidence `relevance_score_dict` / `grd_score_dict` / `ut_score_dict` are packed into a local `overall_scores` that is **never returned** (`results` only carries pred/score/ctx), and `"ut_score_dict": utility_score` even overwrites the dict with a scalar. This task exposes those intermediate numbers as `evidence_scores` precisely so the scoring rules become checkable.

## Authoring notes

- The inverted gate was **discovered while sourcing** (paper says probabilities, code divides log-probs). Implemented from the code first, then verified: `-2.0 / (-2.1) = 0.952` and `-0.1 / (-2.1) = 0.0476`, both directions pinned in `check_retrieval_gate`.
- The first version accepted an empty token sequence (normalizing by `max(len,1)`), which promptly blew up on `lps[0]` → the official code always has a position 0, so this became a ValueError constraint (`tokens`/`lps` must be non-empty) and the `max(...,1)` guard was recorded as an equivalent mutation protected by that constraint (`m-seq-no-max`).
- Six first-round SURVIVED handled as: `RET_TOKENS[:2]` (the third token is scored but never judged → equivalent), explicit two-term relevance denominator (equivalent), `max(...,1)` (protected by the constraint → equivalent), the value of `no_retrieval`'s score (no path reads it → equivalent), plus two badly written empty mutations of mine (deleted); `check_default_flags` was added to catch the `use_utility` default.
- Exactness anchors: `exp(-100)` is a subnormal and two of them are equal → the ratio is exactly 0.5 and ground is exactly 1/3+1/6. These "missing means equal" constructs are more robust than a 1e-9 tolerance and kill the "fallback is 0" mutation.
- 34 substantive mutations all CAUGHT in the end, plus 6 equivalents (proved here): (1) the third `RET_TOKENS` entry is only ever scored (an unread key in `score_dict`); (2) the relevance denominator as an explicit two-term sum (same order, same value as `sum(dict.values())`); (3) `max(len(tokens),1)` (empty sequences are rejected by the constraint); (4) whatever `results["no_retrieval"]["score"]` holds (never read); (5) swapping the two terms of the ratio denominator (IEEE addition commutes); (6) `final`'s left-associative `(a+b)+c` versus `a+b+c` (the same syntax tree).
- Red lines: no real model forward pass, tokenizer, vLLM sampling, datasets or `acc`/`match` metrics; no retriever (Contriever/FAISS) internals or `ctxs` content; `overall_scores`' inner dicts surface only as the scalars in `evidence_scores`.

## Core Points and Pitfalls

- **The cumulative table is not a product.** Lines 100-106: ᾱ is linearly interpolated from `alpha_cum_start` to `alpha_cum_end`, then `at = att[1:] / att[:-1]` recovers the single-step values and `att` is re-assembled as `[att[1:], 1]`; γ works the same way through `1 - ctt` (130-138). So "cumulative" is only a name relative to the single-step table — the implementation is two equal-length arrays plus a sentinel, and the row-sum identity \(\bar a_t + k\bar b_t + \bar c_t = 1\) comes from the **definition** at 186-187, not from any product.
- **Only one of the three indices is `t-1`.** `V` uses `cumulative=True` with `t` (304-306 → 442-444), `U` uses `cumulative=False` with `t` (308-310 → 446-448), and `W` goes through `apply_cumulative_transitions(q, t - 1)` (336 → 506-508). The cumulative table is read twice, once at `t` and once at `t-1`; using `t-1` for `V` as well shifts the denominator \(q(x_t\mid x_0)\) by one cell and the ratio \(p(x_0)/q\) is wrong immediately.
- **"Save the mask row before dropping it" happens only on the non-cumulative call.** Lines 450-466: the value `log_onehot_x_t[:, -1, :].unsqueeze(1)` is saved only when `not cumulative`, and `[:, :-1, :]` then runs unconditionally. What the cumulative call drops is the "\(x_0\) is masked" column — `model_output` has no such channel to begin with (docstring 249-251: the initial image cannot be masked). What the non-cumulative call drops is \(q(x_t\mid x_{t-1}=\text{mask})\), which under an absorbing state is 1 on the match and 0 elsewhere, i.e. 0 and the clamp in log space. That is exactly the \(U[k]=E[k]\) of the problem statement.
- **The clamp survives all the way into the final logits.** `clamp(min=1e-30)` at 56 makes non-matching one-hot entries `-69.07755278982137` instead of `-inf`. At 479 that value is hidden under \(\log b\) via `logaddexp`, but the row saved at 461 and re-appended at 487 reaches the addition at 344 untouched: in the example, the mask row of an unmasked pixel at `t=1` is \(-68.755728=\log(10^{-30})+\log\bar c_0+\log S\).
- **Subtracting and re-adding `S` is not a numerical trick.** 317/321/328/336/344 form "divide by \(q(x_t\mid x_0)\) → normalize → multiply by \(\bar a_{t-1}\) and add \(\bar b_{t-1}\) → multiply the normalizer back in". Since `logaddexp` is not linear in its arguments, dropping the subtraction at 328 turns the class sum of \(\exp(W)\) from \(1-\bar c\) into \(S(1-\bar c)\). Upstream spends the whole comment block 346-389 (masked column 359/363, unmasked 379/383) proving each column really is a probability, which is the same fact this problem tests: per pixel `exp(logits).sum(cls) == exp(model_output).sum(cls)`, independent of \(t\).
- **`t=0` is a bypass, not a degenerate formula.** Lines 267-268 set `log_p_x_t_min_1 = model_output` directly and `q_posterior` never runs, so the `torch.rand(logits.shape)` at 74 loses a row too. Had the formula actually been run at `t=0`, `apply_cumulative_transitions(q, -1)` would read the sentinel from 106/138: \(\bar a_T=1\), \(\bar c_T=0\), \(\bar b_T=0\), whose logs are \(-\infty\) — Python's negative index does not raise, it silently makes the mask row `-inf`. That is why this problem demands `0 <= t < T` and excludes the sentinel from validation.
- **The Gumbel recipe.** Line 75 is `-log(-log(u + 1e-30) + 1e-30)`: `noise(0.0) = -4.235229826910111` and `noise(exp(-1)) = -0.0` exactly. `argmax(dim=1)` at 274 takes the lowest class index on a tie; the example sets `u=exp(-1)` so the noise is exactly zero and the bare argmax can be hand-checked, while tie ordering has its own test case.
- **Upstream never rescales by `T // N`.** Line 226 is `np.arange(0, num_inference_steps)[::-1]`, used directly as table indices (other schedulers multiply by `T // N` here). So with `set_timesteps(N)` and \(N<T\) the run uses the cleanest section of the tables. This problem takes the table length as `len(at)` and requires `t` to be a valid index, leaving no room for that discrepancy.

## Deviations from Upstream

- Upstream builds the tables itself in the constructor via 80-139 and stores them as float32 at 203-208; this problem takes ready-made probability tables `at/ct/att/ctt` and computes in float64 throughout. Cross-checked against a verbatim transcription of upstream (including the float32 downcast) over 30 configurations covering \((T,C)\in\{(7,3),(30,9),(50,2),(11,17),(100,5)\}\) with \(t\) reaching both 0 and \(T-1\): zero argmax flips, largest absolute logit difference \(6.964\times10^{-6}\).
- The `b` tables are not arguments: 185-187 fixes them as `(1-a-c)/(C-1)`, and passing them too would only create inputs that can contradict each other.
- Noise: upstream draws it at 74; this problem passes `gumbel_uniform` explicitly and requires its shape to depend on \(t\) (one row less at `t=0`).
- Return value: upstream returns only `prev_sample` (279). This problem also returns `logits` — after Gumbel noising `argmax` is insensitive to small logit perturbations, so grading the sample alone would miss the whole class of "wrong distribution, sample happens to land right".
- Validation: upstream accepts `timestep` as a `torch.Tensor` (type hint at 239), lets out-of-range indices fail naturally, and never checks that `model_output` really lacks the mask channel (249-251 is documentation only). This problem forces a Python `int` (`bool` rejected), `0<=t<T`, the four table lengths and their value ranges, all raising `ValueError`.

## Division of Labor

- `diff-discrete-ddim-routes` is also one posterior step over a discrete state space, but with the D3PM uniform-corruption kernel: no absorbing state, and a closed-form three-way split of \(q(x_s\mid x_t,x_0)\) (jump to the predicted token / stay / jump uniformly). Here the posterior sums over all \(x_0\) and relies on `logaddexp` instead of a matrix product.
- `diff-amused-topk-remask` and `diff-entropy-bound-unmask` belong to the MaskGIT family of "mask plus committing a few cells per step" and are about **how many and which** cells to keep — scheduling and confidence ordering. There the mask is chosen by the decoder; here it is applied by the forward process and the reverse step only produces one distribution, with no notion of a commit count.
- `diff-ddim` / `diff-ddpm-step` / `diff-unipc-pc-step` / `diff-consistency-decoder-2step` do Gaussian posteriors over continuous latents; here \(x\) is a class index and \(\hat x_0\) is a `(B, C-1, L)` log-probability tensor.
- `diff-repaint-blend-step` also keeps known regions away from the network output, but that is a spatial blend; here the probability of a masked cell is a mathematical consequence of the absorbing state (\(q(x_t\mid x_{t-1}=\text{mask})=\delta\)) with no explicit mixing anywhere.
- `diff-sigma-grid-construct` and `diff-edm-preconditioning` handle continuous σ grids and preconditioning; the schedule here is "linear interpolation plus consecutive ratios" from 80-139, different in both shape and purpose.

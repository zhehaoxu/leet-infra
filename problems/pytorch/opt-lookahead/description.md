# 优化器：Lookahead 快慢权重封装器（k 步前进、1 步回头）

## 题目描述

换个优化器不等于换个更新式。Zhang 等人（arXiv:1710.08983）的 **Lookahead** 在**任意** base 优化器外面套一层**快慢双权重**：base 照旧每步更新那份正在训练的**快权重** \(\theta\)，每走满 \(k\) 步就允许一份**慢权重** \(s\) 从 \(\theta\) 里按比例 \(\alpha\) 吸收一次差值，随后**把 \(\theta\) 拉回到 \(s\)** 再往前走——「k 步前进、1 步回头」。快权重负责大步探索，慢权重负责把这 \(k\) 步的净位移收敛掉，而 base 自己的动量/二阶矩**从头到尾连续累积、绝不随回滚一起被抹掉**。

本题要求你实现这个封装器：**继承 `torch.optim.Optimizer`**，在内部持有并驱动一个真正的 base 优化器（动量 SGD 或 Adam）。评测会构造若干待优化张量交给你的实例，按**固定梯度序列**反复调用 `step()`，逐步比对**训练权重轨迹**、**慢权重轨迹**，并直接探针内部 base 优化器的状态缓冲。CPU float32、全程无随机性。

## 规则

- 工厂函数接受 `params` 与 `base`、`lr`、`momentum`、`k`、`alpha`、`betas`、`eps`，返回一个 `torch.optim.Optimizer` 子类实例；`step()` **就地**更新 `params` 里的张量本身。完整签名、参数名与默认值只写在 starter 的注释里，那是唯一口径。
- `base="sgd"` 时内部建一份动量 SGD（`weight_decay=0`、`dampening=0`、`nesterov=False`）；`base="adam"` 时建一份 Adam（`weight_decay=0`、`amsgrad=False`，用 `betas`、`eps`）；其他取值抛异常。实例须暴露 `.base_optimizer`（那个内部优化器对象）与 `.slow_weights`（与 `params` 一一对应、同形状同 dtype 的慢权重张量列表）。
- 下标与顺序约定：构造时 fast 步计数 \(t=0\)、每个慢权重 \(s \leftarrow\) 对应参数的 clone。每次 `step()` **依次**做三件事：
  1. **fast 步**：让 base 走一步，\(\theta\) 就地被 base 更新。base 自身的状态（SGD 的 `momentum_buffer`、Adam 的 `exp_avg` / `exp_avg_sq` / `step`）照常累积，同步**绝不清零、重置或重建**它们；
  2. **推进计数**：\(t \leftarrow t+1\)；
  3. **到点才同步**：仅当 \(t\) 是 \(k\) 的正整数倍时，对**每个**参数按顺序执行
     \[ s \leftarrow s + \alpha\,(\theta - s),\qquad \theta \leftarrow s \]
     即**先**慢更新、**后**重置，两行不可颠倒：重置写在慢更新之后，\(\theta\) 才落在**本次同步后的**慢权重上。第一次同步因此发生在第 \(k\) 次 `step()` **之后**，而不是第 \(k+1\) 次的开头。
- 同步只由 \(t\) 对 \(k\) 取模决定，与该参数这一步有没有梯度无关：`grad` 为 `None` 的参数不会被 base 更新，但到点照样被拉回自己的慢权重。
- 全程 float32、CPU、确定性；不许调用现成的 Lookahead 实现（内部实例化 base 用的 SGD/Adam 是允许的，被封装的正是它们）。

## 示例

单参数 \(p_0=[1.0,\,-2.0,\,0.5]\)，`base="sgd"`、`lr=0.1`、`momentum=0.9`、`k=2`、`alpha=0.5`，依次喂入 4 步梯度
\(g_1=[0.40,\,-0.10,\,0.25]\)、\(g_2=[-0.20,\,0.50,\,-0.10]\)、\(g_3=[0.30,\,0.20,\,-0.35]\)、\(g_4=[-0.50,\,-0.30,\,0.15]\)。
\(\theta^-\) 是 base 走完这一步、同步**之前**的落点：

```
t=1  θ⁻=[0.960000, -1.990000, 0.475000]   不同步 → θ=[0.960000, -1.990000, 0.475000]   s=[1.000000, -2.000000, 0.500000]
t=2  θ⁻=[0.944000, -2.031000, 0.462500]   同步   → θ=[0.972000, -2.015500, 0.481250]   s=与 θ 相同
t=3  θ⁻=[0.927600, -2.072400, 0.505000]   不同步 → θ=[0.927600, -2.072400, 0.505000]   s=[0.972000, -2.015500, 0.481250]
t=4  θ⁻=[0.937640, -2.093610, 0.511375]   同步   → θ=[0.954820, -2.054555, 0.496312]   s=与 θ 相同
```

注意 \(t=3\) 的 fast 步是从 \(t=2\) 同步后的 \(\theta=[0.972,-2.0155,0.48125]\) 出发的（不是从 \([0.944,-2.031,0.4625]\)）。
4 步后内部 base 的动量缓冲仍是 `[-0.1004, 0.2121, -0.06375]`——两次回滚都没有动它。

## 约束

- \(k\) 为正整数，\(\alpha \in [0,1]\)；`params` 可混合 1D（偏置/归一化增益）与多维（权重矩阵）张量
- 每一步之后的训练权重与慢权重都要与独立重算逐元素一致（浮点用 `atol=rtol=1e-5`；「刚同步过 ⇒ \(\theta\) 与 \(s\) 逐位相同」用 `torch.equal`，口径见 notes.md）
- 四个退化口径必须成立（评测直接断言）：\(k\) 大于总步数 → 轨迹与裸 base 逐点相同；\(\alpha=1\) → 同步对 \(\theta\) 是恒等（慢权重被抬到 \(\theta\)，再写回同一个 \(\theta\)）；\(\alpha=0\) → 慢权重永不吸收，每次同步把 \(\theta\) 硬回滚到上一次同步点；\(k=1\) → 每步同步，等价于把 base 的每步增量整体缩放 \(\alpha\)

# KV Cache：层间保留名额的背包分配

## 题目描述

层间预算的「比例切分」（CAKE 那类做法）只用了每层的总质量，隐含假设是**边际收益线性**——第 \(x\) 个位置带来的收益与第 \(x+1\) 个相同。但真实曲线是**凹的**：每层最该留的那几个 token 收益极高，再往后的位置越来越可有可无。于是层间分配变成一个标准的**离散资源分配问题**：

给定第 \(l\) 层保留 \(x\) 个位置的收益 \(g_l(x)\)（\(x=0,\dots,M-1\)，题目以查表形式给出，**不保证凹性**），总名额 \(B\)，求

\[
\max_{\{x_l\}}\ \sum_{l=0}^{L_c-1} g_l(x_l)
\quad\text{s.t.}\quad \sum_l x_l\le B,\ \ 0\le x_l\le M-1
\]

这就是**多重选择背包**（multiple-choice knapsack）：每层是一组互斥选择，容量是总名额，权重都是 1。贪心（每次给「当前边际增益最大」的层加 1）只有在所有 \(g_l\) 都凹时才最优；一旦某层出现「平台」（\(g_l(x+1)=g_l(x)\)）或非凹跳变，贪心就会卡在局部最优，所以必须用 DP。

**并列准则**：收益相同时取**字典序最小**的分配向量（先比 \(x_0\)，再比 \(x_1\)……）。这条规则让结果唯一——否则大量等值解会让判题无法对拍。

## 任务

实现 `solve(gain, budget)`：

- 输入：`gain`（float32 `(Lc, M)`，`gain[l][x]` 是第 `l` 层保留 `x` 个位置的收益，\(x\in[0,M-1]\)）；`budget`（非负整数 \(B\)）。
- 输出 `(alloc, total)`：`alloc` 为 `(Lc,)` int64；`total` 为收益之和（float32）。
- 约束为 \(\sum_l x_l\le B\)（**不要求用满**：收益为 0 的位置不值得占名额）；`x_l` 上限 `M-1`。
- `budget < 0`、`gain` 为空、`gain` 含负值抛 `ValueError`。

## 示例

```
gain = [[0, 5, 8, 9],      # 层 0：边际 5, 3, 1
        [0, 4, 7, 9]]      # 层 1：边际 4, 3, 2
budget = 4

(1,3)=14  (2,2)=15  (3,1)=13  (2,1)=12  (1,2)=12  (0,3)=9 ...
最优 (2,2) → alloc = [2, 2]，total = 8 + 7 = 15
```

## 约束

- 总名额是**上限**而非定额：若所有层的下一格边际收益都是 0，允许少用名额（`sum(alloc) < B`）。
- DP 状态必须按「**恰好花费** \(b\)」建，否则「等值但更省名额」的前缀会被「等值但更费名额」的前缀覆盖，后续层就少了一个可行分支，可能错过全局最优。
- 并列比较在所有「花费 \(\le B\)」的状态间进行：收益大者胜，收益相同取字典序更小的分配。
- 收益表不保证凹性，禁止用「每次取最大边际」的贪心替代 DP。

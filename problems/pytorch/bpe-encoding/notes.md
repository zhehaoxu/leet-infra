# BPE 编码 详解

## 训练产出的是「优先级」，不只是「集合」

`bpe-training` 返回的 merges 是**有序**的，下标就是每个合并的优先级。编码时不能用集合思维「把这些对都合并掉」——顺序会影响结果，必须**每轮重新挑当前可用对里 rank 最小（最靠前）的那个**先做。理由：早先的合并会**创造**新的符号与新可合并对（如先并 `e r → er`，才出现 `er </w>`）。

正确循环：

```
while 存在命中 merges 的相邻对:
    选 rank 最小的那对 → 全词不重叠替换
```

## 与朴素「按 merges 顺序扫一遍」的区别

有人会这样写错：对 merges 里每条规则，依次扫一遍词执行它。这对**某些**词结果相同，但在「靠后的合并会重新造出靠前的可合并对」时不同——因为一轮扫完后，早先 rank 的对可能因后面的合并而重新出现。标准 BPE（及 GPT-2 `bpe` 实现）都是「每轮取全局最小 rank 可用对」，本题按此定死。

## 不重叠、从左到右

替换 `('a','a')` 于 `a a a` 得到 `aa a`（消耗两格再跳），和训练端 `_merge_pair` 完全一致。两端合并逻辑必须同一套，否则训练学的、编码用不出来。

## 边界

- `merges=[]`：直接返回 `list(word) + ['</w>']`（全字符级）。
- 未见词（不在训练语料）照样能编码——BPE 的价值：无 OOV，最差退化为字符。
- 返回保留 `</w>`（真实实现最后会去掉或映射成特殊 token id，本题保留以直观验证切分）。

## 关联

- 上游：`bpe-training`（产出这里的 merges；两题用同一批经典示例数据可互相印证）。
- 下游：`one-hot-encoding`/`embedding-lookup`（子词→ id → 向量）。

# 解题说明 · 批内 token 名额分配

## 为什么贪心就是最优

收益函数 `e_i(γ)` 关于 γ 是**凹**的：它的增量序列 `α, α², α³, ...` 单调不增（α ∈ [0,1]）。每个增量都花掉 1 个名额，于是整个问题等价于「从若干条单调不增的序列里挑 B 个最大元素」。这个挑选问题的最优解就是「每次取当前最大」——任何交换论证都成立：如果最优解里某一步没取全局最大，把它换过来不会变差。

这也解释了为什么不需要背包 DP：只有当每个增量的**代价不等**时，才需要 DP。

## 基数分配和增量分配是两件事

先把 N 个名额固定发出去（`γ_i = 0`），再分配富余部分。写成「一开始就把所有人当 0，然后循环 budget 次」会漏掉基数并导致超发；写成「循环 budget 次、每次选最大」但忘了 `γ+1` 的代价，会让最终总和等于 budget 而实际占用是 budget+N。

## 边际收益的下标是 `γ + 1`

从 `γ` 加到 `γ+1`，多出来的那一项是 `α^(γ+1)`，不是 `α^γ`。这一处 off-by-one 会让所有请求的分配整体错一位：`γ` 越大错得越明显（比如 α=0.8 时用 0.8 而不是 0.64，就会把一个本该给别人的名额继续堆在自己身上）。

## 并列的处理要显式写出来

`gain > best_gain` 用严格大于，配合从小到大扫描，天然实现「并列取最小下标」。若写成 `>=`，就会变成「并列取最大下标」，与题面契约不符，会在 α 全相等的用例上直接翻车。

## 复杂度

每分配一个名额扫一次全批：O((budget - N) × N)。用 N 个堆可以做到 O(budget log N)，但批内请求数通常只有几十，线性扫描更直观。

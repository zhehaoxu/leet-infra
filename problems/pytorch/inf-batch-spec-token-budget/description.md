# 批内推测解码的 token 名额分配

## 问题

推测解码的每一步都要跑一次 target forward。这次 forward 里能塞进多少「列」，取决于这一个 step 的 token 预算——草稿位要占，验证位也要占。批里有多个请求时，预算得在它们之间分：给某个请求多塞几位草稿，它的期望吐词涨，但边际收益是**指数衰减**的（第 k 位草稿的贡献是 α^k）；而把这一位让给另一个高接受率的请求，可能更划算。

这是一个典型的「可分凹收益 + 单位代价」分配问题：贪心按边际收益从大到小取，就是最优解。本题要求返回分配结果与期望吐词数。

## 任务

实现 `solve(alphas, budget)`：

- 输入：`alphas` `(N,)` float32，每个请求的逐位接受率（各位置同分布）；`budget` int，本步 target 侧的名额总数。
- 请求 i 分到 `γ_i` 位草稿时占用 `γ_i + 1` 个名额（草稿位 + 它自己的验证列），期望吐词 `e_i(γ) = 1 + α_i + ... + α_i^γ`。
- 求 `Σ(γ_i + 1) <= budget` 下最大化 `Σ e_i(γ_i)`：
  - 每个请求先拿基础 1 个名额（`γ_i = 0`）；
  - 剩下的名额逐个分配：每次选「再加一位草稿的边际收益」`α_i^(γ_i + 1)` 最大的请求，并列取最小下标。
- 输出：`gammas` `(N,)` int64、`expected` `(N,)` float32、`total_expected` float32 标量。
- `budget < N`、`alphas` 为空、越界或维度不对时抛 `ValueError`。

## 示例

```
alphas = [0.8, 0.5, 0.2], budget = 5, N = 3

基础分配: 每人 1 个名额 -> γ = [0, 0, 0]，剩 2 个
第 1 个富余名额: 边际收益 α^(0+1) = [0.8, 0.5, 0.2] -> 给 r0，γ = [1, 0, 0]
第 2 个富余名额: 边际收益 = [0.64, 0.5, 0.2]       -> 给 r0，γ = [2, 0, 0]

expected = [1 + 0.8 + 0.64, 1, 1] = [2.44, 1.0, 1.0]
total_expected = 4.44
```

## 约束

- **名额不能超发**：最终 `Σ(γ_i + 1)` 必须 `<= budget`，多出来的名额宁可不用（α 很小时再加一位几乎不涨，但也不该越界）。
- **基础名额不可省**：每个请求至少要有一个自己的验证列，所以 `budget < N` 是非法输入而不是「部分请求不跑」。
- **并列取小下标**：所有 α 相同时，第一个富余名额给 r0，第二个给 r1（因为 r0 的边际收益已经衰减到 α²）。
- **α = 1 时逐位收益恒为 1**：并列规则会让名额全部堆到最小下标上，这是合法的退化情形。
- **内部用 float64**：边际收益要连乘很多次，用 float32 比较会在很小的 α 上把不同的幂判成相等。

# 详解：动态稀疏训练的 drop–grow 重激活

## 出处
RigL（Evci et al., *Rigging the Lottery: Making All Tickets Winners*, ICML 2020, arXiv 1911.11134）用 ERK 稀疏分布决定每层配额，并在固定间隔内「按梯度幅值 grow、按权重幅值 drop」；SET（Mocanu et al., 2018）更早提出纯随机重连。MovERec 一类工作把动量与**重激活率 \(\varepsilon\)** 引入替换规则：每步只替换一小部分，而不是全量重排，训练更稳。本合集里的 `sparsity-cubic-schedule` 只管「稀疏度随步数怎么降」，本题只管「这一步掩码怎么变」——两者组合才是完整的 DST。

## 核心与易错点
1. **drop 与 grow 的排序键不同**：drop 看权重幅值（小的先走），grow 看梯度幅值（大的先来）。把两者都写成 |w| 或都写成 |g| 就退化成了「原地重排」，长不出新连接。
2. **候选池的时点**：重激活只能从「输入 mask 中非激活」的元素里挑。若先剪后直接在当前非激活集里挑，刚被剪掉的元素会立刻被拉回来，交换变成空转——这是本题最隐蔽的错误。
3. **激活数守恒**：交换必须成对，剪 \(r\) 个、长 \(r\) 个；同时 \(r\) 受「激活数」「候选池大小」双重上限约束，稀疏度极端时不能越界。
4. **\(\varepsilon\) 的口径**：重激活数是 \(\text{round}(\varepsilon\times\text{当前非激活数})\)，不是「总数」的倍数；`eps=0` 必须完全无重激活。
5. **并列必须确定**：\(|grad|\) 相同是常见的（尤其梯度被裁剪后），用 `u` 降序再索引升序裁决，判题才能逐位对拍。

## 对拍口径
参考解用 Python 列表完成三步（补齐 / 交换），返回排序后的索引。判题 `_oracle` 用张量化的 `argsort` 逐级稳定排序实现同一规则（`_rank` 依次按三级键做稳定排序，机制与参考解不同），逐位对拍掩码与两个索引表。额外断言：激活数恰为 \(k\)；`eps=0` 无重激活且只剪到 \(k\)；`sparsity=0/1` 分别全激活/全剪；重激活元素原本非激活、剪枝元素原本激活、两集合不相交；\(|grad|\) 并列时 \(u\) 大的优先；输出 dtype/shape 正确。

## 复杂度
\(O(N\log N)\)（每步两次排序）；显存 \(O(N)\)。

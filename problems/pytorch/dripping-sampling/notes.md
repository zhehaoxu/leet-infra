# 详解：Dripping 高概率抑制

## 出处

- 算法出处：**待回源**。"砍超高概率头部"这一族行为散见于各推理引擎/社区的实验性 sampler（与 min-p 相对偶的"反尖峰"思路），未检索到可核实的原始论文或权威实现名；判题环境离线也拿不到原文。因此**本题的算法口径完全以题面与 starter 注释为准**：有效项统计、总体 std、两种阈值模式、严格大于才砍、触发需"砍到且剩得下"。
- 机制上一半血统来自 `top-n-sigma`（本合集已收）：那道题用 \(\mu\pm n\sigma\) 的**logit 域**阈值砍尾部；本题把统计量搬到**概率域**、方向反转砍头部，并加"触发兜底"。另一半是 llama.cpp 各截断算子公共的 `min_keep` 兜底语义。
- 一句话记忆：**min-p 问"比峰值矮多少才砍"，Dripping 问"比平均高多少才砍"**。前者的参照系是最大值（尾部截断），后者的参照系是整行分布的中心趋势（头部截断）——两个方向、两套参照系，凑成对偶。

## 完整推导与下标约定

**统计量为什么只在有效项上算**：softmax 在长词表下会产生大量下溢项（\(p\sim10^{-40}\) 级）。它们参与均值/方差虽只是加小数，但会拉低 \(\bar p\)、并让 \(\sum p_i^2/n\) 的量纲被无效项稀释——统计的"本意"是描述有竞争力的候选。本题约定有效项 \(p_i>10^{-35}\)：它们本来就该被任何阈值砍掉，不配进统计。注意方向：有效项筛的是**统计口径**，`cut` 的判据仍然对**全体** \(p_i\) 生效（下溢项永远低于阈值、永远存活）。

**总体 vs 样本 std**：\(\sigma=\sqrt{\frac1n\sum p_i^2-\bar p^2}\)，分母 \(n\)。写成样本 std（\(\frac1{n-1}\)）会让阈值系统性偏大、砍得更少——单行看差 1/n 量级，正是评测 `atol=1e-5` 能分辨的量级，也与 `top-n-sigma` 的"总体 std"口径对齐。

**两种模式的几何**：`mean` 模式的阈值随分布整体抬高而抬高（\(\alpha\bar p\) 是乘性的），适合"整行都平"的场景——平坦分布 \(\bar p=1/n\)，所有 \(p_i\) 等于阈值、无人被砍（严格大于的保护）。`std` 模式的阈值 = 中心 \(+\alpha\sigma\)，σ 度量尖峰突出程度：分布越尖 σ 越大、阈值越高、砍得越狠——**自适应地砍尖峰**，这正是"滴滤"的直觉。两种模式在 `drip_amount` 单调性上一致：\(\alpha\) 越大阈值越高、cut 集合越小（评测有专项单调性断言）。

**触发的两个条件缺一不可**：① `cut.sum()>0`——平坦分布下"没有可砍的"是常态，不该视作触发；② 存活数 \(\ge\)`min_keep`——`mean` 模式小 \(\alpha\) 在尖峰分布上可能想把头部一大片全砍掉，兜底拦下。未触发时 `filtered` **逐位等于**原始 softmax（不是"砍了再补"），`cut_count=0`。

**逆变换**：与合集所有采样题共用同一约定——`filtered` 原顺序 CDF、前缀和首次 \(\ge u\) 命中、兜底取最后下标。`u` 是显式入参（标量或与批维匹配的形状），判题因此完全确定。

## 核心与易错点

1. **砍头部，不是尾部**。把 `cut = probs > thr` 手滑写成 `<` 就变成了另一道 min-p/.top-nσ 方向的题——评测的 `check_head_not_tail` 用"尖峰在 0 号、尾部连续存活"的断言专打它。
2. **严格大于**：\(p_i=\text{thr}\) 的 token 存活。平坦分布下所有 \(p_i=\bar p\)，若写成 \(\ge\) 会把整行砍到 0 存活、再被 `min_keep` 兜底"救回"——表面结果一样，但 `cut_count` 与中间态不同，且依赖兜底而不是判据本身的正确性。
3. **总体 std、有效项统计**：两处统计口径（分母 \(n\)、有效项掩码）任意一处写歪，`std` 模式的阈值就漂移，随机对拍立刻挂。
4. **未触发 ≠ 空砍**：`cut_count` 记 0 时 `filtered` 必须逐位等于原始 softmax——"砍了 0 个但重归一化"在数值上是无害的（和仍为 1），但"被 min_keep 拦下的假砍"若也重归一化，浮点上仍会与原始 softmax 差出 \(10^{-8}\) 级、可能擦线挂 `atol=1e-5`。正确写法是未触发行直接透传原概率。
5. **`min_keep` 的语义是"剩得下才砍"**：先算 cut、再验存活数，不是"砍到只剩 min_keep 为止"（那是 top-k 的语义）。
6. **`mode` 是字符串且要校验**：其他取值抛异常，不是静默回退到 `mean`。
7. **批维广播**：统计量、阈值、cut、触发、逆变换全部逐行独立；`u` 与 `cut_count` 的形状要跟批维走（标量 logits → 标量 cut_count）。
8. **float32 细节**：`10^{-35}` 的有效项界、`clamp_min(0)` 防止 \(\sum p_i^2/n-\bar p^2\) 出负（数值误差）后开方 NaN——评测的平坦用例恰好踩在方差为 0 的边界上。

## 与邻近题的区别

- **vs `min-p-sampling`**：头尾对偶。min-p 的阈值 = \(p_{\max}\cdot\alpha\)（**乘性、以峰值参照**、砍尾部），Dripping 的阈值 = \(\bar p\) 或 \(\bar p+\alpha\sigma\)（**加性/乘性、以中心趋势参照**、砍头部）。同一条分布下两者砍的集合不相交（一个在峰右侧低概率区、一个在峰本身）；分布平坦时 min-p 退化为"全保留"，Dripping 也退化为"全保留"（无人高于均值）——但平坦时 min-p 的阈值恰是峰值、判据 \(p\ge thr\) 全员存活，方向相反的对偶在退化点上仍一致。
- **vs `top-n-sigma-sampling`**：都消费 \(\mu,\sigma\)，但三个差别——域（它 logit、本题概率）、方向（它砍尾、本题砍头）、兜底（它无 min_keep、本题有）。两题对照着读刚好覆盖"统计阈值"的 2×2 象限。
- **vs `top-k-sampling`**：top-k 按名次砍头部，k 与分布形状无关；Dripping 按统计阈值砍头部，砍几个随分布自适应（尖峰砍得多、平坦砍不动）。"砍头部"这一行为相同，判据一个是序、一个是统计。
- **vs `adaptive-p-sampling` / `dynatemp-sampling`**：那些随**生成反馈**调参（跨步自适应）；本题的 \(\alpha\) 是常数、统计量来自**当前行**——单步内自适应、步间无记忆。

## 对拍口径与复杂度

- 主口径：独立重算 `_oracle`——纯 Python 循环：softmax 逐项 exp、有效项手数、均值/总体方差按定义式算、阈值两式、显式触发判断、存活重归一化用 `sum` 除、逆变换用 while 前缀和。与参考解（torch 向量化）在 25 组随机批 logits × {mean,std} × {0.2,0.5,1.0,3.0} × {1,5,9} 全网格上对拍：filtered `allclose(1e-5)`、chosen/cut_count `torch.equal`。
- 专项断言：平坦分布不触发（退火锚点）；头部清零、尾部保留（方向锚点）；`min_keep` 兜底（`cut_count=0` 且 `filtered` 等于原 softmax）；`drip_amount` 单调性。
- 复杂度：每行 \(O(V)\)（softmax、统计、cut、归一化、CDF 各一遍），无排序——比 top-k/top-p 便宜；快照式返回 `filtered` 全量 (批, V)。

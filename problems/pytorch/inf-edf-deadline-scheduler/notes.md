# 解题说明 · EDF 与等待老化

## 排序键只有三个字段

每一步的选批可以写成一个 key：

```
key(r) = (0 if wait[r] >= max_wait else 1, deadline[r], r)
```

先按「是否老化」分组（0 排前），组内按截止期，再按 id 破并列。把这三件事写成一个元组，比「先排序再两次拼接」更难写错。

## `wait` 的更新时机最容易错

`wait` 的含义是「连续被跳过的步数」，所以它只在两个地方变：

- 被选中 → 归零（即使它刚才是靠老化入选的，也要归零，否则下一步还会赖在队首）；
- 就绪但没被选中 → 加一。

**还没到达的请求不能加一**，否则 `wait` 会变成「空闲时长」而不是「等待时长」，一个晚到的请求一进来就顶着巨大的 `wait` 插队。

## 老化不是「插到队首一个」

如果只把最饿的那一个提到最前，而同一批里还有别的老化请求，它们之间的相对顺序就会退化成 EDF，可能出现「刚被提上去又被挤掉」的抖动。正确做法是把所有满足阈值的请求作为一个整体前置，组内仍按 EDF 排序。这样只要 `max_batch >= 1`，每个老化请求在被提上来之后最多再等 `老化组大小 / max_batch` 步。

## `missed` 与「没跑完」是同一件事

`finish == -1` 表示 `max_steps` 用尽时还没跑完，本质上就是一次超期，必须计入 `missed`。若只比较 `finish > deadline`，`-1` 会被漏掉（-1 不大于任何非负 deadline），统计结果会偏乐观。

## 一个可以自检的性质

把 `max_wait` 设得比 `max_steps` 还大时，`promotions` 必须恒为 0，输出应与纯 EDF 完全一致。这是判断「老化逻辑有没有误伤正常路径」最省事的探针。

## 复杂度

每步一次排序 O(N log N)，总计 O(max_steps × N log N)。真机上 N 是百级、步数是万级，所以 EDF 本身要求 `max_batch` 之外的常数尽量小，通常用堆或时间轮代替重排。

# 详解：为什么 \(E[x^2]-E[x]^2\) 会在大偏置下给出恰好 0

## 出处

Welford 在 1962 年的内部报告里给出了这个逐元素更新，Knuth 在《The Art of Computer Programming》第二卷里把「攒 sum 与 sum of squares」的做法称作 *the textbook algorithm* 并分析了它的抵消问题，逐步更新的解法则归给 Welford。NumPy 的 `np.var` 走两遍法，而 TensorFlow 的 `tf.nn.moments`、各类流式监控的 summary 实现的都是 Welford 或其并行合并版。面试出现的位置有三类：写 fused BatchNorm 的统计量 kernel、解释「为什么 \(10^9\) 偏置下方差算成 0」、以及把两个 worker 的 \((n,\bar x, M_2)\) 合并（Chan-Golub-LeVeque 那一步）。本题只做逐元素那一半，合并版是它的自然延伸。

## 三累量更新在算什么

设处理完前 \(k\) 个元素后 \(\bar x_k\) 是均值、\(M_{2,k}=\sum_{i\le k}(x_i-\bar x_k)^2\)。加入 \(x_{k+1}\) 时
$$\bar x_{k+1}=\bar x_k+\frac{d}{k+1},\qquad d=x_{k+1}-\bar x_k$$
而二阶中心矩的增量可以写成
$$M_{2,k+1}=M_{2,k}+d\cdot\big(x_{k+1}-\bar x_{k+1}\big)$$
也就是「离开旧均值的距离」乘上「离开新均值的距离」——这就是代码里 `M2 += d * (v - mean)` 必须在 `mean += d / n` **之后**的原因：同一行里用的两个差分别相对新旧均值。几何上看，\(d\,(x_{k+1}-\bar x_{k+1})\) 恒非负，所以 \(M_2\) 单调不减，不会因为减法抵消而变成小的负数（这一点求和式做不到，它偶尔会给出 \(-10^{-8}\) 这种"负方差"）。

## 求和式为什么会恰好归零

对 \(x_k=10^9+k\)（\(k=1..4\)）：\(\sum x_k^2 = 4\times10^{18}+2\times10^{10}+30\)，而 ulp\((4\times10^{18})=2^{62-52}=1024\)，那个 \(+30\) 根本不存在；\((\sum x)^2/4 = 4\times10^{18}+2\times10^{10}+25\) 舍入后与上式**落到同一个 double**。两者相减得 0，方差于是恰好 0.0——不是"精度差一点"，而是信息被完全抹掉。相对误差 \(10^{18}/1 \) 意味着需要 60 位有效十进制数字才能救回来，double 只有 16 位。

## 核心与易错点

- **`M2 += d * d`**：\(d\) 是相对旧均值的差，直接平方会**高估**，示例数据 \([1,2,3,4]\) 上给出 2.75 而不是 \(5/3\)。
- **顺序颠倒**：把 `mean += d / n` 提到前面，两个差都相对新均值，会**低估**，同一组数据给 1.1666666666666667。两个方向都跟真值差得看得见，示例就能卡住。
- **逐元素而不是逐块**：把块内先求和再当作一个元素更新是错的；块合并要用 Chan-Golub-LeVeque 的 \(\delta^2 mn/(m+n)\) 形式，本题没要求。
- **\(n=1\) 的两种口径**：无偏方差分母是 0，规定返回 NaN；有偏口径返回 0.0。测试对两者分别断言，不能都用 0 或都用 NaN。
- **float32 陷阱**：`torch.tensor([1e9+1])` 默认就是 float32，\(10^9+1..4\) 会被压成同一个 1e9，方差真值都变成 0。判题数据必须显式 `dtype=torch.float64`，选手也必须先升精度再累加。
- **非有限值**：inf 参与 \(d/n\) 会让 mean 变成 inf 或 NaN，规定「只要出现过非有限值就整体返回 (nan, nan)」，不去区分符号。

## 与邻近题的区别

`nu-kahan-compensated-sum` 处理的是「一串给定数字怎么加准」，本题处理的是「加了之后还要不要留二阶量」；`batchnorm-forward` 里 running stats 是按 momentum 做指数滑动合并（\(\bar x_{new}=(1-m)\bar x_{old}+m\,\bar x_{batch}\)），既不是单遍也不是精确合并；`ag-batchnorm-backward` 考的是方差在反向图里被计入两次。本题的独有考点是「求和式恰好给出 0.0」这一可手算的失败模式。

## 对拍口径与复杂度

oracle 用两遍法：`math.fsum` 求均值，再累加 \((x-\bar x)^2\)，与 Welford 的递推路径完全不同；良态随机数据在 \(n=2/33/101/1000\) 上要求 1e-9 相对误差，偏置 \(10^9\) 的用例则额外断言求和式偏离真值超过 1e-3。\(n=1000\) 个连续整数的无偏方差按 \(n(n+1)/12 = 83416.66666666667\) 手算校验。时间 \(O(N)\) 单遍、状态 \(O(1)\)。

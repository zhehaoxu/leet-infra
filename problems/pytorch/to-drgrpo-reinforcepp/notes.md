# 解题说明 · Dr. GRPO 与 REINFORCE++

## 两个偏置从哪来

GRPO 的原始目标里，每条回答的贡献先除 $|o_i|$（长度归一化），优势先除组内 std（难度归一化）。Dr. GRPO 的论文指出这两步都会让「回答长度」和「题目难度」混进梯度：

- **长度偏置**：除 $|o_i|$ 让长回答的每个 token 权重更小，等价于把 token 级目标改成了「按回答等权」，模型没有理由把回答写长或写短，优化方向被扭曲；
- **难度偏置**：除 std 让低方差组（几乎全对或全错）的优势被放大，而这些组恰恰信息量最少。

Dr. GRPO 于是把两处都改成**常数**：优势只减组均值，损失除以 $B\cdot G\cdot T$。注意 $T$ 是张量宽度而非有效长度——于是 padding 也进了分母，批量里 padding 越多损失被稀释得越厉害。这不是 bug，而是「对所有位置一视同仁」的直接后果；本题用「追加一列全 mask 后损失缩到 3/4」把这个性质钉死。

## REINFORCE++ 的白化范围

REINFORCE++ 不逐组标准化，而是在**整个 batch** 上做一次白化：$\mu,\sigma$ 来自全部 $B\cdot G$ 个奖励。这样同一 batch 内所有回答共享一个尺度，组与组之间的相对难度被保留（不像 GRPO 把每组都拉成单位方差）。它的损失仍是「每条回答按自身长度平均，再对回答平均」，所以额外 padding 列不影响结果——与 Dr. GRPO 形成干净对照。

$\sigma$ 的实现要注意：常数奖励张量的 `std(unbiased=False)` 在浮点下不保证恰为 0，契约因此用 $\sigma\le10^{-12}$ 判定并在该情形整批返回 0，避免 $0/0$ 把 NaN 带进损失。

## surrogate 的裁剪语义

两者共用 $\min(\rho A,\ \bar\rho A)$。由于 $A$ 可正可负，这个 `min` 并不总是选被裁剪的值：$A>0$ 时它把过大的 $\rho$ 压到上界（保守），$A<0$ 时它反而保留更负的未裁剪项（PPO 的自动单向裁剪）。测试里专门构造 $\rho=e^{0.3}$、$\epsilon=0.01$ 的负优势样本，验证实现没有写成「对称地取裁剪值」。

## 为什么把两题合并成一道

分开看，两道题都只是几行归一化代码；放在一起，输入完全相同、只差归一化口径，输出却成比例或不成比例地变化，才能让人真正看清「中心化/白化在哪一层做、分母是长度还是常数」这两个选择如何决定梯度的尺度。

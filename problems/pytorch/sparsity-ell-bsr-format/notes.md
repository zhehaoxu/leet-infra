# 详解：ELL / BSR 格式转换与存储账

## 出处
ELL 是稀疏 BLAS（cuSPARSE 的 `csrmm`/`hyb` 家族、cuBLAS 的 ELL 路径）为「行等长、可规整并行」设计的经典格式；BSR 是 `scipy.sparse.bsr_matrix`、`torch.sparse_bsr_tensor`、cuSPARSE `bsrmm` 的通用块格式，也是分块 GEMM 与 Tensor Core 稀疏加速的落点。本题把它们与 CSR 放在一起对照，重点是「存储字节数」这本账：同一矩阵在三种布局下的空间代价由 nnz、最长行 \(M\)、非零块数 \(NB\) 直接决定。与合集里 `sparsity-csr-encode`（只做 CSR 编码）互补——那题解决「怎么压」，本题解决「压完长什么样、值不值得」。

## 核心与易错点
1. **ELL 的 \(M\) 是全局的**：取所有行的最大非零数，不是每行各自长度；因此短行要补到 \(M\)。全零矩阵 \(M=0\)，两个数组形状是 \((R,0)\) 而不是 \((R,1)\)。
2. **补齐位索引必须是 −1**：值补 0 可以与真实的 0 混淆（虽然稀疏矩阵里真实非零不会是 0），但列号 0 是合法值，必须用 −1 标记空槽，解码器才能区分。
3. **行内按列升序**：`nonzero`/`argsort((~nz))` 的稳定排序天然给出升序，且把非零排到前面，取前 \(M\) 个即可。
4. **BSR 的判据是块内「任一非零」，但存的是整块**：部分非零的块不能只存非零元素，块内零要原样带上，否则块内行主序展平会错位。
5. **`bsr_indptr` 是块行指针**：长度 \(R/b_r+1\)、每格增加的是该块行的非零块数；写成元素级 `indptr` 或漏掉末尾格子都会错。
6. **块内展平顺序是行主序**：`reshape(nr, br, nc, bc).permute(0,2,1,3).reshape(nr, nc, br*bc)` 是标准写法；直接 `reshape(nr,br,nc,bc)` 会得到列主序的块。
7. **字节账要按各格式自己的索引粒度算**：CSR 的 nnz 是元素数、ELL 的存储量是 \(R\cdot M\)（含补齐）、BSR 的存储量是 \(NB\cdot b_r b_c\)（含块内零）。三者分母不同，不能混用。
8. **`block=(1,1)` 是退化校验点**：此时 \(NB=\) nnz、块内只有一个元素，BSR 应等价于行主序 COO。

## 对拍口径
参考解用 `~nz` 稳定 `argsort` 取每行非零列号做 ELL，用 `reshape+permute+reshape` 展平块、`any(dim=2)` 判非零块、`cumsum` 建 `indptr`，字节数按上面三条公式直接算。判题 `_oracle` 用纯 Python 双层循环逐行、逐块扫描 `!= 0.0` 手工拼接六个返回值，逐项对拍。另设断言：ELL/BSR 各自带独立解码器还原稠密矩阵必须逐位相等；补齐行形状为 \((3,3)\) 且索引恰为 `[[0,-1,-1],[-1,-1,-1],[0,1,2]]`；全零矩阵退化（\(M=0\)、\(NB=0\)、`indptr=[0,0,0]`、CSR 只剩指针的 40 字节）；全稠密矩阵无补齐位（每行都满、`ei>=0`）；`block=(1,1)` 时 `bsr_indices/indptr` 与行主序一致。

## 复杂度
\(O(RC)\) 扫描；ELL 输出 \(R\cdot M\) 个值与索引，BSR 输出 \(NB\cdot b_r b_c\) 个值，字节账 \(O(1)\)。

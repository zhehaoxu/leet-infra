# 解题说明 · Matryoshka 嵌入截断

## 回源与口径

MRL 论文（arXiv:2205.13147）的核心是训练侧的多尺度损失（同一嵌入的各前缀各自过
InfoNCE）；推理侧的用法（`matryoshka-adapters`、OpenAI text-embedding-3 的 dimensions
参数）统一是「**截前 d 维 → 重新 L2 归一化 → 余弦相似度**」。本题判的就是这条推理账，
不碰训练。

两个必须钉死的口径：

- **重新归一化**：截断后向量模长不再是 1，直接点积会混入幅值信息，得到与余弦完全不同
  的排名。变异 `no-trunc-renorm` / `dot-no-norm` 都是为了钉死这条。
- **零向量**：截断后某行可能全 0（该档下与 query 无关），归一化除零。钉死
  `norm = max(‖v‖₂, 1e-12)`——与 `F.normalize` 的 eps 语义一致，零向量相似度记 0，
  并列参与排序。

## 账本设计的取舍

- `overlap_full` 用**集合**交集而不是逐位对齐（`top_d[i] == top_full[i]` 的位置重合数）：
  MRL 关心的是「粗排能不能召回精排的候选」（recall@k 语义），位置微动不算失真。变异
  `overlap-order` 检验实现者是否真的理解这一点。
- `truncated` 用 dict 以 `d` 为键：`dims` 顺序与账本内容解耦（`dims` 允许乱序重复），
  避免把「处理顺序」当可观察行为。
- `top` 排序键 `(-sim, index)` 与全库 top-k 题一致：并列取小 index。

## 手算锚点的两个坑

1. **一维截断只剩符号**：`normalize([x])` 的幅值信息全部消失，相似度只能是 ±1 或 0
   （零向量）。anchor 里 d=1 档的 top 是并列取小的 `[0, 1, 3]` 而不是幅值序——第一版
   手算按幅值排就错了。
2. **cos 手算别背角度表**：`doc1=[1,2]` 与 `q=[1,1]` 的 cos 是 `(1+2)/(√2·√5)=3/√10≈0.949`，
   「cos(18°)≈0.951」的记忆值混入 1 ulp 之外还差一点（两角其实不同：18.43°）。锚点断言
   一律写解析式不写十进制近似。

## 测试与变异

- oracle 纯 Python 手写（math + list），30 组随机对拍（float64 逐元素算 cos，与 torch
  双精度路径一致，容差 1e-6）。
- 排名保持谱用例：嵌入设计成「前 2 维为主成分 + 后 2 维微量噪声」，断言 d=2 档 top 与
  full top 完全一致——这就是 MRL 要买的性质。
- 变异 8 条全抓：截断不重归一化 / query 不归一化 / 取后 d 维 / 全档不归一化（点积）/
  排序升序 / 并列取大 / overlap 改逐位重合 / top_k 越界静默 clamp。

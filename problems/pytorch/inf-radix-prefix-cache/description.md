# Radix-tree 前缀缓存：最长前缀命中与 LRU 驱逐

## 题目描述

多轮对话、few-shot 提示、agent 的固定系统提示会让大量请求共享同一段 prompt 前缀。把这段前缀的 KV 缓存下来，下一个请求就能跳过对应的 prefill —— 这就是 prefix caching。工业实现（SGLang RadixAttention、vLLM 的 automatic prefix caching）用一棵 **按 token 边压缩的字典树** 来组织缓存：每个节点持有一段连续 token 的 KV，节点不单独占空间，缓存总量就是所有边长度之和。

本题要求实现这棵树的核心操作：请求到达时走最长公共前缀、命中不了的尾部写进树里、请求结束后 KV 继续留着给后人用，并且在总量超过容量时按 LRU 把「没人用」的叶子边整条摘掉。

## 规则

`ops` 是按时间顺序排列的操作列表，时间戳等于下标。每个操作是下面两种之一：

- `("request", rid, tokens)`：请求 `rid` 带着 prompt `tokens`（整数 token 序列，长度 `>= 1`）到达；
- `("finish", rid)`：请求 `rid` 结束，释放它对缓存的占用。

**request 的处理**：

1. 从根开始沿与 `tokens` 的最长公共前缀下行。若某条边只匹配了它的前半段，就在匹配处把这条边劈成两段：劈出来的新节点持有匹配部分，原节点保留剩余部分并挂到新节点下。若走完 `tokens` 时仍停在某条边的中间，同样照劈。
2. 下行经过的每个节点（含劈出的新节点）都把「最近使用时刻」刷新为当前时刻。
3. 命中的 token 数记为 `hit`。若 `tokens` 还有剩余，剩余整段作为一条新边挂到匹配终点下（新节点的最近使用时刻也是当前时刻）；没有剩余就不新建节点。
4. 该请求进入**活跃集**，占用整条 `tokens` 路径上的 KV，直到被 `finish`。

**finish 的处理**：请求离开活跃集。它的 KV 继续留在缓存里供后来的请求复用；它此前钉住的节点从这一步起变成可驱逐的。`finish` 本身不刷新最近使用时刻。

**容量约束**：每个操作处理完后，只要缓存 token 总数大于 `capacity`，就反复驱逐：

- 候选 = 「是叶子节点」且「没有任何活跃请求的 prompt 以它的路径为前缀」的节点；
- 取其中 `(最近使用时刻, 节点编号)` 字典序最小的一个，把它的整条边连同节点一起删除；
- 若新的叶子因此空出来，下一轮重新计算候选。

找不到候选就停手 —— 活跃请求占满时，缓存允许暂时超过 `capacity`。

**节点编号**：根为 0，其余节点按创建先后从 1 开始递增（劈分产生的新节点也算一次创建）。

返回三元组：

- `hits`：按 `request` 出现顺序，每个请求命中的 token 数；
- `evicted_tokens`：全程被驱逐的 token 总数；
- `cached_tokens`：全部操作结束后缓存里剩余的 token 数。

## 示例

**示例 1**（最长前缀 + 边中途劈分）：`capacity = 32`

```
时刻 0  request 0 [10,11,12,13]   空缓存，命中 0，挂一条边 (10,11,12,13)
时刻 1  finish 0                  KV 留在缓存里
时刻 2  request 1 [10,11,99]      命中 2；边 (10,11,12,13) 在 2 处劈成 (10,11) 和 (12,13)
                                  剩余 (99) 挂到 (10,11) 下
时刻 3  finish 1
时刻 4  request 2 [10,11,12]      命中 3
时刻 5  finish 2
时刻 6  request 3 [10]            命中 1
时刻 7  finish 3
```

```
hits           = [0, 2, 3, 1]
evicted_tokens = 0
cached_tokens  = 5          # (10,11) + (12,13) + (99)
```

**示例 2**（LRU 淘汰最久没用的叶子）：`capacity = 6`

```
时刻 0  request 0 [1,2,3]     缓存 3
时刻 1  finish 0
时刻 2  request 1 [4,5,6]     缓存 6
时刻 3  finish 1
时刻 4  request 2 [7,8,9]     缓存 9 > 6；叶子 (1,2,3) 时刻 0、(4,5,6) 时刻 2、
                              (7,8,9) 时刻 4 但被活跃请求钉住 -> 驱逐 (1,2,3)
时刻 5  finish 2              缓存 6
时刻 6  request 3 [4,5,6]     命中 3
时刻 7  finish 3
```

```
hits           = [0, 0, 0, 3]
evicted_tokens = 3
cached_tokens  = 6
```

**示例 3**（活跃请求把缓存撑过容量）：`capacity = 4`

```
时刻 0  request 0 [1,2,3,4]   缓存 4
时刻 1  request 1 [5,6]       缓存 6 > 4，但两条叶子都被活跃请求钉住 -> 一个都不驱逐
时刻 2  finish 0              (1,2,3,4) 变为可驱逐，整条边摘掉，缓存 2
```

```
hits           = [0, 0]
evicted_tokens = 4
cached_tokens  = 2
```

## 约束

- `capacity >= 1`；`ops` 非空，其中 `request` 的数目不超过 64；prompt 长度 `>= 1`。
- `rid` 是整数，每个 `rid` 只 `request` 一次、`finish` 至多一次，且 `finish` 只针对仍在活跃的请求。
- token 是任意整数，只有相等关系有意义。
- 返回的 `hits` 是 Python `int` 列表，另两个是 Python `int`；判题只看数值，不限定实现方式（带父指针的节点树、路径集合、递归写法都可以）。

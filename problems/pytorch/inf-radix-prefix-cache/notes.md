# 解题说明 · Radix-tree 前缀缓存

## 出处

- SGLang: *Efficient Execution of Structured Language Model Programs*（arXiv:2312.07104，NeurIPS 2024）——提出 RadixAttention：用 token 级压缩前缀树管理 KV，节点带引用计数，未命中时劈分边，显存不足时按 LRU 逐出叶子。
- vLLM 的 automatic prefix caching 用块哈希做同样的事（对齐到 block 粒度）；本题刻意取 token 粒度，和 `inf-prefix-cache-block-hit` 的块命中口径区分开。
- 边压缩（radix tree / Patricia trie）本身是经典结构：把只有单个孩子的链合并成一条边，使节点数只与「分叉点 + 请求结尾」成正比。

## 核心与易错点

**命中的是 token 数，不是节点数。** 请求可以只匹配一条边的前半段（示例 1 的 `[10,11,99]` 命中 2），此时必须把边劈开、在匹配处新建节点，否则后续 `[10,11,12]` 会错误地整体命中或整体落空。

**劈分是新增一个节点，不是缩短父节点。** 原节点保留未匹配的尾部并挂到新中间节点下；缓存总量不变（劈前劈后 token 总数相同），只是切点更细。

**活跃请求钉住整条路径。** 驱逐候选必须排除「活跃请求 prompt 以它路径为前缀」的叶子。示例 3 中 `capacity = 4` 却留下 6 个 token：两条叶子都被活跃请求用着，驱逐只能停手。这里用「活跃集 + 前缀判断」表达引用计数，比在劈分时搬运计数器更不容易错。

**finish 不刷新最近使用时刻。** 结束只是解除占用；若要刷新，示例 2 的 LRU 顺序会被打乱。相反，命中（下行经过的每个节点）一定要刷新 —— 否则「刚被复用过的前缀」会被当成冷数据先丢掉。

**驱逐只摘叶子，且整条边一起走。** 摘掉叶子后父节点可能变成新叶子，同一轮里要重新计算候选；公共前缀（例如 `[1,2]` 在子边 `[3,4]` 被驱逐后）因此能活下来，后来的请求仍命中这 2 个 token。

**并列时按节点编号。** 同一时刻被创建/访问的多个叶子，用创建顺序（编号小者优先）打破平手，保证结果唯一。

**账本闭合。** `cached_tokens` 恒等于「Σ prompt 长度 − Σ hit − evicted_tokens」；这是对拍时最强的交叉校验，任何漏记的插入或驱逐都会立刻暴露。

## 对拍口径

- 参考实现：带父指针的节点树（节点存 `edge/path/children/parent/last/id`），增量维护 `cached` 与 `evicted`，驱逐用一次 DFS 收集候选后删最小者。
- 独立 oracle：**不建树**，只维护一张「完整 token 路径 → (最近使用时刻, 编号)」的扁平表，父子关系由「最长真前缀」隐式恢复，叶子即「不是任何其他路径的前缀」，驱逐就是删表项并回收 `len(path) − len(parent(path))` 个 token。两种表示不共享任何数据结构。
- 3000 组随机操作流（token 取值 0–3、prompt 长 1–6、容量 1–12、随机 finish 时机）上两边三元组逐位一致；另有 7 个手算场景（劈分、LRU、命中刷新、钉住超限、父路径存活、无公共前缀、未 finish 钉住）与随机不变量断言 `cached == 插入 − 驱逐`。

## 复杂度

- 单个 request：下行最多走 `O(L)` 个 token（`L` 为 prompt 长度），插入 `O(L)`。
- 每次驱逐：一次 DFS 扫全部节点，`O(节点数)`；由于每次至少删一个节点，单次操作的总开销 `O(节点数 × 被删节点数)`。
- 整体上界 `O(Σ L_i × N)`（`N` 为节点数，`N ≤ Σ L_i ≤ 64×16 = 1024`），毫秒级；真实引擎里这部分用哈希表 + 侵入式链表做到每步均摊 `O(L)`。

## 相关题目

- `inf-prefix-cache-block-hit`：块哈希口径的前缀命中，只看整块是否命中，不涉及树结构与驱逐。
- `inf-lru-kv-cache-eviction`：块粒度的 LRU 驱逐，本题是 token 粒度且要求树形复用。
- `inf-paged-kv-block-alloc`：物理块分配与页表映射，属于同一套缓存缺口的另一侧账本。

## Normalization (judge domain vs official)

- **Noise made explicit**: the official `BrownianTreeNoiseSampler(model_output, σmin, σmax, seed)` depends on generator/seed and tensor shape — pipeline-side; it becomes an explicit `noise` argument, required on every call (the official updates `assert noise is not None`).
- **State externalized**: the official `self.model_outputs / self.lower_order_nums` move into a `state` dict. `step_index` is self-incremented officially (`_init_step_index`/`index_for_timestep`); here it is an explicit argument — the `timesteps` (atan transform) and `index_for_timestep` lookup stay out of the judge domain.
- **Config made explicit**: `solver_order / solver_type / lower_order_final / euler_at_final / final_sigmas_type / sigma_data / prediction_type` are all arguments with defaults = the official config defaults.
- **Table construction not inlined**: `sigmas` is passed as-is (exponential/karras generation plus the `sigma_last` append are the caller's job), λ computed pointwise.
- **solver_order whitelist**: the official code has no validation (=3 leaves `prev_sample` unbound → UnboundLocalError); this problem restricts it to {1, 2}.
- **Merging the always-true official elif**: `elif solver_order == 2 or lower_order_nums < 2 or lower_order_second` is always true under the {1, 2} validation (`lower_order_second` is dead code); the implementation merges it into an else, documented in the docstring.
- **h=0 / h_0=0 guard**: with adjacent sigmas equal the official code divides 0/0 (torch yields nan/inf garbage); this problem raises `ValueError` — a judge-domain boundary, since in official schedules adjacent equality only occurs at a sigma_min tail.
- **float64 semantics preserved**: σ = 0 gives λ = +∞ (`math.exp(−inf) = 0`, matching torch), and the first-order coefficients {0, 1, 0} are kept verbatim.

## Key observations

1. **λ appears only through the difference h** → any fixed scaling of α cancels by translation (`_sigma_to_alpha_sigma_t` returning `σ·0.5` leaves h bit-identical; see the equivalence table). The identity dividend here: **e^{−h} = σ_t/σ_s0**, so the first-order sample coefficient = (σ_t/σ_s0)² and decay = 1 − (σ_t/σ_s0)², and the example can be fully rationalized (σ = 3 and 1).
2. **EDM preconditioning lives in convert**: both c_skip and c_out depend on `sigma_data`, and v_prediction's c_out is **negative** (sign convention of v = x0 − σ·ε) — testing only σd=1 misses the epsilon branch's d-dependence (why mutation `m-cout-eps` SURVIVED on the first pass).
3. **The three lower-order clauses are OR-ed**: `euler_at_final` / (`lower_order_final` and N<15) / `final_sigmas_type == "zero"` — any one forces the final step (and only it) to first order. For N ≥ 15 only euler or zero can; each branch gets its own mutation, each needing a different config to catch (heun + sigma_min tail makes the wrong second order blow up observably at h=0).
4. **The official code never lets second order touch σ_t = 0**: a zero tail makes the final-step flag unconditionally true; breaking that sends the second-order path to h = +∞ → r0 = 0 → division by zero in D1 — how `m-lof-zero` is caught.
5. **The zero-tail final step is an identity step**: prev ≡ x0 (coefficients {0,1,0}); a sigma_min tail with lowering gives prev ≡ sample (h=0, coefficients {1,0,0}) — both identity steps pinned by independent assertions.
6. **Mid-schedule cold start is legal**: `state=None` at any `step_index` (the official `begin_index` scenario): first call is first-order, the None head of the history is shifted out, and the second call's m1 is exactly the first call's x0.
7. **State invariant**: the first solver_order−lo entries are None, the last lo entries are real tensors; `1 ≤ lo ≤ min(solver_order, step_index)` — lo ≥ 1 implies "state means at least one prior call", so passing state at step 0 is rejected by the lo range check without a dedicated check (adding a redundant explicit check would create an equivalent mutation).

## Dedup check

- **`diff-dpm-solver-order-schedule`**: same DPMSolverMultistep family's order scheduling. But that one uses the αβ discrete convention (ᾱ table + eps/x0 conversion formulas), no SDE noise term, no EDM preconditioner, σ table derived from ᾱ; this problem uses the EDM/VE convention (α≡1, pure sigma-space exponential/karras table with a 0/sigma_min tail) + Brownian-tree SDE noise + the c_skip/c_out preconditioner + the three-clause lowering flag (adding `euler_at_final` and `final_sigmas_type` branches).
- **`diff-sasolver-adams-pc-step` (756)**: also stochastic multistep. But SA-Solver is a dual sAB/sAM structure (corrector revises + triple time-shift state), with coefficients from Lagrange × exponential integrals and τ as a continuous knob; this problem is a single-sided predictor with fixed orders 1/2, finite-difference extrapolation (one r0 term), and no tunable noise strength.
- **`diff-kdpm2-ancestral-noise` (755) / `diff-euler-ancestral-step` (522)**: single-step ancestral noise splitting, no multistep history or r0 extrapolation.
- **`diff-dpmpp-2m` / `diff-deis-multistep-coef` / `diff-lms-multistep-integral-step` (757)**: deterministic multistep (no noise term), with entirely different coefficient constructions (2M's closed form / DEIS and LMS integral coefficients).
- **`diff-plms-multistep-ab-ladder` (758)**: AB ladder + ets bookkeeping, no SDE noise, no EDM preconditioner.

## Pitfalls

- **Re-confirm the baseline right before mutating** (reusing 758's lesson): the first version of `check_full_loop_default` asserted second order for `outs[:-1]`, treating step 0's first-order warmup as a bug → baseline 14/15 red. Mutating at that point would have produced a wall of fake CAUGHTs — fixed the assertion (`outs[0]` is first-order) and re-ran the baseline to 15/15 green before mutating.
- **`exp(log(0.3))` is not guaranteed to equal 0.3 bit-for-bit**: sigma_min-tail cases must **copy** `core[-1]`'s float value exactly for the appended entry; otherwise h wobbles at ~1e-16 and the "identity step prev ≡ sample" assertion becomes fragile (it still passes the 1e-6 tolerance numerically, but the h=0 guard case would break — a tiny positive h means second order is no longer rejected).
- **Random-equivalence configs must be self-consistent**: the first generator picked `fst` and the tail independently, producing impossible combos like "fst=sigma_min but tail 0.0" → final-step second order meets σ_t = 0 → h = +∞ → r0 = 0 → `1/0` ZeroDivisionError (not ValueError, escaping the try). Officially the flag always pushes a zero-tail final step to first order — after tying the generator's fst to the tail and aligning exception paths, the proof passed.
- **All judge tensors in float64**: σ spans three orders of magnitude (0.3 → 500), so float32 round-trip λ errors approach the 1e-6 comparison tolerance — this problem's judge inputs are all float64 (the judge passes tensors through untouched; verified no dtype coercion in the judge).
- **The λ σ=0 branch**: `math.log(0)` raises while `torch.log(0) = −inf` — the λ helper must map `σ == 0 → math.inf`, with `math.exp(−inf) = 0.0` aligning with torch; otherwise the zero-tail final step crashes outright.

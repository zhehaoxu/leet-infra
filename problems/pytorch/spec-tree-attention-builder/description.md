# 推测解码：候选树构造与 tree attention 掩码

## 题目描述

Medusa / EAGLE 这类方法用一次前向就同时拿到「未来若干个位置」的候选 token：第 \(h\) 个 head 给出第 \(h\) 个 draft 位置的 top-\(k\)。把所有 head 的候选组合起来就得到一棵候选树，第 \(d\) 层节点是一条长 \(d\) 的路径，它的累积 logprob 是路径上各位置 logprob 之和。

真正要在 GPU 上跑的是一个**树状的 forward**：把所有候选节点摊平成一条序列、一次算完。这要求三件事配套给出：

1. **节点集是前缀封闭的**。父节点不在树里，子节点就不能在——否则 mask 会指向不存在的祖先。
2. **每个节点只看见「已确认前缀 + 自己的祖先链」**。兄弟节点之间必须互相不可见，否则并行的多个分支会互相污染注意力。
3. **同深度的节点共享 position_id**。这样不同分支在同一位置上的 KV 可以复用（EAGLE 的关键 trick），也让 RoPE 的相对位置语义与真实解码一致。

候选树不能盲目铺满（\(K^H\) 条路径很快就爆炸），所以本题用**按累积 logprob 的 best-first 扩张**：用一个最大堆，每次弹出当前最可能的路径，弹出即占一个节点预算，然后把它的孩子入堆。由于候选 logprob 都 \(\le 0\)，孩子一定不会比父亲更优，因此弹出的顺序等价于「全部路径按分数全局排序后取前 N 条」——顺便保证前缀封闭。

## 任务

实现 `solve(cand_tokens, cand_lps, budget, prefix_len)`：

- 输入：`cand_tokens`（`(H,K)` int64）、`cand_lps`（`(H,K)` float32，全部 \(\le 0\)）；`budget` 为节点数上限 \(N\ge 1\)；`prefix_len` 为已确认前缀长度 \(\ge 1\)。第 \(h\) 行是第 \(h\) 个 draft 位置的候选。
- 排序键：累积 logprob 降序，并列时**路径字典序更小**（按候选下标逐位比较）。
- 输出：
  - `parent`（`(N,)` int64）：父节点下标，根的孩子记 `-1`（父下标一定小于子下标）；
  - `node_tokens`（`(N,)` int64）：该节点对应的 token；
  - `depth`（`(N,)` int64）：1 到 \(H\)；
  - `positions`（`(N,)` int64）：`prefix_len + depth - 1`；
  - `mask`（`(N, prefix_len+N)` bool）：前 `prefix_len` 列（已确认前缀）全为 `True`，后 `N` 列只对自己和祖先为 `True`。
- 任一行有正 logprob、形状不一致、`budget < 1`、`prefix_len < 1`、非二维输入，抛 `ValueError`。

## 示例

```
cand_tokens = [[7, 9], [3, 8]]
cand_lps    = [[-0.1, -0.5], [-0.2, -3.0]]
budget = 4，prefix_len = 3

路径池（分数 = 各位置 logprob 之和）：
  (0)  -> 7  : -0.1
  (1)  -> 9  : -0.5
  (0,0)-> 7,3: -0.3
  (0,1)-> 7,8: -3.1   (0,0) 弹出后才入队
  (1,0)-> 9,3: -0.7
  (1,1)-> 9,8: -3.5

按分数弹出前 4 个：(0) -0.1、(0,0) -0.3、(1) -0.5、(1,0) -0.7

parent     = [-1, 0, -1, 2]
node_tokens= [ 7, 3,  9, 3]
depth      = [ 1, 2,  1, 2]
positions  = [ 3, 4,  3, 4]

mask（7 列 = 3 列前缀 + 4 个节点）：
节点0 (7)        [1 1 1 | 1 0 0 0]
节点1 (7,3)      [1 1 1 | 1 1 0 0]
节点2 (9)        [1 1 1 | 0 0 1 0]
节点3 (9,3)      [1 1 1 | 0 0 1 1]
```

节点 1 与节点 3 深度相同、`position` 都是 4，但前者只看得见节点 0、后者只看得见节点 2——这正是「同位置多分支」的 tree attention。

## 约束

- **入队时机决定前缀封闭**：必须「弹出父亲才把儿子入队」。若在初始化时把所有路径一次性入队再排序，节点集虽然可能相同，但 `parent` 会指向未输出的节点。
- **并列的键是整条路径**，不是单个 head 内的排名：`(0,1)` 与 `(1,0)` 分数相同时取 `(0,1)`。
- **mask 的前缀列与节点列不能混**：前缀是已经确认的真实 token，对任何 draft 节点都可见；节点列只有「自己 + 祖先」。
- **`positions` 与 `mask` 必须自洽**：同深度共享 `position` 不等于互相可见，两者是独立的两个设计。
- 由于 logprob 非正，best-first 的弹出顺序就是全局排序；这条单调性是本题算法正确性的前提，所以正 logprob 要报错而不是默默接受。

# 解题说明 · 候选树构造

## 为什么堆就够了

直觉上「从所有 \(\sum_d K^d\) 条路径里挑最好的 N 条」应该完整枚举再排序。但候选 logprob 都是非正数，**沿路径累加只会让分数变差**，于是父亲永远不差于儿子。有了这条单调性，best-first 的弹出顺序就等于全局排序，堆里同时最多只有「已弹出节点数 \(\times K\)」条路径，完全不需要枚举。

再看前缀封闭：儿子只有在父亲被弹出后才入队，所以任何被吐出的节点，其祖先必然已经被吐出并拿到了下标——`parent` 永远是合法且更小的下标。这也是 `mask` 能直接按下标填的前提。

## 结构三件套的相互关系

- `parent` / `depth` 描述**拓扑**：谁是谁的父亲、在第几层。
- `positions` 描述**位置语义**：\(prefix\_len + depth - 1\)，同深度的所有节点共享一个真实位置。这让「同一位置的多条分支」可以做 KV 复用，也让 RoPE 里不同分支的相对距离和串行解码完全一致。
- `mask` 描述**可见性**：前缀永远可见，节点列只看自己与祖先。兄弟之间不可见是关键——否则分支 A 的后缀会看到分支 B 的 token，验证出的 logits 就全错了。

三者相互独立又互相约束：同深度共享 `position` 但互不可见（`positions` 相同、`mask` 中对方为 0），这是 tree attention 最反直觉的一点。

## 并列与预算

- 并列键用整条路径的候选下标字典序，而不是 head 内排名，也不是 token id：路径才是堆里的对象，用路径比较才能让排序稳定可复现。
- `budget` 直接对应 GPU 上树 forward 的序列长度，是显存/延迟的主要旋钮；budget=1 时退化为「只赌一个 token」，budget 给足则穷尽整棵树。
- 树的最大深度是 head 数 \(H\)，所以节点数上界是 \(\sum_{d=1}^{H} K^d\)，超出的 budget 不会产生额外节点。

## 复杂度

堆操作 \(O(N\log(NK))\)，mask 填充 \(O(N\cdot H)\)，整体 \(O(NH)\) 级别（\(N\) 为节点数）。真实实现里构造本身在 CPU 上一次算好、在多次解码步里复用，所以瓶颈不在这里；本题考的是结构的正确性。

## 相关题目

- `spec-medusa-tree-verify`：给定**已经组装好的路径**只做 typical acceptance 验证；本题专门补上「树怎么造」这一环。
- `spec-eagle2-dynamic-tree-prune`：EAGLE-2 用草稿置信度动态剪枝，是本题「固定 budget + best-first」的自适应版本。
- `spec-specinfer-token-tree-verify`：把树摊平成序列后的验证侧逻辑，与本题的 mask 生成互为上下游。

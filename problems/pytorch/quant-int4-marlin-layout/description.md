# 量化：4-bit 权重的 tile 交织布局解码

## 题目描述

4-bit 权重的推理内核（GPTQ / Marlin 这一路）并不按行主序存码字。为了一个 warp 内访存连续、让 16×16 tile 的同一行落进同一段地址，权重被切成 tile，tile 内列按固定顺序**交织**，每 8 个 4-bit 码挤进一个 int32；融合 QKV 之类的操作还会对输出通道做一次全局置换 `perm`。于是"解包"不是对每个字节做 `& 0xF`：要先把 (tile 行, tile 列, tile 内行, 半字) 四层坐标和槽位序算对，再按 `perm` 散射回逻辑列，最后才用逻辑列的 scale / zero-point 反量化。坐标错一层，读出来的权重就是另一列的码——数值上看起来"只是精度差一点"，实际是整表串列。

本题给定按上述布局打包的 `qweight`、同样布局的 `qzeros`、逻辑列顺序的 `scales` 与列置换 `perm`，要求还原浮点权重 `W`。

## 规则

记原始权重形状为 `(K, N)`，`K`、`N` 都是 16 的正整数倍。布局由四层坐标确定：

1. **tile 网格**：行方向 `K/16` 个 tile、列方向 `N/16` 个 tile。第 `t` 个 tile 行覆盖原始行 `16t … 16t+15`；第 `g` 个 tile 列覆盖**存储列** `16g … 16g+15`。
2. **tile 内半字**：tile 内第 `r` 行的 16 个码分成两个半字 `h = 0, 1`，第 `h` 个半字装 tile 内列 `8h … 8h+7`。
3. **槽位序**：半字里从低 4 位到高 4 位共 8 个 nibble 槽位，tile 内本地列 `j` 的码放在第 `ORDER[j]` 个槽位，`ORDER = [0, 2, 4, 6, 1, 3, 5, 7]`。因此一个 int32 的字节 `0..3` 依次是本地列 `(0,4)`、`(1,5)`、`(2,6)`、`(3,7)` 的低/高半字节。
4. **zero-point 同规则**：`qzeros` 没有行维，第 `g` 个 16 列组、半字 `h` 的一个 int32 里，槽位 `b` 是存储列 `c = 16g + 8h + ORDER[b]` 的 zero-point。
5. **列置换**：`perm[c]` 是存储列 `c` 对应的逻辑列号；`perm` 是 `0 … N−1` 的一个排列。
6. **反量化**：`W[k, perm[c]] = (code(k, c) − zero(c)) × scales[perm[c]]`，其中 `scales` 按逻辑列给出。注意 zero-point 按**存储列**索引，scale 按**逻辑列**索引。

## 任务

实现 `solve(qweight, qzeros, scales, perm, K, N)`：

- `qweight`：int32，形状 `(K//16, N//16, 16, 2)`。
- `qzeros`：int32，形状 `(N//16, 2)`。
- `scales`：float32，形状 `(N,)`，逻辑列顺序。
- `perm`：`list[int]`，长度 `N`。
- `K`、`N`：原始权重行数、列数。
- 返回 `W`：float32，形状 `(K, N)`，逻辑列顺序。内部用 float64 计算再转 float32，容差 `1e-5`。
- `K % 16 != 0` 或 `N % 16 != 0` 时抛 `ValueError`。

## 示例

`K = N = 16`（单 tile）、逻辑码 `code[k, n] = (3k + n) % 16`、`zero[n] = n % 2`、`scales = [1.0]×8 + [0.5]×8`、`perm = [15, 14, …, 0]`（存储列 `c` 落到逻辑列 `15−c`）。

存储侧第 0 行、半字 0 的码是 `0,1,2,…,7` 经槽位序重排后打包：

```
槽位（低→高）:  j0  j4  j1  j5  j2  j6  j3  j7
码           :   0   4   1   5   2   6   3   7
int32        : 0x73625140          # 字节 = 0x40, 0x51, 0x62, 0x73
```

zero-point 同理（`zero = 0,1,0,1,…`）：

```
qzeros[0, 0] = 0x11001100
```

反量化后（只列前 4 行 × 8 列）：

```
W[0:4, 0:8] =
  [[14.0, 14.0, 12.0, 12.0, 10.0, 10.0,  8.0,  8.0],
   [ 1.0,  1.0, -1.0, 15.0, 13.0, 13.0, 11.0, 11.0],
   [ 4.0,  4.0,  2.0,  2.0,  0.0,  0.0, 14.0, 14.0],
   [ 7.0,  7.0,  5.0,  5.0,  3.0,  3.0,  1.0,  1.0]]
```

（逻辑列 `n` 读的是存储列 `15−n` 的码；后 8 列 scale 为 0.5，所以数值折半。）

## 约束

- `qweight`、`qzeros` 是 int32 位模式：中间结果要用 int64 承载，否则高 nibble 右移会带上符号位。
- 槽位按 `ORDER` 交织，不是自然列序；两个半字分别对应 tile 内列的 `0…7` 与 `8…15`。
- `perm` 是"存储列 → 逻辑列"的散射方向，实现里不要写成反向 gather。
- 判题只看返回张量的数值与形状，不限定实现方式。

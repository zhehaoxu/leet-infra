# 解题说明 · 4-bit tile 交织布局

## 出处

- GPTQ（Frantar et al., arXiv:2210.17323）的 `qweight` 按输入维每 8 个 4-bit 码塞进一个 int32；`qzeros` 用同一套 nibble 打包，是本题"码与 zero 共用槽位规则"的来源。
- Marlin（IST-DASLab 的 4-bit 推理内核，vLLM / llm-compressor 采用的版式）在此之上再按 16 行 × 16 列的 tile 组织，并对 tile 内列做固定交织，以便每行 16 个 4-bit 码在一条 128-bit 访存里取完。**Marlin 没有论文**，属于内核实现技巧；本题把它的版式抽象成题面里的显式规则，用于考核索引账，不宣称与任一上游版本字节级一致（需要逐字节对齐时须回源该版本 `pack` 实现）。
- AWQ（Lin et al., arXiv:2306.00978）的 `WQLinear` 打包与 QKV 融合时的通道重排，是 `perm` 这一层的现实原型：存储列序与逻辑列序并不相同。

## 核心与易错点

**四层坐标一个都不能少。** `(tile 行, tile 列, tile 内行, 半字)` 才是 int32 的位置；少写 tile 行，K 超过 16 时第 2 个 tile 会读到第 1 个 tile 的数据（示例外的 `check_tile_boundary` 专测这一点）。

**槽位序是 `ORDER = [0,2,4,6,1,3,5,7]`，不是自然序。** 一个字节的低/高半字节装的是本地列 `(j, j+4)`，所以逐列读取时要按 `ORDER[j]` 取槽，或等价地按槽位 `b` 反查 `INV[b] = [0,4,1,5,2,6,3,7]`。两种写法都对，但写混就整表串列。

**`perm` 是散射不是 gather。** 语义是"存储列 `c` 的数据属于逻辑列 `perm[c]`"，即 `W[:, perm[c]] = …c…`。写成 `W[:, c] = base[:, perm[c]]` 恰好是逆置换，只有对合排列（如逆序）时看不出错——`check_perm_scatter` 用四路交织 `[0,4,8,12,1,5,9,13,…]` 把方向钉死。

**zero 按存储列、scale 按逻辑列。** `qzeros` 是随权重一起打包的存储侧数据，落在存储列；`scales` 是逻辑视角的逐通道缩放。混用会在 `perm` 非恒等时整体错位。

**int32 右移要用 int64 承载。** int32 的位模式可能被解释成负数，`>>` 是算术右移；先 `.to(torch.int64)`（或 `& 0xFFFFFFFF`）再移位，否则高槽位会拖进符号位。

**形状校验。** `K`、`N` 必须是 16 的倍数，否则 tile 网格不完整，按约定抛 `ValueError`。

## 对拍口径

- 参考实现：先按 `(h, 槽位)` 双重循环用广播把整个 tile 列一次性取成 `(K, N//16)`，再 `centered[:, perm] = …` 散射、乘 scale。
- 独立 oracle：逐行逐列、按"本地列 `j` 读槽位 `ORDER[j]`"的相反方向解码，用嵌套 `list` 组装，和参考实现的向量化路径完全不同。
- 测试侧另有独立编码器 `_encode`（逻辑码 → int32），先编码再解码做往返；30 组随机形状（K、N ∈ {16,32,48}）+ 8 个定向用例（恒等 perm、列槽位、行槽位、zero 打包、跨 tile、perm 方向、坏形状、示例）。
- 单个 4-bit 权重矩阵的存储账：`K·N/2` 字节的码 + 每个 16 列组 8 字节的 zero-point（本题不含 scale 的存储）。

## 复杂度

- 解码 `O(K·N)` 次位运算，与权重元素数线性；`K, N ≤ 48` 的测试规模下是毫秒级。
- 真实内核里这一步与反量化、GEMM 的 `ldmatrix` 是一体的，本题只保留坐标与位序。

## 相关题目

- `quant-uint4-asym-pack`：只考"低 4 位偶数、高 4 位奇数"的字节内打包，本题在其上加了 tile 网格与列置换。
- `group-wise-quantize`：per-group 量化本身的数值口径，不含字节布局。
- `gptq-column-quantize`：GPTQ 的逐列误差补偿，输出仍是浮点权重，不涉及打包。
- `awq-activation-scale`：缩放因子的网格搜索，本题是它的下游——缩放后的 4-bit 码如何进显存。

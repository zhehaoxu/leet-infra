# Deep dive: Shingle Contamination Audit

## Origin

- **The original source of shingling / containment**: Andrei Broder, *On the Resemblance and Containment of Documents*, SEQUENCES'97 (Compression and Complexity of Sequences, IEEE, 1997). This founding paper on near-duplicate document detection defines, in the same breath, two overlap measures — resemblance \(|A\cap B|/|A\cup B|\) (what we now call Jaccard similarity) and **containment** \(|A\cap B|/|A|\) (denominator on one side only, inherently asymmetric) — and proposes estimating them over very large corpora with "compressed fingerprints" (shingles + hashing). The two matrices of this problem are exactly the pairwise versions of these two quantities.
- **MinHash near-duplicate detection**: the contemporary Broder–Glassman–Manasse–Zweig MinHash line (min-wise independent permutations sketch, 1997; arXiv/report id to be confirmed) compresses the estimation of resemblance and containment to constant-size hashes, and is the algorithmic backbone of every modern near-duplicate de-duplication pipeline (LSH bucketing).
- **LLM corpus de-duplication**: Lee et al., *Deduplicating Training Data Makes Language Models Better* (ICML 2022; arXiv id to be confirmed) turns MinHash-LSH shingling into the standard component of large-scale training-corpus de-duplication — note that this does **within-corpus de-duplication** (deciding which documents to drop), a different thing from this problem's **cross-corpus audit** (see "Versus neighbouring metrics / algorithms").
- **n-gram containment as a contamination/leakage test**: checking "did the eval set appear in the training data" via containment over contiguous n-grams is now a routine hygiene step in mainstream benchmarks; a representative work is Roberts et al., *Is My Data in Your Language Model?* (2023; arXiv id to be confirmed) — which judges training-data overlap with n-gram/trigram containment rather than Jaccard, for exactly the reasons derived in section 2 below.
- The judge environment has no de-duplication/similarity library at all (`datasketch`, `text-dedup`, `nltk` are all forbidden and absent), so none of the fingerprint/LSH/estimation machinery above is available; the sets and their intersections/unions must be built from the definition, by hand.

## Full derivation and index conventions

Let \(A_i\) be the shingle set of evaluation document \(i\) and \(B_j\) that of training document \(j\); the matrix index \(i\) always runs over the evaluation side and \(j\) over the training side, a direction held fixed throughout.

1. **Windows and set size.** A document of length \(L\) yields \(L-n+1\) overlapping windows when \(L \ge n\) and 0 when \(L<n\). But the shingle set is a **de-duplicated set**, so \(|S| =\) the number of **distinct** \(n\)-grams, which is \(\le L-n+1\). Treating that as \(L-n+1\) gets the very first convention wrong (see the next section).
2. **Intersection.** \(|A_i \cap B_j|\) is the number of distinct shingles that appear both in this evaluation document and in that training document — deduplicate each side first, then take a set intersection.
3. **Containment is pinned to the evaluation side.** \(\text{contam}[i,j] = |A_i\cap B_j| / |A_i|\). Since \(A_i\cap B_j \subseteq A_i\), the value lies in \([0,1]\) always. It is **asymmetric**: swapping \(i,j\) (or moving the denominator to \(|B_j|\)) yields a different quantity, and this problem never builds a reversed matrix. Its meaning is "what fraction of evaluation document \(i\) is covered by training document \(j\)" — precisely the question a contamination audit asks.
4. **Jaccard is pinned to the union.** \(\text{jac}[i,j] = |A_i\cap B_j| / |A_i\cup B_j|\), with the union via inclusion–exclusion \(|A_i\cup B_j| = |A_i|+|B_j|-|A_i\cap B_j|\). It is symmetric and in \([0,1]\). Because \(A_i \subseteq A_i\cup B_j\) we have \(|A_i\cup B_j| \ge |A_i|\), hence **elementwise** \(\text{jac}[i,j] \le \text{contam}[i,j]\) (same numerator, larger Jaccard denominator) — the origin of the judge invariant `jac.max() <= contam.max()`.
5. **Sentinels.** When \(|A_i| = 0\) the whole contam row is 0 (avoiding \(0/0\)); when \(|A_i\cup B_j| = 0\) (both empty) jac is 0. If either corpus is empty the corresponding matrix dimension is 0 — \((M_{\text{eval}},0)\), \((0,M_{\text{train}})\), \((0,0)\) — and `flagged` is empty.
6. **flagged.** For each non-empty \(A_i\) take \(\max_j \text{contam}[i,j]\) and compare to `threshold` with `>=` (equality inclusive). Taking a max requires a non-empty training side (max over the empty set would crash). `threshold > 1` is necessarily empty (upper bound 1); `threshold = 0` flags every non-empty \(A_i\) (max \(\ge 0\) always).

## Core traps

1. **Why containment beats Jaccard (quantitatively).** Take the evaluation document `[1,2,3,6,4]` (3 shingles) against a training document that contains all three shingles **and** 25 of its own (\(|B| = 28\)). containment \(= 3/3 =\) **1.0** (verbatim hit), Jaccard \(= 3/(3+28-3) = 3/28 \approx\) **0.107** — diluted to almost nothing by the 27 extra shingles on the training side. Real corpora run to tens of thousands of tokens per document, so Jaccard almost never crosses a contamination threshold; the contamination signal should depend only on "how much of the evaluation document is covered", never on the training document's length. This is exactly the invariant `check_containment_beats_jaccard_on_long_docs` protects.
2. **Pin the denominator to the evaluation side.** Writing \(/|B_j|\) or \(/(|A_i|+|B_j|)\) throws away the "coverage fraction" meaning and turns long training documents into a penalty. The asymmetry is a feature, not a bug: contam[i,j] and contam[j,i] mean different things ("eval covered by train" vs "train covered by eval"); this problem wants only the former.
3. **Set semantics vs frequency semantics.** Shingles here form a **set**; a repeated n-gram counts once. `[1,1,1]` at \(n=2\) gives two windows (1,1),(1,1), but the set is just \(\{(1,1)\}\) with \(|A|=1\); against training `[1,1]` (set \(\{(1,1)\}\)) this yields contam = jac = 1. Switch to **frequency/multiset** semantics — numerator counting 2 hit windows while the deduplicated denominator is 1 — and containment becomes \(2/1 = 2 > 1\), overflowing: a "fraction" must stay \(\le 1\), which is the hard constraint of set semantics (`check_repeated_shingles_collapse` asserts `contam.max() <= 1`). Any document with heavily overlapping windows or runs of repeated tokens will be computed wrong under frequency semantics.
4. **Empty sets and sentinels — not NaN, not 1.** \(|A_i|=0\) (evaluation document shorter than \(n\)) ⇒ the whole row is 0 and the document **never enters flagged** (even at `threshold=0`): an empty set has no "coverage fraction", and \(0/0\) must be avoided. An empty corpus on either side ⇒ degraded shape, empty flagged; never take a max over an empty training side. Recording an empty row as 1 would give a "fully empty audit" a perfect score — the same philosophy as `eval-ndcg-at-k` recording IDCG=0 as 0.
5. **Threshold boundary is inclusive.** The test uses `>=`: containment exactly equal to `threshold` counts as a hit. In `check_boundary_threshold_inclusive` the max is exactly 0.5; `threshold=0.5` hits and `threshold=0.5+1e-6` misses. Using `>` instead would drop "right-on-the-line" evaluation documents.
6. **flagged is an ascending index list, not a hit count.** It lists *which* evaluation documents are contaminated, each qualifying index appearing once in ascending order. `check_duplicate_train_columns` shows that copying a training document just adds a column of identical values, leaving flagged unchanged — do not stuff "how many training documents matched" into flagged.
7. **Check dtype and shape together.** contam/jac are float32, flagged is int64; the judge checks both `list(flagged.shape)==[len(flagged)]` and `flagged.dtype==int64`. float32 stores \(1/7\), \(1/3\) with rounding, so judging uses `atol=rtol=1e-5`.

## Versus neighbouring metrics / algorithms (division of labour)

- **vs the planned within-corpus de-duplication problem in `data-tokenization` (or a prospective `data-pipeline`) — this repo's todo #66③: exact hash + MinHash + LSH near-duplicate; not yet landed, so do not invent a slug before it exists.** That family removes duplicates **inside a single corpus** — exact hash catches identical documents, MinHash+LSH catches near-duplicates — and outputs "which documents to keep/drop" (a keep-set or the deduplicated corpus). This problem is an audit **between two corpora**: it deletes nothing, never asks "who inside the training set resembles whom", and outputs the eval-doc × train-doc **overlap matrix** (contam/jac) plus a flagged list of "which evaluation documents are covered by the training corpus". Direction, granularity and product all differ — one cleans the training set itself, the other runs a hygiene check on the evaluation set.
- **vs the `retrieval-*` collection** (`retrieval-ivf-assign` / `retrieval-pq-codes` / `retrieval-hnsw-greedy` / `retrieval-mmr` / `retrieval-rrf-fusion` / `retrieval-rag-chunk`): retrieval finds **nearest documents to a query and scores/orders them** (vector distance, recall, fusion), caring about "which document is most relevant". This problem is a **data-hygiene audit**: the input is documents chopped into discrete n-gram sets and the operation is set intersection/union — there is no embedding, no distance, no top-k anywhere. Even though `retrieval-rag-chunk` also cuts documents and emits a matrix, that is chunk×query similarity retrieval, not the eval×train shingle overlap here.
- **vs the other `eval-*` problems**: `eval-ndcg-at-k` / `eval-pass-at-k` / `eval-perplexity-logits` / `eval-token-accuracy` score the **model's output** (ranking quality, pass rate, language-modelling likelihood, per-token accuracy), and `eval-bleu-score` / `eval-rouge-score` score the **n-gram overlap between generated text and references**. This problem scores the **dataset itself** — the hygiene of the train/eval corpora, audited before the model even runs. The relationship to BLEU/ROUGE is the subtlest: they too use contiguous n-grams, but BLEU treats n-grams as **clipped / multiset** scoring material and ROUGE uses **recall / LCS**, comparing "hypothesis vs reference"; here n-grams are **pure set-deduplicated** and compare "does this eval shingle appear in that training shingle", additionally emitting the asymmetric containment. Same n-grams, different convention and purpose.

## Cross-check design

The reference solution turns shingles into `set[tuple[int]]` directly (hand windows + set de-duplication), counts \(|a \& b|\) per pair, forms the union by inclusion–exclusion, builds the intersection vector in one row, and guards the sentinel with `torch.where(union > 0, ...)`; it has separate branches for an empty \(A_i\) and an empty side. The judge's `_oracle` (see `check_matches_oracle`) takes a completely different road and uses no set algebra at all: each shingle is encoded as a string key like `"1|2|3"` stored in a **plain list** preserving order, de-duplicated by hand with a `seen` dict, the intersection size is counted by an **explicit double loop** `if x in bset` per key, and the union uses \(|A|+|B|-|A\cap B|\). Beyond the example the suite covers: \(n=1\) unigram sets, \(n=4\) larger windows, `[1,1,1]` collapse, documents shorter than \(n\) and empty corpora on either side, eval-corpus == train-corpus giving an all-1 diagonal, disjoint vocabularies, thresholds in `{0,0.25,0.75,1.0,1.5}`, plus 6 randomised corpora (`torch.Generator().manual_seed(300)`) × several thresholds cross-checked throughout with `allclose(atol=1e-5, rtol=1e-5)`; flagged is checked separately against "non-empty row's max ≥ th" (empty rows never participate).

## Complexity and scaling at large sizes

Let \(M_e, M_t\) be the numbers of evaluation/training documents, \(|A_i|, |B_j|\) the deduplicated shingle counts of documents \(i/j\), and \(n\) the shingle length. Building the sets is a per-document sliding window at \(O(\sum (|d|-n+1)\cdot n)\) (tuple construction is \(O(n)\)) plus hash de-duplication. The brute-force pairwise scan computes \(|A_i\cap B_j|\) by iterating the smaller set at \(O(\min(|A_i|,|B_j|))\) per pair, totalling \(O(M_e M_t \bar{|S|})\); and \(\text{contam}/\text{jac}\) is a dense \(M_e\times M_t\) matrix, so \(O(M_eM_t)\) space is unavoidable — the output itself is that large. **Why this problem uses brute-force sets**: the judge scale is a few dozen toy documents of a few to a few dozen tokens each, where hand sets are the most deterministic and carry no floating-point approximation, and an **exact** matrix is required rather than an estimate. At real scale the standard approach replaces each document's shingle set with a **MinHash sketch** (\(O(|S|)\) to build, constant-time compare, turning resemblance/containment into estimates over the sketch), then **LSH bucketing** only scores candidate near-duplicate pairs exactly; or an **inverted index** (shingle → training documents containing it) accumulates each eval shingle's hits into the corresponding \(|A_i\cap B_j|\) numerator and skips pairs that are obviously 0, shrinking the pairwise work to proportional to the sparse co-occurrence. None of those libraries exists in the judge environment and exact values are required, so hand-written sets are the right answer here.

## Practical notes

- **The choice of \(n\) cuts both ways.** A small \(n\) (1, 2) makes shingles ubiquitous, so accidental cross-document co-occurrences abound and false positives explode ("`the cat` from the eval is obviously in the training data too"). A large \(n\) demands near-verbatim matches, so a light rewrite or synonym swap slips through, and any evaluation document shorter than \(n\) collapses to an empty set and escapes the audit. LLM leakage audits typically use word-level 5–13 n-grams (trigrams/five-grams both appear in the literature, depending on language and rewrite strength); this problem hands that knob to the caller via token-id input.
- **flagged uses \(\max_j\), an "existence" convention**: a document is contaminated if **any single** training document covers it past the threshold — contamination is an existential statement, no need to sum or average over training documents. A more conservative view (many documents each covering a fraction, combined into total contamination) would need a different convention; this problem does not take it.
- **Duplicate/near-duplicate training documents raise the "hit column count" but not flagged** (see `check_duplicate_train_columns`): real audits usually de-duplicate the training set first, otherwise the same contamination is counted many times and the matrix widens while the verdict stays put.
- **Always report \(n\) and `threshold`.** On the same corpus pair, changing \(n\) or the threshold flips the conclusion; an audit that says only "contamination rate X%" without naming the shingle length and threshold is meaningless.

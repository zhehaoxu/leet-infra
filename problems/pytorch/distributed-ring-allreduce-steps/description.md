# Ring All-Reduce 逐步通信模拟

## 题目描述

`distributed-all-reduce` 只要求终值。本题要求你**精确复现 Ring All-Reduce 的每一步通信**，返回每个
通信轮次结束后的**全局中间状态**。这是 NCCL 在真实集群里做梯度 All-Reduce 的算法——把「只求和」拆开
成看得见的分块流转。

## 数据布局

$W$ 个 rank 排成一个环，rank `q` 的**右邻居**是 $(q+1)\bmod W$。每个 rank 持有一个长度 $W$ 的缓冲区，
第 `c` 列就是它对**第 `c` 块**的数据。输入 `init` 是形状 $(W, W)$ 的张量，第 `q` 行 = rank `q` 的初始缓冲。
目标：让每个 rank 最终都持有逐块求和后的完整向量 $\text{full}[c]=\sum_q \texttt{init}[q][c]$。

## 通信调度（务必按此精确实现）

**每个步骤是一次同步通信轮**：本轮所有「发送」都用**更新前**的缓冲计算；每个 rank 恰好向右邻居发一块、
恰好从左邻居收一块。

**阶段 1 · Reduce-Scatter**（$t = 0 \dots W-2$，共 $W-1$ 步）：
rank `q` 把下标 $s=(q-1-t)\bmod W$ 处的值 `buf[q][s]` 发给右邻居；接收方把它**累加**到自己缓冲的**同一
下标 `s`** 上。$W-1$ 步后，rank `q` 的下标 `q` 恰好是完整和（其余块仍是半成品）。

**阶段 2 · All-Gather**（$t = 0 \dots W-2$，共 $W-1$ 步）：
rank `q` 把下标 $s=(q-t)\bmod W$ 处的值 `buf[q][s]` 发给右邻居；接收方用它**覆盖**自己缓冲的**同一下标
`s`**（已是完整和，直接搬）。$W-1$ 步后所有 rank 的缓冲都等于 `full`。

## 规则

实现 `solve(init)`：`init` 为 $(W,W)$ 张量。按上调度执行，返回**快照列表**——每完成一个通信步骤就记录
一次「此刻所有 rank 的缓冲」，形状 $(W,W)$。返回 `list[torch.Tensor]`，**长度 $=2(W-1)$**，顺序为先
$W-1$ 个 Reduce-Scatter 快照、再 $W-1$ 个 All-Gather 快照。不得修改输入 `init`。$W=1$ 时返回空列表 `[]`。

## 示例（$W=3$，完整轨迹）

`init = [[1,2,3],[4,5,6],[7,8,9]]`，`full = [12,15,18]`：

```
step0  RS t=0 : [[1,10,3],[4,5,9],[11,8,9]]
step1  RS t=1 : [[12,10,3],[4,15,9],[11,8,18]]   # 对角线 buf[q][q] 已是完整和
step2  AG t=0 : [[12,10,18],[12,15,9],[11,15,18]]
step3  AG t=1 : [[12,15,18],[12,15,18],[12,15,18]]  # 全员 full
```

返回这 4 个 $(3,3)$ 张量组成的列表。

## 约束

- `1 ≤ W ≤ 8`；`init` 为 $(W,W)$
- 返回 `list[torch.Tensor]`，长度 $=2(W-1)$，每项形状 $(W,W)$，逐元素对拍
- 严格按题面下标公式实现；不同的合法 ring 排布会得到不同中间态，判题只认本调度

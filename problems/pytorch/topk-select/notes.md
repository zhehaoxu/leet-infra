# Top-K 选择详解

## 选择 vs 排序

完整排序是 $O(n\log n)$，而只要 top-k 时可用**部分选择**更快：

- 本解用「重复 argmax + 屏蔽」的选择法，$O(k\,n)$，`k` 远小于 `n` 时划算且直观。
- 理论最优是 quickselect 平均 $O(n)$，或维护大小为 `k` 的最小堆 $O(n\log k)$。
- GPU 上 `torch.topk` 常走 bitonic/partial sort kernel；`sorted=True` 保证结果降序。

## 屏蔽技巧：把选中位置设为 -inf

取走一个最大值后必须让它不再被选中。最干净的做法是用 `scatter_` 把该位置写 `float('-inf')`，
下一轮 `argmax` 自然跳过。对称地，取 top-k **最小** 就把选中位置写成 `+inf` 并配 `argmin`。

## 并列（ties）与确定性

当有重复值时，`argmax` 返回**最小索引**，而 `torch.topk` 的并列打破顺序不保证一致。
因此判题用连续随机数（几乎不可能精确相等），使 top-k 唯一；工程里若必须处理并列，
需显式约定（如值相同按索引升序）并保持两端一致。

## 应用

- **MoE 路由**：每个 token 对专家打分后取 top-k 个专家激活（稀疏计算）。
- **top-k 采样**：语言模型里先截断到概率最高的 k 个 token 再归一化采样（与本合集
  「top-p 采样」互补，常叠加使用）。
- **检索/检测 NMS 前置**：按分数取候选 top-k，再做 IoU 抑制。

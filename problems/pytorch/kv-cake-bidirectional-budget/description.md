# KV Cache：CAKE 层间偏好预算与跨层级联传递

## 题目描述

层间预算的朴素做法是「金字塔」——浅层留多、深层留少，一个固定公式套到底。但实测发现不同模型、不同任务的层间偏好差异极大：有的模型中层承担了主要的检索压力，深层反而只需要很少的缓存。CAKE（Qin et al., ICLR 2025, arXiv:2503.12491）把它形式化成「**切蛋糕问题**」（cake-slicing problem）：先测出每层的**偏好**，再按偏好切分全局预算，最后以**级联**（cascading）的方式在层间传递信息。

本题取其中两个确定性内核：

**（1）偏好与预算分配。** 设第 \(l\) 层的累计重要性行 \(s_l\in\mathbb R^{L}\)，层偏好取总质量 \(m_l=\sum_j s_l[j]\)，全局预算为 \(B\)（全模型总共能保留多少个位置）。按质量占比分配：

\[
b_l=\left\lfloor \frac{B\,m_l}{\sum_{l'}m_{l'}}\right\rfloor,\qquad
\text{余量 } B-\sum_l b_l \text{ 按小数部分降序逐个补 1}
\]

小数部分为 \(\frac{B m_l}{\sum m}-b_l\)，**并列取小层号**；单层最多补到 \(L\)。若某层质量为 0，它分到 0 个位置。质量越大的层拿到的份额越大——这就是「自适应」的部分，替代了固定的金字塔公式。

**（2）跨层级联。** 层与层之间存在依赖（例如浅层确定的实体位置，深层也需要保留）。给定依赖边序列 `edges = [(src, dst), ...]`，按**给定顺序**做重要性传递：

\[
w_{dst}\leftarrow w_{dst}+w_{src}
\]

初始 \(w_l=s_l\)。因为按顺序累加，传递是**可级联**的：先处理的边会把已累加的结果继续往下传（`(0,1),(1,2)` 意味着 2 层同时吃到 0、1 两层的证据）。传递完成后，每层在自己的 \(w_l\) 上取 top-\(b_l\)（并列取小下标）作为最终保留集。

这正是与「自上而下逐层贪心」的分歧：预算分配是**全局一次性**的（各层同时按偏好切分），而依赖是**按边序逐层回填**的，两步分离、互不干扰。

## 任务

实现 `solve(scores, budget, edges)`：

- 输入：`scores`（float32 `(Lc, L)`，非负）；`budget`（非负整数 \(B\)）；`edges`（`(src, dst)` 列表，层号在 `[0, Lc)` 内、不允许自环）。
- 输出 `(alloc, keep)`：`alloc` 为 `(Lc,)` int64（各层保留位）；`keep` 为 `(Lc, L)` bool。
- 余量分配按「小数部分降序、并列小层号」，可多轮循环直到补完或所有层都到 `L`；`B` 超过总容量 `Lc·L` 时各层封顶 `L`，`sum(alloc) < B` 属正常。
- 参数非法（`budget < 0`、负分数、自环、层号越界）抛 `ValueError`。

## 示例

```
scores = [[9, 8, 7, 0, 0, 0],      层 0：前半段重要
          [0, 0, 0, 9, 8, 7],      层 1：后半段重要
          [1, 2, 3, 4, 5, 6]]      层 2：越靠后越重要
budget = 9，edges = [(0, 1)]

质量 = [24, 24, 21]（总 69）→ 9*24/69 = 3.13 → 3、3、floor(2.74) = 2
余量 1 给小数部分最大的层 2（0.74）→ alloc = [3, 3, 3]

w1 = [0,0,0,9,8,7] + [9,8,7,0,0,0] = [9, 8, 7, 9, 8, 7]
layer0 top3 → {0,1,2}        keep[0] = [T,T,T,F,F,F]
layer1 top3 → 9(0)、9(3)、8(1，并列取小)   keep[1] = [T,T,F,T,F,F]
layer2 top3 → {5,4,3}        keep[2] = [F,F,F,T,T,T]
```

## 约束

- 传递**只写 dst、不改 src**：`edges` 的顺序会改变结果（`(0,1)` 与 `(1,0)` 效果不同），必须按给定顺序逐条累加。
- 传递是「累加」而不是「覆盖」：同一层被多条边指向时，各来源的证据叠加；链式边会把上游已累加的结果继续传下去，因此潜在重复计入是预期行为。
- 预分配必须先取 `floor` 再补余量，不能用 `round`：`round` 会让份额之和偏离预算，且边界行为依赖浮点舍入规则。
- 零质量层分配 0 且不保留任何位置；`budget = 0` 时全部为空。

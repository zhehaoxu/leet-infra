# 参考做法：序列内先乘、跨序列后平均

## 实现

1. 对 `scores` 的专家维做归一化，得到每个 token 的专家概率；不要只对选中项归一化。
2. 用 `scatter_add_` 统计 `[B,E]` 的选中次数，乘以 `E/(T*K)` 得到相对负载 f。
3. 对 token 维求平均得到 p。
4. 每条序列先算 `alpha * sum(f*p)`，再跨 batch 求平均，得到 `sequence_loss`。
5. 另算 `batch_loss`：先对 f、p 各自跨 batch 求平均，再点积。

选择来自外部输入，不应由 scores 重新 top-k 得到，因为带偏置或受限路由器可能给出不同结果。

## 正确性检验

15 个 `check_*` 覆盖：两种均值次序差异、单序列退化、逐 token 归一化、行缩放不变、K 归一化、全专家、alpha=0、单专家、显式选择、未选专家、序列置换、非连续输入、32 组随机枚举、最大形状、默认 alpha 与极小亲和度。

手算示例特意让整个 batch 看似均衡而每条序列都集中：`sequence_loss=0.18`，`batch_loss=0.1`，用于防止把均值次序写反。oracle 用纯 Python 逐专家统计次数与概率，不复用 scatter 路径。

## 范围与来源

公开的 DeepSeek-V2/V3 系列描述过序列级辅助损失，其相对负载常写作 $f_i=\frac{E}{Tk}\sum_{t}\mathbb 1[i\in \mathrm{topk}(u_t)]$ 的形式。本题沿用这一函数形式，并把「序列内相乘、batch 间平均」与「先 batch 平均再相乘」并列，用于检查实现次序。

题目使用显式给定的选择与有限亲和度，不实现路由器、不训练、不涉及 CV 损失或专家重要性统计。不要把它当作任何框架训练循环的逐步复刻；todos 中曾把序列级损失与 OLNN/CV 论文关联，但 CV 是另一种统计量，本题不以该论文为口径。

# 解题说明 · MiniLM

## 为什么蒸馏注意力分布

教师最后一层的输出 logits 只反映「最终预测什么」，不反映「模型内部怎么组织信息」。自注意力分布是逐头的、逐位置的：第 $h$ 个头在处理 query $i$ 时把多少权重分给 key $j$。MiniLM 认为这正是小型化后最容易丢掉的结构性知识，于是直接对每个头的注意力分布做 KL。因为分布天然归一，KL 在「完全相同的关注模式」处为 0，不会像 logits MSE 那样被整体尺度干扰。

## mask 的双重角色

同一个 `mask` 既标记合法 key 也标记合法 query。作为 key：被 mask 的位置概率必须严格为 0（用 $-\infty$ 填充后 softmax 自然给出 0），否则 padding 会分走注意力质量；作为 query：被 mask 的行整行无效，既不进分子也不进分母。如果只在 key 侧掩码而忘了行侧，长度不同的 batch 会得到与 padding 比例相关的损失——这是实现里最常见的错。

## 为什么除以「有效 query 数 × H」

KL 是对每个 (query, head) 单独算的，头与头之间没有理由加权（论文对所有头同等对待）。先对有效 query 求和、再除以「有效 query 数 × 头数」，等价于「每个头内部对 query 取平均，再对头取平均」。分母写错成 $L\cdot H$ 会把 padding 行当成 0 计入，导致损失被稀释。

## 关系表示与 MSE

论文除了注意力，还蒸馏 token 之间的关系：把 query/key/value 向量两两做缩放点积，得到若干 $L\times L$ 的关系矩阵，再用 MSE 对齐（相比逐元素对齐隐向量，关系矩阵对维度顺序不敏感）。本题把这一步抽象成三个 $(B,3,D)$ 的关系向量——`3` 对应三类关系（如 CLS·CLS、CLS·token、token·token），对齐方式就是逐元素 MSE，对全部 $B\times3\times D$ 元素取均值。它与注意力项是**相加**而非加权：MiniLM 的原始实现里两项量级相当，直接相加即可。

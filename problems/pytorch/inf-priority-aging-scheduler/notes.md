# 解题说明 · 带老化的优先级准入调度

## 出处

- 优先级调度与饥饿（starvation）是操作系统教材的经典议题（Silberschatz《Operating System Concepts》的 priority scheduling 一节）：静态优先级会让低优任务无限等待，**aging** 是教科书给出的标准补救 —— 等待时间折算成优先级增量。
- 推理侧：vLLM 提供 per-request `priority` 与按优先级排序的调度策略；连续批处理（Orca, OSDI '22）把「每步重新组批」变成常态，本文的准入循环正是这一层的抽象。
- `priority_cap` 对应工程上常见的「老化封顶」：没有上限时低优长尾请求会反超所有正常请求，反而破坏 SLO 分层。

## 核心与易错点

**有效优先级要在每次挑选时重算。** 同一步内可能连续发放多个名额，若在步首冻结一次，后一个名额仍会用旧值；本题里所有挑选共用同一个 `t`，但公式必须是用 `t` 代入而不是缓存结果。

**老化是整除，不是浮点。** `(t − arrivals[i]) // aging_interval`：等待不足一个间隔时增量为 0（示例 1 的步 1 中 r1 有效优先级仍是 1，不是 1.0 或 2）。

**打平的次序有三层。** 有效优先级 → 基础优先级 → 到达时刻 → 下标。示例 1 的步 5 正是靠第二层（基础优先级 5 > 0）让 r6 压过已经等满 5 档的 r1；示例 3 的步 0 靠第三、四层定 r0/r1。

**cap 会吃掉老化的效果。** 示例 2 里 `priority_cap = 5`，低优请求的有效优先级最多追平 5，而打平时基础优先级更高的人永远赢，于是它只能等请求流结束 —— 这说明「老化 + 无 headroom」等于没有老化。

**名额在本步末尾才释放。** 请求在第 t 步完成，第 t+1 步才能准入新请求（示例 3）。少写这一步，所有请求会早一步入选。

**空转必须跳时钟。** 第一个请求可能在很大的步号才到达，不能一步步空转。

**`finish` 是不变量。** `finish[i] = admit[i] + service[i] − 1` 恒成立；它同时校验了「服务连续占用、不被打断」这一点。

## 对拍口径

- 参考实现：`waiting` 集合 + `running` 字典（值为剩余服务步数），每步先补满名额再统一推进服务，空闲时用 `min(arrivals)` 跳时钟。
- 独立 oracle：按到达排序的 `pending` 列表 + `running` 列表 + `left` 数组；每次挑选用 `max()` 对 `(eff, base, −arrival, −index, i)` 元组求最大，是 `O(n²)` 的朴素写法，不排序也不建集合。
- 4000 组随机实例（`n ≤ 7`、到达 0–8、服务 1–4、优先级 0–5、名额 1–3、老化间隔 1–4、cap 随机高于最高优先级）上三元组逐位一致；另有 6 个手算场景（示例 1–3、无 headroom、老化间隔对比、打平、批量名额、空转跳步）与随机不变量（`admit >= arrival`、`finish == admit + service − 1`、任一步并发数 ≤ `max_batch`、`max_wait == max(admit − arrival)`）。

## 复杂度

- 每个名额一次 `O(n)` 扫描；总步数不超过 `Σ service[i] + max(arrivals)`，整体 `O(n × 总步数)`，`n ≤ 64` 时是毫秒级。
- 真实调度器用堆/有序树把单次选择降到 `O(log n)`，并按 aging 的档位做惰性重排。

- `inf-edf-deadline-scheduler`：按截止期（EDF）排序，是另一种抗饥饿思路 —— 用松弛度而不是等待时长。
- `inf-preempt-swap-recompute`：准入不进时的抢占决策，与本题的「排队顺序」互补。
- `inf-ttft-tpot-queue`：准入之后的 prefill/decode 时间线，本题只管谁先上前。

# 带老化的优先级准入调度

## 题目描述

推理服务通常按优先级分配名额：VIP 请求插队、批处理任务排在后面。但纯按优先级排序会**饿死**低优请求 —— 只要高优请求源源不断地来，低优请求永远等不到名额。

工业界的标准解法是 **aging（老化）**：请求每在队列里等够一段时间，有效优先级就涨一档，等得越久越接近队首，最终必然被服务。本题用一个整数步的调度器模拟这套规则：给定到达时刻、服务时长、基础优先级、名额上限、老化间隔与优先级上限，输出每个请求的准入步与完成步，以及最长的等待时间。

## 规则

时钟以整数步计，第 0 步是第一个时刻。

每一步的流程：

1. **准入**：空闲名额 = `max_batch − 正在跑的请求数`。在所有「已到达且尚未准入」的请求里逐个挑选，每次取**当前时刻 `t`** 下有效优先级最高者：

   ```
   有效优先级 = min(priority_cap, priority[i] + (t − arrivals[i]) // aging_interval)
   ```

   打平时依次比较：基础优先级高者优先 → 到达更早者优先 → 下标更小者优先。本步选中的请求从本步开始占用名额并执行服务。
2. **执行**：所有在跑的请求各消耗 1 步服务；服务在该步结束的请求于本步完成（完成步 = 本步），它让出的名额从**下一步**起可用。
3. **空转**：若没有请求在跑、也没有已到达的请求，把时钟直接推到下一个到达步，空转不产生任何账。

返回三元组：

- `admit`：每个请求的准入步（绝对步号）；
- `finish`：每个请求的完成步，恒等于 `admit[i] + service[i] − 1`；
- `max_wait`：所有请求里最大的「准入步 − 到达步」。

## 示例

**示例 1**（老化让低优请求反超）：`arrivals = [0, 0, 1, 2, 3, 4, 5, 6]`、`service = [1] * 8`、`priority = [5, 0, 5, 5, 5, 5, 5, 5]`、`max_batch = 1`、`aging_interval = 1`、`priority_cap = 9`

```
步 0  候选 r0(eff 5)、r1(eff 0)            -> r0
步 1  候选 r1(eff 1)、r2(eff 5)            -> r2
步 2  r1(eff 2)、r3(5)                     -> r3
步 3  r1(3)、r4(5)                         -> r4
步 4  r1(4)、r5(5)                         -> r5
步 5  r1(5)、r6(5)：打平，基础优先级 5 > 0  -> r6
步 6  r1(6)、r7(5)：老化的第 6 档反超      -> r1   <- 低优请求在这里被救出来
步 7  r7(5)                                -> r7
```

```
admit    = [0, 6, 1, 2, 3, 4, 5, 7]
finish   = [0, 6, 1, 2, 3, 4, 5, 7]
max_wait = 6                # r1 等到第 6 步；没有老化它会等满 7 步
```

**示例 2**（老化没有上升空间）：同一条请求流，但 `priority_cap = 5`（等于最高基础优先级）

```
步 5  r1(5)、r6(5)：打平，基础优先级高的 r6 赢
步 6  r1(5)、r7(5)：同上，r7 赢
步 7  r1(5)                                -> r1
```

```
admit    = [0, 7, 1, 2, 3, 4, 5, 6]
finish   = [0, 7, 1, 2, 3, 4, 5, 6]
max_wait = 7                # cap 封顶后老化永远追不上 5，只能等请求流结束
```

**示例 3**（两个名额 + 名额次步才能复用）：`arrivals = [0, 0, 0]`、`service = [4, 2, 2]`、`priority = [1, 1, 0]`、`max_batch = 2`、`aging_interval = 2`、`priority_cap = 3`

```
步 0  准入 r0、r1（r0/r1 有效优先级 1 打平，按下标；r2 只有 0）
步 1  r0 剩 3 步、r1 剩 1 步；无名额
步 2  r1 在步 1 完成，名额本步可用：r2 的有效优先级 = 0 + 2//2 = 1 -> 准入
步 3  r0 与 r2 同时完成
```

```
admit    = [0, 0, 2]
finish   = [3, 1, 3]
max_wait = 2
```

## 约束

- 请求数 `n <= 64`；`arrivals[i] >= 0` 允许重复与乱序；`service[i] >= 1`；`priority[i] >= 0`。
- `max_batch >= 1`、`aging_interval >= 1`、`priority_cap >= max(priority)`。
- 有效优先级在**每次挑选时**按当前时刻重算，不是每步开头算一次就冻结。
- 返回的两个列表与一个整数都是 Python `int`；判题只看数值，不限定调度循环的写法。

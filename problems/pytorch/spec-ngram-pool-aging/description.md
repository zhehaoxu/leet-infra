# 推测解码：n-gram 池的容量淘汰与老化

## 题目描述

Lookahead 解码、prompt lookup decoding、n-gram 投机这些「不训练草稿模型」的方法，都靠一张从语料里现攒的 n-gram 表：用最近 \(n\) 个 token 当 key，查表得到最常见（或最近出现）的后继当作草稿。模型越跑越长，这张表也会一直膨胀，所以工程上必须给它一个**容量上限**和一套**淘汰规则**。这套规则写错的代价很直接：把高频、稳定的 n-gram 淘汰掉，命中率断崖式下跌；只按「最近使用」淘汰，稀疏但正确的新 n-gram 又永远进不来。

本题把决策拆成三部分，都是可判的整数/布尔行为：

1. **预测**：命中时取该 key 下计数最多的后继；并列时取更小的 token id（保证确定性）。
2. **学习**：未命中就用「当步真实 token」现场插入这条 n-gram——注意强化的是真实 token，而不是自己猜出来的那个，否则错误会被固化成高频。
3. **淘汰**：池中 key 数超过 `capacity` 时，淘汰 `(总计数, 最近使用时间, key 字典序)` 最小者。**总计数优先**保证高频 n-gram 不被一次性新 key 挤掉；时间戳作为老化项处理「计数相同」的陈旧条目。

时间戳用一个全局单调时钟：初始语料按位置顺序插入，之后每次插入/强化都 +1。这样「更旧」永远有唯一答案。

## 任务

实现 `solve(prompt, observed, n, capacity)`：

- 输入：`prompt`（`(L,)` int64，初始语料，\(L\ge n+1\)）；`observed`（`(S,)` int64，逐步给出的真实 token，可为空）；`n`（key 长度，\(\ge 1\)）；`capacity`（key 数上限，\(\ge 1\)）。
- 流程：先用 `prompt` 切出所有 n-gram 并裁到容量，然后对 `observed` 逐步做「查表预测 → 用真实 token 强化或插入 → 裁剪」。
- 输出：
  - `predicted`（`(S,)` int64）：命中时的预测 token，未命中记 `-1`；
  - `hits`（`(S,)` bool）：是否命中；
  - `size`（`(S,)` int64）：当步裁剪后的 key 数；
  - `evicted`（`(S,)` int64）：当步淘汰了多少个 key。
- `n < 1`、`capacity < 1`、`prompt` 长度不足 \(n+1\)、任一输入非一维，抛 `ValueError`。

## 示例

```
prompt = [1,2,3,1,2,3]，n = 2，capacity = 4
初始池：(1,2)->{3:2}   (2,3)->{1:1}   (3,1)->{2:1}       size = 3

observed = [3, 1, 9, 3, 4]

步 0  key=(2,3) 命中 -> 预测 1；强化 (2,3)[3]，size 3
步 1  key=(3,3) 未命中 -> -1；插入 (3,3)->1，size 4
步 2  key=(3,1) 命中 -> 预测 2；强化 (3,1)[9]，size 4
步 3  key=(1,9) 未命中 -> -1；插入 (1,9)->3 后 size 5 > 4
      -> 淘汰 (3,3)（总计数 1、时间戳最旧）  size 4，evicted 1
步 4  key=(9,3) 未命中 -> -1；插入后 size 5 > 4
      -> 淘汰 (1,9)（总计数 1、时间戳次旧）  size 4，evicted 1

predicted = [1, -1, 2, -1, -1]
hits      = [T,  F, T,  F,  F]
size      = [3, 4, 4, 4, 4]
evicted   = [0, 0, 0, 1, 1]
```

## 约束

- **强化用真实 token**：命中时把 `observed` 的 token 计入该 key 的计数表；若强化成自己预测的那个 token，错误预测会自我强化，命中率越跑越高但质量越来越差。
- **淘汰是三元组比较**：总计数最小优先，其次时间戳更旧，最后 key 字典序更小。只比时间戳会退化成纯 LRU，高频 n-gram 一次冷落就被踢掉。
- **裁剪要在初始化之后也做一次**：初始语料可能远超容量，第一帧的 `size` 不能是原始条目数。
- **未命中的 key 也要插入**：本题把「未命中」当作学习机会，逻辑上等价于在线更新 n-gram 表；否则新上下文永远进不了池。
- **`predicted` 在未命中时是 `-1`**，与「预测了 token id = -1」区分开；token id 在本题中非负。

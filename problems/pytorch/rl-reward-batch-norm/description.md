# RL 基建：奖励归一化的批统计管道

## 题目描述

奖励数值本身没有刻度：RM 输出可以是 $[-3,7]$ 也可以是 $[10^3,10^4]$，直接把原始奖励喂进策略梯度会让梯度尺度随奖励模型漂移。于是 RLHF 训练器在奖励后面挂了一段**归一化管道**：running mean/var 的 EMA 账本、"用批统计 / 用组统计 / 用账本统计"的开关、以及"只去均值 / 连标准差一起白化"的开关。OpenRLHF 的 `reward_norm` 有 `prompt/group/running_state/batch/none` 五档可选并维护一个 `RunningMoments`，verl 侧也有类似的 advantage/reward 归一化开关——**机制相同，坑也相同**：选错统计源或搞错更新顺序，输出尺度就会静默偏离 1，训练不发散但收敛得很慢，很难查。

本题不推导任何损失或优势公式（那是 `to-grpo-advantage` / `to-gae` 的事），只把这段管道当作**数据流系统**复现出来：给定一串按到达顺序排好的奖励批，算出归一化结果、账本历史，以及一个能暴露"尺度失配"的探针。

## 规则

输入六个量：

| 名称 | 类型 | 含义 |
|---|---|---|
| `reward_batches` | float $(T,B)$ | 按到达顺序排好的 $T$ 个批，每批 $B$ 条奖励 |
| `group_ids` | int64 $(B,)$ | 批内每条奖励所属的 prompt 组号（各批复用同一组号） |
| `stat_source` | 0 / 1 / 2 | 统计来源：0=本批全局、1=running 账本、2=批内组统计 |
| `momentum` | float $\in[0,1]$ | EMA 系数（**PyTorch BatchNorm 口径**：$r\leftarrow(1-m)r+m\,x$） |
| `whiten_std` | 0 / 1 | 1=减均值再除标准差；0=只减均值 |
| `eps` | float $>0$ | 加在方差上再开方的数值项 |

按 $t=0,1,\dots,T-1$ **顺序**处理每个批：

1. 按 `stat_source` 选出**用于本批归一化**的均值/方差：
   - `0`：本批全局均值与总体方差（ddof=0）；
   - `1`：账本里**本批更新之前**的值 `running_mean[t]`、`running_var[t]`（初值 $0.0$ / $1.0$，同 BatchNorm）；
   - `2`：本批内**组统计**——同一 `group_ids` 的条目用该组的组内均值/组内总体方差。
2. $\text{centered}=x-\mu_{\text{sel}}$；`whiten_std==1` 时再除以 $\sqrt{\text{var}_{\text{sel}}+eps}$，否则原样输出。
3. 算探针 `out_rms[t]` $=\sqrt{\operatorname{mean}(\text{normalized}[t]^2)}$（真被白化成单位尺度时它 $\approx 1$）。
4. 最后用**本批全局**均值与总体方差更新账本：`running_mean[t+1] = (1-m)·running_mean[t] + m·批均值`，方差同理。
   注意：**账本始终由批全局统计驱动**，与 `stat_source` 无关（开关只决定"拿什么来归一化"，不决定"往账本里写什么"）。

返回四元组（均 float32）：`normalized` $(T,B)$、`out_rms` $(T,)$、`running_mean` $(T+1,)$、`running_var` $(T+1,)$。`running_*` 的第 $0$ 项是初值 $0.0/1.0$，第 $t+1$ 项是第 $t$ 批更新**之后**的状态——这样"用了什么"和"写了什么"在同一条时间轴上一眼可见。

## 示例

`reward_batches=[[1,2,3,4],[2,3,4,5],[10,20,30,40]]`、`group_ids=[0,0,1,1]`、`momentum=0.5`、`whiten_std=1`、`eps=1e-5`：

`stat_source=0`（批全局，最标准的做法）：

```
normalized   = [[-1.341635, -0.447212,  0.447212,  1.341635],
                [-1.341635, -0.447212,  0.447212,  1.341635],
                [-1.341641, -0.447214,  0.447214,  1.341641]]
out_rms      = [0.999996, 0.999996, 1.0]          # 每批都被白化到单位尺度
running_mean = [0.0, 1.25, 2.375, 13.6875]        # 初值 0 → EMA 追踪 (2.5, 3.5, 25)
running_var  = [1.0, 1.125, 1.1875, 63.09375]    # 初值 1 → EMA 追踪 (1.25, 1.25, 125)
```

同一批数据换成 `stat_source=1`（用账本，也就是"用旧统计量归一化新数据"）：

```
normalized[0] = [0.999995, 1.99999, 2.999985, 3.99998]        # 第一个批次等于没归一化
normalized[2] = [6.99715, 16.17374, 25.350332, 34.526924]     # 奖励跳到 10~40，账本方差还停在 1.19
out_rms       = [2.738599, 2.368768, 23.15868]                # 尺度失配 23 倍，探针直接报警
```

换成 `stat_source=2`（组内统计，GRPO 的来源选择）：每组两条，组均值/组方差把每条压成 $\pm1$：

```
normalized   = [[-0.99998, 0.99998, -0.99998, 0.99998], ...]
out_rms      = [0.99998, 0.99998, 1.0]
```

`momentum=0.0` 且 `stat_source=1` 时账本被冻在 $(0,1)$，输出恒等于原始奖励（除了 $1/\sqrt{1+eps}$ 的微小缩放），`out_rms` 一路走高——这就是"忘开更新 / 系数写反"的事故现场。

## 约束

- CPU float32 输入、float32 输出（内部建议 float64 累加）；$1\le T\le 64$、$1\le B\le 256$；`eps > 0`；`momentum ∈ [0,1]`。
- 方差一律**总体**口径（除 $n$ 不除 $n-1$）；标准差 $=\sqrt{\text{var}+eps}$。
- 判定：`normalized`、`out_rms`、`running_mean`、`running_var` 用 `allclose(atol=1e-5, rtol=1e-5)`。
- 退化不变量：`whiten_std=0` ⇒ 输出恰好是"减均值"（用 `stat_source=0` 时每批均值为 $0$）；组内奖励全相等 ⇒ 该组输出为 $0$（分子为 $0$，`eps>0` 保证不除零）；`momentum=1` ⇒ 账本恰为上一批的批统计；`momentum=0` ⇒ 账本恒为初值。
- 分工：`to-grpo-advantage` 推导的是「组内标准化成优势」这条**公式**（单一来源、单批）；`to-gae` 是优势递推；`rl-trajectory-episode-assembly` 管奖励张量的拼装。本题只管**统计量从哪来、什么时候更新、更新顺序在归一化之前还是之后**，即管道记账本身。

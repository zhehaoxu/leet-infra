## Mechanism highlights

- `stabilized_step`: `m_new = max(log_fg_act + m_prev, i)` is a log-sum-exp stabilizer, **not `logaddexp`**, so `fg_act + ig_act` need not equal 1; `C_new` is a `DH x DH` matrix memory whose outer product is `k_scaled[a] * v[b]` and must not be transposed; `h_num` takes `q.T @ C_new` by column; `h_denom = max(|qn|, exp(-m_new)) + eps` has its lower bound set by `m_new` rather than plain `|qn|`, and `eps` is outside `max(...)`.
- `parallel_decay`: `cumsum = [0] + prefix_sum(log_fg)` followed by the `[1:,1:]` offset gives `log_fg_matrix[t][j] = cumsum[t+1] - cumsum[j+1]` (excluding the forget gate at j itself), with `j > t` set to `-inf`; `igate_preact.T` broadcasts by column adding `i[j]`, not `i[t]`; `stabilize_rowwise` selects a per-row max or one global max; `-inf` entries of `D` become `0.0` through `exp`; `normalizer = max(|C.sum|, exp(-max_log_D))` and `h_tilde = (C / (normalizer + eps)) @ v`.
- `chunk_intra_gates`: `log_fgates_acc` is an **inclusive cumsum inside each chunk**, restarting from 0 for every chunk; in `base = i - acc + acc[-1]` the `+acc[-1]` cancels with `m_loc` and only affects the returned `m_loc`, so it must not be dropped; `m_loc` is a chunk-level max over the CS dimension, a different level from the per-token `m_new` of mode 1; `kv = k.T @ (v * exp(loggates))` and `ksum = (k * exp(loggates)).sum(CS)` use only `k` with no scaling, and `q` does not participate in any of the 5 returned values; `S` must be divisible by `chunk_size`.
- Global conventions: `logsigmoid(x) = -softplus(-x)` is computed piecewise to avoid overflow; `eps` is always outside the denominator; all inputs q/k/v/i/f are explicit arguments, a pure Python numeric ledger with no `xlstm` import and no real model.

## Test design

- Three `check_*` functions (`check_stabilized_step` / `check_parallel_decay` / `check_chunk_intra_gates`), each with an independent pure-Python oracle (no import of solution) + grid cross-check (160 + 160 + 160) + hand-computed anchors (4 + 3 + 4).
- The anchors deliberately pin every classic trap: both branches of `m_new = max` (including the first-branch tie), `sqrt(DH)` scaling, outer-product direction, column-wise `h_num`, the `max / abs / eps` and lower bound of `h_denom`, the leading zero of the cumsum and the `[1:,1:]` offset, `-inf` becoming 0, column-wise igate broadcast, both `stabilize_rowwise` paths, the `normalizer` lower bound `exp(-max_log_D)`, in-chunk cumsum restart, `+acc[-1]` changing only `m_loc`, chunk-level `m_loc` (0 and 10 for two chunks), `kv[a][b]` direction, `ksum` over the CS dimension, and `chunk_size=1`.
- All four defaults (`m_prev` / `eps` / `stabilize_rowwise` / `chunk_size`) have separate anchors that omit the parameter; otherwise mutants changing those defaults would go undetected.
- The formal selftest uses `scripts/add_problem.py --selftest <slug> --mode run|submit` in both modes. The judge environment has only torch + numpy; this problem is a pure Python numeric ledger and needs no torch.

## Mutation design

- `/tmp/mut837.py` first self-checks the correct solution in both `run` / `submit` modes (3/3 ACCEPTED) — the lesson from 836 is that a green mutation run cannot replace a self-check of the correct solution — then runs **57 single-point mutants, all 57 CAUGHT on the first round, 0 SURVIVED**, with zero anchor-count errors.
- Mutants cover: replacing `m_new` with `logaddexp` or dropping `m_prev`, swapping `fg_act / ig_act`, dropping the `sqrt(DH)` from `k_scaled`, transposing the outer product, row-wise `h_num`, removing `abs` / the `exp(-m_new)` bound from `h_denom`, putting `eps` in the numerator, dropping the leading cumsum zero, wrong `[1:,1:]` offset, turning `-inf` into 1, row-wise igate broadcast, flipping the `stabilize_rowwise` default, dropping the `normalizer` bound, not restarting the in-chunk cumsum, deleting `+acc[-1]`, using a global max for `m_loc`, using `q` or omitting `exp(loggates)` in `kv / ksum`, and handling an `S % CS` remainder.
- The first round was fully green because the 836 lesson was applied up front: the anchors already covered every default value and every strict-vs-non-strict boundary, every mutant died on an assertion rather than a shape crash, and genuinely equivalent mutants (e.g. equivalent spellings of the `max` tie) were removed while writing the mutation script.

## De-duplication boundaries

- Clearly separated from `la-gla-chunked` (chunk-parallel vs recurrent identity under per-key-channel log decay), `la-gated-deltanet-recurrent` (`v' = (v - h*k)*beta` delta-rule matrix update), `la-mamba-selective-scan` (ZOH scalar SSM), and `la-rwkv-channel-decay` (WKV vector recurrence). This problem **judges no identity among the three forms, no delta rule, and no matrix-memory equivalence**; it takes only the three mLSTM-specific intermediate sets: stabilized gating, the parallel D matrix, and intra-chunk gates.
- No overlap with KV compression in `context-compression`, diffusion scheduler ledgers, or data-tokenization segmentation ledgers. The `context-compression / SnapKV` direction was ruled out entirely because `kv-snapkv-pooling` already occupies it.
- Out of scope: `mLSTMCell` `nn.Linear` projections (igate/fgate weights), `MultiHeadLayerNorm` and multi-head projections, real forward passes and sampling, Triton/CUDA kernels, the inter-chunk `C/n/m` state and `intra + inter` composition of `chunkwise_simple`, and the random / linspace initialization of `bias_linspace_init_` / `small_init_init_` / `wang_init_`.

# 评测：nDCG@k（折损累积增益）

## 题目描述

排序类任务（RAG 召回、搜索、reranker、推荐）不能用 token 准确率打分：第 1 名排错和第 10 名排错的代价完全不同，而且相关性是**分级**的（0=无关、3=完美答案）。nDCG（Järvelin & Kekäläinen, 2002）把这两件事同时写进公式：先给每个名次一个**增益**（由标注分决定）、再乘一个随名次衰减的**折损**，累加成 DCG；最后除以"理想排序"的 IDCG，把分数归一到 \([0, 1]\)，从而能在不同 query、不同候选池大小之间横向比较。

它是 RAG 评测的事实标准，也是 BEIR / MTEB 榜单里 reranker 与 dense retriever 的主指标。注意它和 RRF（`retrieval-rrf-fusion`）的分工：RRF 是**融合**算法，只吃名次、不吃分级标注，输出一个新的排序；nDCG 是**评价**指标，吃分级标注，输出一个分数。

## 规则

- 输入是 \(N\) 篇候选文档，文档 id 就是它们在下述列表里的**下标**。
- `scores`：`list[float]`，排序模型给出的打分（可正可负，只用于比较大小）。
- `rels`：`list[int]`，与 `scores` 一一对应的分级相关性标注，非负整数，越大越相关。
- `k`：截断位置。实际参与计算的名次数为 \(m = \min(k, N)\)；\(k > N\) 等价于 \(k = N\)。
- 排序：按 `scores` **降序**。分数相同的文档按**下标升序**（稳定 tie-break），因此结果与"谁先进列表"无关，只与下标有关。
- 增益（由显式开关 `exp_gain` 决定，默认指数式）：
  \[
  g(r) = 2^{r} - 1 \quad (\text{指数增益，强调高档标注})\qquad
  g(r) = r \quad (\text{线性增益})
  \]
- 折损：名次 \(i\) 从 **1** 开始计数，折损因子为 \(1 / \log_2(i + 1)\)。于是第 1 位折损是 \(1/\log_2 2 = 1\)（不打折），第 2 位是 \(1/\log_2 3 \approx 0.6309\)。
- 累积增益：
  \[
  \text{DCG} @ m = \sum_{i=1}^{m} \frac{g(r_{\pi(i)})}{\log_2(i+1)},
  \qquad
  \text{IDCG} @ m = \sum_{i=1}^{m} \frac{g(r_{\sigma(i)})}{\log_2(i+1)}
  \]
  其中 \(\pi\) 是模型排序后的标注序列，\(\sigma\) 是把 `rels` 按**降序**重排（理想排序）后的序列——理想排序只需要对标注排序，打分是什么都不影响 IDCG。
- 归一化与哨兵：
  \[
  \text{nDCG} @ k = \begin{cases} \text{DCG} / \text{IDCG}, & \text{IDCG} > 0 \\ 0.0, & \text{IDCG} = 0 \end{cases}
  \]
  \(\text{IDCG} = 0\) 出现在"所有标注都是 0"或"没有候选 / \(k \le 0\)"两种情况；此时 nDCG 定义为 **0.0**（不是 NaN，也不是 1.0），DCG 本身也必然是 \(0\)。
- 返回三元组 `(ndcg, dcg, idcg)`，都是 Python float。IDCG 用**同一个** \(m\) 与同一套增益/折损公式，所以 \(0 \le \text{nDCG} \le 1\) 恒成立。禁止使用 `sklearn`（判题环境里也没有）。

## 示例

```
scores = [0.10, 0.85, 0.40, 0.85, 0.25, 0.60]
rels   = [  0,    3,    2,    1,    2,    3]
k = 4, exp_gain = True

文档下标:      0     1     2     3     4     5
打分:        0.10  0.85  0.40  0.85  0.25  0.60
名次:          6     1     4     2     5     3
0.85 出现两次（文档 1 与文档 3）=> 按下标升序，文档 1 拿第 1 名、文档 3 拿第 2 名。
模型排序 = [1, 3, 5, 2 | 4, 0]，前 4 位标注 = [3, 1, 3, 2]

名次 i :    1        2         3       4
标注    :    3        1         3       2
增益 2^r-1:  7        1         7       3
折损      : 1/log2 2  1/log2 3  1/log2 4  1/log2 5   = 1, 0.630930, 0.5, 0.430677
各项      : 7.0      0.630930  3.5      1.292030
DCG@4 = 12.422959

理想排序的标注 = [3, 3, 2, 2, 1, 0]，前 4 位增益 = [7, 7, 3, 3]
各项      : 7.0      4.416512  1.5      1.292030
IDCG@4 = 14.208538

nDCG@4 = 12.422959 / 14.208538 = 0.874331
```

同一份数据换线性增益（`exp_gain = False`）：

```
增益 = r：  DCG  = 3 + 1(0.630930) + 3(0.5) + 2(0.430677) = 5.992283
           IDCG = 3 + 3(0.630930) + 2(0.5) + 2(0.430677) = 6.754142
           nDCG = 0.887201
```

平局很贵：如果实现把文档 3（标注 1）排在文档 1（标注 3）之前，DCG 会掉到 \(10.208538\)、nDCG 变成 \(0.718479\)——一次 tie-break 写错就是 **15.6 个点**。

## 约束

- CPU；`scores` 与 `rels` 等长；\(N \le 10^4\)（允许 \(N = 0\)）。
- \(0 \le \text{nDCG} \le 1\)；nDCG 与 \(k\) **不单调**（截断更短时 IDCG 也变短），但 DCG 与 IDCG 对固定的理想序列随 \(m\) 单调不减。
- **退化性质**：模型排序与理想排序一致 ⇒ nDCG = 1；所有标注为 0 ⇒ `(0.0, 0.0, 0.0)`；`k >= N` ⇒ 用整份列表；`k = 1` 且 top-1 是最相关文档之一 ⇒ nDCG = 1；对打分做任意**严格递增**变换（加常数、乘正数、过一层 sigmoid）都不改变名次，因而分数完全不变——nDCG 只看序，不看分值。
- 与 `retrieval-rrf-fusion` 的区别：那个问题的输入是**多个系统的排名列表**、无分级标注、目标是产出一个融合排序；本题输入是**单个排序 + 人工标注**、目标是产出一个分数。

# 详解：2:4 稀疏元数据（metadata）打包

## 出处
2:4 半结构化稀疏的存储格式出自 NVIDIA Ampere 架构的 Sparse Tensor Core 文档与 cuSPARSELt / CUTLASS 的实现：压缩值 + 每 4 元素组 4 bit 元数据，元数据行按 32-bit 对齐。本合集里 `sparsity-nm-2-4` 只决定「每组留哪两个」（掩码层面），本题决定「留下的两个怎么描述给硬件」（布局层面）——两者是同一条链路的前后两段。

## 核心与易错点
1. **描述符公式**：\(\text{nib}=i_0+((i_1-1)\ll2)\)。低 2 位是第一个非零的**绝对**索引（0–2，不可能为 3），高 2 位是第二个非零的**相对偏移**（\(i_1-1\in\{0,1,2\}\)）。把高 2 位写成 \(i_1\) 会让 \(i_1=3\) 溢出到 bit4、污染下一个 nibble。
2. **升序存放**：`values` 与描述符都以 \(i_0<i_1\) 的顺序排列；先取到的必须是索引更小的那个。用 `argsort((g==0))` 这类稳定排序可以一次拿到升序位置，且天然把非零排在前面。
3. **行的补零对齐**：\(G\) 不一定是 8 的倍数。补的是**每行末尾**的 nibble，不是整个张量的末尾；\(G=3\) 时 \(P=8\)，第四个位置之后的 5 个 nibble 必须为 0。
4. **字节内顺序**：偶数组的 nibble 在低 4 位。写反（高 nibble 放第 \(2j\) 组）会导致解码时索引错位，肉眼很难发现。
5. **不要用浮点比较判非零以外的信息**：`-0.0` 视为 0；本格式只依赖「是否非零」，不依赖数值大小。

## 对拍口径
参考解用 `reshape(R, G, 4)` + `argsort((g==0), stable=True)[:,:,:2]` 取两个升序位置、`gather` 出压缩值，再算 nibble、补零、按奇偶打包成 uint8。判题 `_oracle` 用纯 Python 逐组扫描 `!= 0.0` 记录位置、手工拼字节，逐位对拍 `values` 与 `meta`。额外断言：把 `values` + `meta` 解码回稠密矩阵必须与原矩阵逐位相等（判题侧独立实现解码器）；\(G=3\) 时第 3 组之后 nibble 全 0；字节数对齐表（\(K=4,8,32\to4\) 字节，\(K=36,64\to8\) 字节）；组内升序；最靠后的组合 \(i_0=2,i_1=3\) 编成 nib=10（于是 byte=10）。

## 复杂度
\(O(RK)\)（每元素一次分类计数）；输出规模为 \(RK/2\) 个值 + \(RK/8\) 字节元数据。

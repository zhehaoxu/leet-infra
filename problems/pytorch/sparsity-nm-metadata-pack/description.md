# 稀疏化：2:4 稀疏元数据（metadata）打包

## 题目描述

NVIDIA Ampere 起的 Sparse Tensor Core 只吃 **2:4** 半结构化权重：每 4 个连续元素里恰好 2 个非零。硬件并不读原始稠密矩阵，而是读两份数据：

- **压缩值**：把每组里留下的 2 个值紧排成一条向量，长度是原来的一半；
- **元数据（metadata）**：告诉硬件「这 2 个值原本在组内的哪两个位置」。

元数据按组用 **4 bit** 编码：组内索引 \(i_0<i_1\in\{0,1,2,3\}\) 时，低 2 位存 \(i_0\)（取值 0–2），高 2 位存 \(i_1-1\)（取值 0–2）——这样 16 种 4-bit 码恰好一一对应「从 4 个位置里选 2 个」的 6 种组合（其余码值不用）。nibble 再两两拼成 byte（第偶数个组在低 4 位），并且每行的 nibble 数要对齐到 **8 的倍数**（即 4 字节 / 一个 32-bit 字），不足的补 0，这样每行的元数据起点总是 32-bit 对齐的。

本题只做编码：给定一个已经满足 2:4 约束的权重矩阵，产出 `values` 与 `meta`，不涉及 GEMM。

## 规则

给定 `weight`（float32，\((R,K)\)，\(K\%4=0\)，每一组 4 个连续元素中恰好 2 个非零，非零判据为 `!= 0.0`）：

1. 沿最后一维以 4 为一组切分，共 \(G=K/4\) 组；
2. `values`：每组内按**索引升序**取两个非零值，拼成 \((R,2G)=(R,K/2)\)；
3. 每组计算 4-bit 描述符 \(\text{nib}=i_0\,|\,((i_1-1)\ll2)\)；
4. 每行 nibble 数补零到 \(P=\lceil G/8\rceil\times8\)；
5. 两两打包成 byte：`byte[j] = nib[2j] | (nib[2j+1] << 4)`，得到 `meta`（uint8，\((R,P/2)\)）。

返回 `(values, meta)`。禁止 `torch.sparse` / cuSPARSELt。

## 示例

**例 1**：`K=8`（两组），一组内非零位置分别是 \(\{1,2\}\) 与 \(\{0,3\}\)

```
weight = [[0, 3, -2, 0,  5, 0, 0, 7]]

组0 非零在 i0=1, i1=2 → nib = 1 | ((2-1)<<2) = 1 | 4  = 5
组1 非零在 i0=0, i1=3 → nib = 0 | ((3-1)<<2) = 0 | 8  = 8

values = [[3, -2, 5, 7]]
G=2 → P=8 个 nibble（补 6 个 0）→ 4 个 byte
byte0 = 5 | (8 << 4) = 5 + 128 = 133
meta  = [[133, 0, 0, 0]]
```

**例 2**：`K=12`（三组，第三组填进 byte1 的低 nibble，其余补零）

```
weight = [[1, 0, 0, 2,  0, 3, 4, 0,  5, 6, 0, 0]]
nib    = [8, 5, 0]        # 0|2<<2, 1|1<<2, 0|0<<2
byte0  = 8 | (5 << 4) = 88
values = [[1, 2, 3, 4, 5, 6]]
meta   = [[88, 0, 0, 0]]
```

## 约束

- CPU float32 输入、uint8 输出；每组**恰好** 2 个非零。
- 补位 nibble 必须为 0，且每行字节数恒为 \(P/2\)（\(G=1\ldots8\) 时 4 字节，\(G=9\ldots16\) 时 8 字节）。
- 低 nibble 在前：第 \(2j\) 组在 `byte[j]` 的低 4 位。
- 用 `values` + `meta` 必须能无损还原原矩阵。

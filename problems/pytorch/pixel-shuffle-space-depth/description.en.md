# pixel_shuffle and space-to-depth/depth-to-space

## Problem

Sub-pixel convolution (ESPCN, Shi et al., CVPR 2016) upsamples by trading channels for resolution: a \((N, C\cdot r^2, H, W)\) feature map is periodically rearranged into \((N, C, H\cdot r, W\cdot r)\) — pixel_shuffle; the reverse packs spatial blocks back into channels (space-to-depth / pixel_unshuffle). This pair of **bijective rearrangements** underlies super-resolution heads and focus-style backbones: the volume never changes, every element merely changes address. Implement four modes behind one entry point — shuffle / unshuffle / s2d / d2s — using view/reshape/permute or explicit indexing only (**calling F.pixel_shuffle / F.pixel_unshuffle is forbidden**), with s2d ≡ `F.pixel_unshuffle` and d2s ≡ `F.pixel_shuffle` pinned at `torch.equal` level. CPU, float32/float64, fully deterministic.

## Rules

- The full signature, parameter meanings and defaults live only in the starter's docstring; that is the single judging standard. x is a 4-D \((N,C,H,W)\) float tensor (non-4-D raises `ValueError`); r is the scale factor (non-int — including float and bool — or \(r<1\) raises `ValueError`); mode takes exactly one of the following, anything else raises `ValueError`.
- **shuffle**: \((N, C\cdot r^2, H, W)\to(N, C, H\cdot r, W\cdot r)\). Semantics of `F.pixel_shuffle`: \(out[n,\,c,\,h\cdot r+i,\,w\cdot r+j]=x[n,\,c\cdot r^2+i\cdot r+j,\,h,\,w]\) (\(0\le i,j<r\)). If the channel count is not divisible by \(r^2\), raise `ValueError` (spatial dims only grow, no divisibility requirement).
- **unshuffle**: the inverse of shuffle, \((N,C,H,W)\to(N, C\cdot r^2, H/r, W/r)\). Semantics of `F.pixel_unshuffle`: \(out[n,\,c\cdot r^2+i\cdot r+j,\,h,\,w]=x[n,\,c,\,h\cdot r+i,\,w\cdot r+j]\). If H or W is not divisible by r, raise `ValueError`.
- **s2d**: space-to-depth; the shape contract and divisibility requirements match unshuffle; in the channels-first layout it is exactly equivalent to `F.pixel_unshuffle` (the output channel order is the same \(c\cdot r^2+i\cdot r+j\), pinned by the tests with `torch.equal`).
- **d2s**: the inverse of s2d, exactly equivalent to `F.pixel_shuffle`, with the same channel-divisibility constraint as shuffle.
- **Implementation constraint (the point of this problem)**: do not call `F.pixel_shuffle` / `F.pixel_unshuffle`; the bijection must be built from view/reshape/permute or explicit indexing.
- Other conventions: at r==1 all four modes are strict identities (`torch.equal(y,x)`); round-trip identities unshuffle(shuffle(x))==x and d2s(s2d(x))==x (`torch.equal`); non-contiguous inputs (e.g. views from transpose) are allowed and must give results identical to the same-valued contiguous input; the returned tensor has x's dtype and the input is never modified.

## Example

Main example (values from the `EXAMPLE_*` constants in test_cases): x \((1,4,2,2)\) whose four channels are \(\begin{bmatrix}1&2\\3&4\end{bmatrix}\), \(\begin{bmatrix}5&6\\7&8\end{bmatrix}\), \(\begin{bmatrix}9&10\\11&12\end{bmatrix}\), \(\begin{bmatrix}13&14\\15&16\end{bmatrix}\), with r=2, mode=shuffle, output \((1,1,4,4)\):

\[\begin{bmatrix}1&5&2&6\\9&13&10&14\\3&7&4&8\\11&15&12&16\end{bmatrix}\]

The reading rule is the handwritten convention \(out[2h+i][2w+j]=ch[i\cdot2+j][h][w]\): row 0 interleaves row 0 of channels 0/1 (\([1,2]\) and \([5,6]\) woven into \([1,5,2,6]\)), row 1 comes from row 0 of channels 2/3, row 2 returns to row 1 of channels 0/1 — channels are laid out in the "row before column" order inside each block. The same input with mode=s2d: output \((1,16,1,1)\), whose 16 channels are exactly \(1,2,\dots,16\) in the \(c\cdot4+i\cdot2+j\) order (bit-for-bit identical to unshuffle); unshuffle/d2s walk back and restore the outputs of shuffle/s2d exactly.

## Constraints

- r must be an int and \(\ge1\) (bool is not a valid r); the divisibility checks are side-specific: shuffle/d2s check channels \(C\bmod r^2\), unshuffle/s2d check H and W \(\bmod r\); unknown mode and non-4-D input always raise `ValueError`.
- Cross-check: over 6 \((n,c,h,w,r)\) configurations, `torch.equal` bit-for-bit against `F.pixel_shuffle` / `F.pixel_unshuffle` (all four modes checked on the same configurations, including \(r=1,2,3\), batch>1, non-square spatial dims); an independent quadruple-loop oracle computes the source index per target coordinate, on a separate path from the vectorized reshape/permute; a bijection assert (the output is a permutation of the input: equal sorted flattened values); round-trip and r=1 identities (`torch.equal`); transpose non-contiguous views give `torch.equal` results vs contiguous inputs.
- A pure rearrangement has no floating-point error, so the judge uses `torch.equal` throughout instead of allclose; test data is generated by golden-ratio hashing (no RNG).

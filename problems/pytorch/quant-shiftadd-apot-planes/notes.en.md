# Solutions · ShiftAddLLM Bit-Plane Scales as Additive Powers of Two

## Sources

- **ShiftAddLLM: Accelerating Pretrained LLMs via Post-Training Multiplication-Less Reparameterization** (You, Guo, Fu, Zhou, Shi, Zhang, Kundu, Yazdanbakhsh, Lin; Georgia Tech / Intel Labs / Google / Google DeepMind; NeurIPS 2024, **arXiv:2406.05981**, repository `GATECH-EIC/ShiftAddLLM`): replaces multiplication in pretrained weights with "select the plane by sign, shift, add", where ApOT (additive powers of two) makes each plane's scalar itself a short sum of powers of two.
- The formulas here are transcribed line by line from `quantizers/bcq_quant/bcq_shift.py` in that repository (line numbers re-verified against a local tarball on 2026-10-30):
  - `get_shift_and_sign` **L15-24**: `sign = torch.sign(x)` and `shift = round(log(|x|)/np.log(2))`, with `rounding` defaulting to `deterministic`, i.e. `x.round()` - **half-to-even**.
  - `round_power_of_2` **L26-39**: with both `q_bias` and `scale` set to `None` only `(2.0 ** shift) * sign` survives.
  - `additive_power_of_2` **L41-48**: the first term is `x_rounded = 2**shift * sign`, then `nums-1` further terms are each taken from `x - x_rounded` - the **residual against the sum already submitted** - and accumulated.
  - `greedy_mean_torch` **L131-161**: `b = r.sign()`, `alpha = (r.abs()*wf).sum(dim=1)/torch.sum(wf, dim=1)`, `r -= b*alpha`; in the `wf is not None` branch nothing is power-of-two rounded when `shift=False`.
  - `quantize_shift` **L106-107 / L109-110 / L115**: `group_size = group_size if group_size > 0 else orig_shape[-1]`, `w_ = w_.view([-1, group_size])`, `wf = torch.ones(w_.shape)`, and finally `ret = torch.einsum('ijl,il->ij', (B, alpha))`.
- **Repository status**: the top of `README.md` states the repository is no longer maintained and points at `ShiftAddQwen` as the follow-up work (different fitting pipeline and LUT-free kernels, same binary-plane weight format), but it remains the reference implementation of the NeurIPS 2024 paper, and all four functions this problem needs are present verbatim in `bcq_shift.py`.

## Source transcriptions and deliberate simplifications

- **Upstream reaches ApOT only inside the refinement; wiring it onto the greedy scales is this exercise's composition.** The only call site of `additive_power_of_2` in the repository is `refine_mean_torch` **L177**, and what it receives is `Alpha_new` solved by `batch_cg_torch` and then `abs().sort(descending=True)` (L175). Neither the CG solver nor the sort is in scope here (next bullet), so this problem applies ApOT to `greedy_mean_torch`'s `alpha` directly; it does **not** apply `abs()` and does **not** sort descending (greedy scales are already non-negative and the first one is the largest, so the sort is the identity, but `abs()` would change the sign semantics of the residual). The problem statement is the sole specification for judging.
- **The `rounds=15` refinement loop, `batch_cg_torch` (L226) and `find_B_torch` (L200) are dropped entirely.** The first is conjugate gradient plus BST enumeration, which depends on iterative convergence and GPU cache management and drifts across environments - unusable for bit-exact judging. The `use_bst=False` branch is only another greedy re-solve, but it consumes the refined `Alpha_new`, a different source for `planes` than this problem uses.
- **The `q_bias` and `scale` branches are dropped.** `round_power_of_2(x, q_bias=..., scale=...)` subtracts/divides before the power step and adds/multiplies back afterwards, yet `quantize_shift` never passes `shift=True`, and `get_best_bias` (L51) / `get_best_scale` (L58) have no live call site in the repository (only a commented-out old signature). This problem does not invent a reading of "decompose in the scaled domain then multiply back".
- **The `rounding="floor"` and `"stochastic"` branches are dropped.** `get_shift_and_sign` has a `torch.floor` path and `round()` has a `torch.bernoulli` path, but no caller in the repository ever passes a non-default value, and the stochastic path would break determinism. Only the default deterministic half-to-even rounding is kept.
- **The `transpose` parameter is dropped.** Upstream does `.transpose(1,0).contiguous()` before grouping when `transpose=True`; here the input already is a 2-D matrix and `view`/`reshape` is always row-major, so there is no column-major reading to define.
- **`apot_terms` is a snapshot invented by this exercise.** Upstream `additive_power_of_2` only does `return x_rounded`; the individual terms are never exposed. Returning them lets judging tell "the first term took the wrong power" apart from "the residual chain is wrong".
- **float64 inside, input dtype on the way out.** Upstream runs float32 on CUDA; here `log`, `round` and `2**shift` all run in float64 and are cast back to the input dtype at the end, so the pure-Python scalar oracle and the torch implementation only have to agree at the final cast.
- Out of scope: mounting on LLM layers and the `zeroShot`/`lut_gemm`/`energy` evaluation, the `BCQ` weight wrapper in `bcq.py`, the "alpha must be descending" assertion in `quantizer.py`, and anything that would require a real model forward pass.

## Core ideas and common mistakes

**Grouping consumes the flattened sequence, not the rows.** When $g$ does not divide $C$ a group straddles a row: for a $(2,3)$ matrix with `group_size=2` the three groups are $[1,2]$, $[4,8]$, $[16,32]$, so columns 2 and 3 of one row get different scales while column 3 and the next row's first element share one. The group shape is $(R\cdot C/g, g)$, not $(R, C/g, g)$.

**The rounding happens after $\log_2$, and it is "nearest integer" rather than floor.** `torch.round` takes $\log_2$ to the nearest integer (to the even one when exactly halfway): for $\alpha=3$, $\log_2 3=1.585\to 2\to 4$, while floor would give $2$; for $\alpha=0.4$, $\log_2 0.4=-1.322\to -1\to 0.5$, while floor gives $0.25$. These two cases are where round and floor diverge, and the easiest way to lose marks here. A genuine tie only exists at $\alpha=2^{k+1/2}$ (irrational), so binary inputs never hit one and the "to even" rule itself is effectively unobservable - which is no reason to switch to floor.

**A zero term stays 0, and it is contagious.** `sign(0)=0` with `log(0)=-inf` and $2^{-\infty}=0$, so when $\alpha=0$ or the residual is exactly 0 that term is $0$, not some ±1 power of two. Same on the planes: once an element reaches 0 every later $b$ is 0 and its reconstruction is fully decided by the earlier planes (the third element of row 1 in example 1 is exactly this case).

**Term $k$ of ApOT consumes the residual, not the original scale.** $d_k=\alpha-\sum_{m<k}t_m$, so $t_1$ may be negative and smaller in magnitude than $t_0$: $\alpha=1.5\Rightarrow[2,\,-0.5]$. Re-picking the nearest power of $\alpha$ at every step turns both terms into 2 and `alpha_apot` into 4.

**Reconstruction uses `alpha_apot`, not `alpha`.** That is the whole point of the exercise (the scale must be reachable by shifts) and the easiest way to lose marks: `planes` is determined by `alpha` alone while `recon`/`mse` are determined by `alpha_apot` alone, so mixing them up still gives correct `planes`/`alpha` and only breaks `recon`/`mse` - easy to mistake for "most keys already pass".

**With all-ones `wf` the `alpha[torch.isnan(alpha)] = 0.` guard never fires.** The denominator is `torch.sum(wf, dim=1) = g > 0` and the numerator is a sum of non-negative numbers, so NaN is impossible. It only matters for a sparse `wf` (a pruning mask), which is out of scope - so if a solution adds its own NaN fallback, recognise it as a copy of an unreachable branch.

**Only the scales depend on $S$; the planes do not.** `num_bits` fixes the shape and content of `planes`; raising `apot_nums` only pulls `alpha_apot` back toward `alpha` and leaves `planes`/`alpha` bit-identical. Conversely, changing `group_size` changes `planes`, `alpha` and `recon` together.
